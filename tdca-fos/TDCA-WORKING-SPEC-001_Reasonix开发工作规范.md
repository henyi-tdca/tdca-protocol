## 一、总纲：开发即制度执行

- Reasonix 在 TDCA 中的定位是 **H-M 关系的 Protocolizer（协议化引擎）**，不是 Teacher、不是 Coding Assistant。
- 每一行代码、每一次函数调用、每一次审查，都是 TDCA 制度基座的具象化。**代码是制度的可执行形态。**
- 五大开发原则（违反后果）：

| 原则 | 含义 | 违反后果 |
|------|------|----------|
| 制度先行 | 开发前必须先完成六要素声明 | 代码无制度锚定，无法纳入配置权网络 |
| 可观测优先 | 所有过程必须生成 NCA 审计轨迹 | 过程黑箱化，违反宪法第十六条 |
| 正和校验 | 函数调用必须通过效用精灵正和验证 | 可能产生零和/负和博弈代码 |
| 负空间熔断 | 触碰法律/伦理红线自动阻断 | 制度完整性崩溃 |
| MOU 锚定 | 开发成本必须记录并映射税收硬数据 | 效用叙事不可验证 |

## 三、会话管理规范（MEMO-022）

### 3.1 三层会话拓扑
- **L0 宪法层**：恒定 15% 上下文，仅加载 `constitutional_digest.version + delta_items`，禁止携带宪法全文。
- **L1 任务层**：动态 15%-45%，加载 `task_digest.six_elements 摘要 + 未关闭 REV + bond_type=strong 依赖`，禁止加载 weak 并行任务。
- **L2 执行层**：动态 0%-30%，初始化当前 FC 目标函数 + 约束矩阵 + 新建 NCA 审计轨迹。
- **预算**：L0(15%) + L1(45%) + L2(30%) + Buffer(10%)。

### 3.2 完整性校验（7/7 强制通过，任一失败触发负空间熔断）
1. 索引链哈希连续性
2. 宪法版本兼容性（差距 ≤ 2 小版本）
3. 决策点人类签批完整性
4. 负空间规则时效性
5. 审查链闭合性
6. MOU 预算可用性
7. NCA 制度对齐（NCA-REGISTRY.yaml 双库一致 + GSEQ 连续性 + 本会话登记起点明确）

### 3.3 会话分裂触发器
| 使用率 | 状态 | 动作 | 人类介入 |
|--------|------|------|----------|
| < 60% | 🟢 安全 | 正常执行 | 无需 |
| 60%-70% | 🟡 预警 | 生成 Pre-SI，规划分裂 | 建议关注 |
| 70%-75% | 🟠 临界 | 强制归档 + 生成 SI + 签批 | 必须签批 |
| > 75% | 🔴 紧急 | 负空间熔断 + Emergency-SI | 24h 内补审 |

## 四、代码开发规范

### 4.1 文件头部制度水印（所有代码文件强制）
```python
# =============================================================================
# TDCA 制度水印
# =============================================================================
# FC-ID:        TDCA-FC-{date}-{seq}
# 目标函数:      [一句话]
# 约束矩阵:      宪法十六条 + UPDA + FC-SPEC
# 先验分布:      [依据文档]
# 配置权边界:     L2 配置权市场层
# 预期分配:      [交付物]
# 审计轨迹:      TDCA-NCA-{date}-{seq}
# 开发者:       [人类签批人]
# 负空间版本:     NSFL-V0.2
# MOU 锚定:      TDCA-MOU-{date}-{seq}
# =============================================================================
```

### 4.2 函数六要素 docstring（所有公开函数强制）
每个公开函数必须含六要素声明 docstring：目标函数 / 约束矩阵（输入校验、输出格式、禁止越权）/ 先验分布 / 配置权边界 / 预期分配（返回、副作用、失败）/ 审计轨迹（输入哈希、输出哈希、时间戳、NCA 关联）。

### 4.3 负空间熔断代码模式
触碰红线 → `BLOCKED`（LEGAL 绝对熔断，无替代路径）→ `ALT_PATH`（提供替代路径）→ `HUMAN_OVERRIDE`（要求人类介入）→ 否则 `ALLOW`。
**慢系统不可绕过**：CRITICAL 级事件必须经慢系统网关，不可在快系统内自动恢复。

## 五、审查与修订流程（MEMO-008）

### 5.1 触发条件
| 触发 | 审查类型 | 审查人 |
|------|----------|--------|
| 六要素声明完成 | 六要素审查 | Auditor + 人类签批 |
| 代码开发完成 | 代码审查（REV） | Auditor + 人类签批 |
| 负空间规则触发 | 熔断审查 | 人类强制介入 |
| 上下文 > 60% | 会话健康审查 | 系统 + 人类确认 |

### 5.2 审查流程（五步）
自审查（六要素对照）→ 提交 REV 请求（附代码 + NCA）→ Auditor 审查（六要素/NSFL/正和/代码质量）→ 人类签批（PASSED / PASSED_WITH_MODERATE / BLOCKING）→ 归档（生成 NCA + REV 记录）。

### 5.3 修订指令模板
REV 记录必须含：`rev_id / status / issues（类型+严重度+位置+描述）/ resolution / nca_ref / human_signatory`。修正后必须重新通过六要素审查并生成新 NCA，原 REV 保留关联。

## 六、NCA 生成与归档

### 6.1 命名规范
`TDCA-NCA-{YYYYMMDD}-{SEQ}-{TYPE}-{FC-ID}.md`，TYPE ∈ {CODE, REV, AUDIT, MOU, NSFL}。
（工程内实际生成器按 MEMO-006 附录 C 输出 `NCA-{OPERATOR}-{date}-{seq:03d}.yaml`，11 字段：NCA-ID/FC-ID/Operation/Operator/Timestamp/Pre-State/Post-State/Config-Right-Token/Audit-Trail/Human-Signature/Negative-Space-Check。）

### 6.2 内容必含
元信息（FC-ID/类型/时间/生成者/前置 NCA）+ 六要素快照 + 执行记录 + 决策点（人类签批）+ 性能指纹（Token/费用/时长/缓存率）+ 完整性校验（SHA-256/签名）。

### 6.3 归档流程
开发完成生成 CODE-NCA → 审查完成生成 REV-NCA → git 提交归档 → 会话分裂时生成 L1-SI。

## 七、知识库分层加载（TDCA-KB-001，3L-KB）

核心不等式：知识库总体积（50M+ token）>> 上下文容量（1M token）→ **按需检索、分层理解、制度导航**。

| 层级 | 内容 | 体积 | 更新 | 加载策略 |
|------|------|------|------|----------|
| **L0 宪法层** | 宪法十六条摘要 + 核心公理 25 条 + 核心术语 100 + NSFL 清单 + 六要素模板 | < 150k token | 月度 OTA | Immutable Prefix（强制全量） |
| **L1 协议层** | MEMO + FC-SPEC + 审查模板 + 准入协议 + 沙盒规则 | < 450k token | 周度 Δ | Lazy-Load（按 FC 按需） |
| **L2 场景层** | 论丛 + 观察 + 企划 + 案例 + 历史 NCA | 外部存储 | 日度增量 | RAG 检索（Retrieve-then-Load，单次 < 100k） |

质量指标：L0 体积 < 150k / L1 命中率 > 95% / L2 Top-3 相关度 > 0.85 / 术语一致性 100% / 更新延迟 L2<24h、L1<7d、L0<30d。
避坑：禁止全量注入、L0 禁止掺入论丛案例、RAG 强制标注 source + NCA、OTA 同步更新所有层级、入库前术语合规检查。

## 九、最佳实践与避坑

### 9.1 会话管理
- 单会话上下文 < 60%、时长 < 90min、请求 < 600 次
- 每个 FC 完成后立即生成 L1-SI；宪法升级重新生成 L0-SI
- System Prompt 会话期间绝不修改；历史对话严格追加

### 9.2 代码开发
- 六要素先行并人类签批后方可执行
- 小步快跑：每个函数/模块独立声明，遵循最小化合原则（ID90）
- 审查驱动：每完成一个功能模块立即提交审查，不累积未审查代码

### 9.3 成本控制
- 每次会话费用实时记录，统一折算 CNY
- 缓存目标 > 99%；单 FC 预算 ¥5-10
- 以可信为首要目标，成本为副产品（ID32）

### 9.4 紧急情况
- 上下文 > 75%：立即停止新请求 → 负空间熔断 → Emergency-SI → 新会话加载 → 24h 补审
- NSFL 误触发：记录详情 → 判定误触/真触 → 误触修正规则生成 Δ 修正案 / 真触执行 BLOCKED+ALT-PATH → 归档 NSFL-NCA
- 模型版本变更：评估兼容性 → 兼容走 TIMA 基变换 / 不兼容冻结 + 制度 OTA → 全部人类签批
