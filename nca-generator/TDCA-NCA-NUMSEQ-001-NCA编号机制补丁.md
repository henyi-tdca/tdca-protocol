## 〇、定性

编号事故非"错误"，而是**负空间边界测试**：暴露"人工干预 vs 自动执行"状态同步缺口。未来自动化生态中大量外部智能体并发申请 NCA 编号——若不修复，"编号资产被覆盖"将成制度性事故。冷启动初期暴露，代价最小。

## 一、机制补丁（两项决策）

### 选项 B · generate_nca 扫盘校验（根治并发冲突）

`generate_nca` 增加**落盘前扫描前置**：
- 生成编号前扫描文件系统/注册表，检测目标编号是否已被占用
- 占用 → 自动顺延至下一个空闲位
- 本质：宪法十六条"可观测性"落到代码层——**编号以"事实存证"为准，非"内存计数器"**

### 选项 C · 禁止手动预分配（掐断冲突源头）

制度红线：
- **所有 NCA 编号必须由 `generate_nca` 统一生成，人工只能通过 API 触发**
- 禁止人工/脚本手动指定编号落链（如 M2 编译曾手动预分配 155）
- 本质：ID90 最小化合——单一事实源（Single Source of Truth），制度规则只有一个入口

## 二、实施要求（WorkBuddy）

1. `generate_nca` 改造：落盘前扫盘（目标编号存在 → 顺延空闲位）→ **测试 ≥5 用例**（占用顺延 / 并发模拟 / 手动分配拒绝 / 空闲位选取 / 链连续性）
2. 纪律固化：注释 + 文档声明"编号仅由 generate_nca 生成，人工不得指定"
3. 实施后 Reasonix 见证

## 三、恢复原则（既有，保留）

编号冲突恢复按「保留已落链、新链顺延至空闲号」原则（如 M1 155/156/157 保留、M2 顺延 158）。

## 四、实施状态与口径裁定（2026-08-28 更新）

- **B+C 已实施（WorkBuddy）**：`_reserve_free_nca_slot()`（O_EXCL 原子预约）+ `explicit_seq` 拒绝 + `Generated-By` 标记 + lint；测试 7/7 OK（含事故复现/并发唯一）；见证 NCA-159（未覆盖 158）
- **编号口径裁定（GSEQ-0551）**：**追加 max+1，保留缺口**——编号=事实存证时间序，不可回填；缺口=历史事故痕迹，保留即审计线索（编号不可回填 = 不可篡改精神）。**已实施（WorkBuddy）**：`_reserve_free_nca_slot` candidate 初值改 `max(existing)+1`（单点改动），测试同步改为 max+1 语义（T2 取 004、T1b 顺延 156），7/7 OK。
