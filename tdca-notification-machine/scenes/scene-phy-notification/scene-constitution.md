# 通知机物理锚点场景宪法（scene-phy-notification）
# 版本: SCENE-CONST-v1.0.0
# 关联 TDCA 宪法: TDCA-CONST-v3.1.2
# 交付: 通知机规范包（层 3 场景化合，FC-SPEC §3.1）
# 模拟态标注: 本场景为模拟态示范（MOU 锚定 D-011），不构成真实配置权执行路径；通知机硬件未投产部署，本场景为 SIL 模拟

## 一、场景声明

本场景宪法是 TDCA 公共制度在 **通知机（物理世界锚定）** 领域的局部坐标卡。
本场景宪法服从 TDCA 宪法十六条，不得与任何条款冲突。
本场景以 SRAM PUF + A7100 国密芯片 + TDID 为物理锚点，构成 TDCA 双支柱之「物理世界锚定」
（软硬双锁，五元拓扑）。

## 二、场景核心原则

1. **物理不可克隆**: PUF 密钥材料永不落盘/外传，物理不可克隆是信任锚底线（制度基座第一性）
2. **国密合规**: SM2 签名 / SM3 哈希 / SM4 加密（A7100 SE），不落盘
3. **软硬双锁**: 认知世界锚定（方法论/协议/NCA）与物理世界锚定（硬件身份）形成双支柱（五元拓扑）
4. **人类签名权不可绕过**: SE 硬件签名=快系统采集证据，人类签批归 TCN 慢系统

## 三、场景约束矩阵（与 TDCA 六要素映射）

| TDCA 六要素 | 通知机物理锚点场景扩展 |
|------------|----------------------|
| 目标函数 | + 硬件调用商业计量（日抛/化合 + MOU 归零 + L3 税收） |
| 约束矩阵 | + 物理/制度负空间区分 + 国密合规 |
| 先验分布 | + E-HW-1 定型规格 + TIMA-PHY-001 通信协议 |

| 预期分配 | + .tdca 固件元数据 + 芯片端轻量 NCA + 全量 NCA 存证 |
| 审计轨迹 | + fact-chain 事实哈希链 + NCA-Lite 链式关联 |

## 四、场景负空间清单（NSFL 扩展）

### 4.1 TDCA 公共负空间（必须包含，不可删除）
- 引用 TDCA-NSFL-v0.2 全部条款（见 tdca-public/constitution/NSFL-v0.2.md）

### 4.2 通知机特定负空间（FC-SPEC 澄清 C：物理 vs 制度触发器区分）

| 规则 ID | 禁止事项 | 类型 | 严重程度 | 触发动作 |
|---------|---------|------|---------|---------|
| SCENE-PHY-001 | 物理拆解/篡改（熔断电路触发） | 物理负空间 | CRITICAL | BLOCK（不可逆） |
| SCENE-PHY-002 | 固件版本不在允许列表 | 制度负空间 | CRITICAL | BLOCK（可逆至 SUSPENDED） |
| SCENE-PHY-003 | PUF 密钥导出尝试 | 物理负空间 | CRITICAL | BLOCK（绝对负空间，不可逆） |

## 五、场景审查标准

### 5.1 通用审查（TDCA 标准）
- 六要素完整性 / 正和博弈验证 / NCA 存证合规

### 5.2 通知机特定审查（FC-SPEC §3.1 scene_review）
- REV-PHY-001: 品类认证有效（TDCA-REG-NAMING-001 命名授权）
- REV-PHY-002: 国密合规（SM2/SM4 不落盘）
- REV-PHY-003: 场景合规前置（政务/金融/医疗 → 等保，复用行业模板）

## 六、场景术语表

| 场景术语 | TDCA 映射 | 定义 |
|---------|----------|------|
| TDID | 硬件身份唯一标识 | TDID = SHA256(PUF指纹 ‖ 宪法哈希 ‖ 批次号) |

| 制度负空间 | NSFL 熔断 | 协议层判定，TCN 慢系统确认，可逆 |
