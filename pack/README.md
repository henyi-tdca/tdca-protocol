## 一、协议包是什么

**TDCA 智能体编程协议包**是把 TDCA 制度框架编译为**可执行的开发协议**的交付物。它不是一个工具、不是一套框架，而是一组**协议文件**——定义智能体如何协作、如何审计、如何继承知识、如何触碰边界（负空间）。

核心主张（来自方法论 V1.1）：

- **协议优先、模型无关**：无论底层是 DeepSeek、Kimi、GPT 还是 Claude，协议层保持稳定
- **可审计、可遗传、可验证**：NCA 存证 / SI 遗传 / 六要素声明
- **负空间意识**：法律禁止领域 = 绝对负空间，只识别并熔断
- **制度红利大于技术红利**（ID32）：本协议包的价值在秩序创造，不在代码本身

## 六、结构最小化合论证（ID90 最小化合原则）

> 制度审查意见（TDCA-PRINCIPLE 级）：需显式论证为何 13 文件结构不可还原为更简单的物理叠加。

**必要性判定三条件**（13 文件同时满足，缺一即破坏协议包的制度功能）：

| # | 条件 | 论证 | 反证（若违反） |
|---|------|------|---------------|
| 1 | **功能不可归并** | 每文件承载不可替代的制度功能：docs/ 为规范-程序（阅读执行），templates/ 为产物-复制（直接取用），README 为自指声明（六要素+合规红线） | 合并任一文件 → 制度功能缺失或语义降级。如速查卡并入编码规范，则破坏"开发全程一页对照"的执行场景；模板并入规范，则破坏"复制即用"的产物边界 |
| 2 | **变更频率/生命周期异构** | 规范文档随制度演进变更（L0 月度 OTA / L1 周度 Δ），模板随工程迭代变更（随 FC 按需）——物理分离使 Δ 更新最小化，制度同构跃进（ID82）硬约束之一：接口熵=0 的存储侧表达 | 物理叠加为单文件 → 制度层任一 Δ 修订都需整体重写，更新开销 ↑90%（对照 3L-KB 缓存更新频率 -90% 实证） |
| 3 | **消费场景分离** | docs/ 面向"阅读执行"（一次性加载，对应 L1 协议层 Lazy-Load），templates/ 面向"复制产出"（反复引用，对应 L2 按需检索）——分离是 3L-KB 分层加载的前提 | 混装单文件 → L0/L1/L2 分层失效，知识库加载策略无法执行，50M+ token 体积不等式不可控 |

**结论**：13 文件 = 制度功能（docs 7）+ 产物模板（templates 5）+ 自指声明（README 1）的**最小完备划分**。任一文件既不能归并（条件 1）、不能合并（条件 2）、不能混装（条件 3），结构不可还原为更简单物理叠加。
