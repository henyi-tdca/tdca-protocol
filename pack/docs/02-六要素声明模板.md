# 02 · 六要素声明模板（填写指南）

> TDCA-PACK-001-DOC-02 | 依据方法论 V1.1 附录 C + TDCA-WORKING-SPEC-001 §2.2
> 每个 FC（函数调用任务）强制声明；文档类产出在文档头部声明（本文档自身作为 FC 的制度约束）

---

## 六要素速览

| # | 要素 | 回答的问题 |
|---|------|-----------|
| 1 | 目标函数 | 本次开发要解决什么问题？预期产出是什么？ |
| 2 | 约束矩阵 | 必须遵守哪些制度约束？ |
| 3 | 先验分布 | 基于哪些已有 NCA/验证报告/制度文件？ |
| 4 | 配置权边界 | 本任务的操作权限范围？不可触碰什么？ |
| 5 | 预期分配 | 输出什么？如何分配？审查通过标准？ |
| 6 | 审计轨迹 | NCA 文件如何命名与关联？ |

---

## 逐项填写指南

### 1. 目标函数
- 一句话：动词 + 对象 + 产出。例如："建立 D-2 并集引擎，输出 O(|A|+|B|) 并集算法 + 单测（覆盖率 >90%）"
- 反面示例（不可用）："优化系统性能"（无对象、无产出、不可验收）

### 2. 约束矩阵
按优先级列举，至少覆盖：
- 宪法十六条相关条款
- UPDA 定价约束（如适用）
- NSFL 负空间边界（三不可原则）
- 配置权层级限制（L0/L1/L2/L3，工程默认 L2 配置权市场层）
- 专属约束（当前 FC-SPEC 附加项、跨 FC 依赖契约）

### 3. 先验分布
- 上游 FC 依赖（bond_type=strong 的必须列出）
- 历史审查记录（同类任务的 REV）
- 制度基线版本（宪法/UPDA/NSFL 版本号）
- 实战数据（如缓存命中率、成本基准）
- 负空间触发历史（如有）

### 4. 配置权边界
- **可触碰**：列明制度层级与操作范围
- **不可触碰**：法律禁止领域（绝对负空间，无替代路径）；人类价值领地（相对负空间，不可算计）
- 跨主体协作权限（是否涉及多主体、需不需要对方签批）

### 5. 预期分配
- 交付物清单（代码/文档/测试）
- NCA 审计轨迹（主 NCA + 审查 REV + NSFL 触发 NCA）
- 审查通过标准（PASSED 判定条件）
- MOU 税收锚定（成本记录映射）

### 6. 审计轨迹
- 主 NCA: `TDCA-NCA-{date}-{seq}-{FC-ID}`
- 审查 REV: `TDCA-NCA-{date}-{seq}-REV-{n}`
- 负空间触发: `TDCA-NCA-{date}-{seq}-NSFL-{n}`
- 关联 SI: `TDCA-SI-{date}-{seq}-L1-{hash}`

## 质量检查（填写后自审）

- [ ] 目标函数可验收（有明确产出标准）
- [ ] 约束矩阵含 NSFL 负空间边界
- [ ] 配置权边界同时声明"可触碰"与"不可触碰"
- [ ] 预期分配含审查通过标准
- [ ] 审计轨迹命名符合规范
- [ ] 人类签批栏已留（`人类签批: ____________`）

> **接口熵 = 0 声明（制度同构跃进 ID82 硬约束之一）**：本模板是制度约束的**非蒸馏同构映射**——六要素声明作为「FC → Auditor」跨模块接口，须显式声明输入（任务描述）/ 输出（六要素结构）/ 异常（要素缺失即拒绝）；与 `docs/04` §6 接口契约贯通。

> 六要素是审查的第一输入：审查官（K3 Auditor / tdca-compliance-auditor）逐项核对声明与实现的一致性。
