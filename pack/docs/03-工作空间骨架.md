# 03 · 工作空间骨架（目录模板）

> TDCA-PACK-001-DOC-03 | 依据方法论 V1.1 第五章（MEMO-019 / TIMA）
> 使用：按此结构建立项目根目录，`.tdca/` 为制度元数据区，`src/` 为源码区。

---

## 目录结构

```
tdca-dev-workspace/
├── .tdca/                          # TDCA 元数据目录
│   ├── constitution/               # L0 宪法层（活宪法，只读引用）
│   │   ├── TDCA-CONST-v3.1.2.md
│   │   ├── UPDA-v2.0.md
│   │   ├── NSFL-v0.2.md
│   │   └── terms-v3.0.md
│   ├── session-index/              # SI 遗传文件（MEMO-022）
│   │   ├── L0/                     # 宪法层索引
│   │   ├── L1/                     # 协议层索引
│   │   └── L2/                     # 执行层索引
│   ├── nca/                        # NCA 嵌套认知资产
│   │   ├── code/                   # 代码开发 NCA
│   │   ├── review/                 # 审查记录 NCA
│   │   ├── audit/                  # 审计轨迹 NCA
│   │   └── mou/                    # MOU 税收锚定 NCA
│   ├── memory/                     # TIMA 制度记忆层
│   │   ├── project/                # 项目级记忆（单 FC 周期）
│   │   ├── user/                   # 用户级记忆（跨项目持久）
│   │   └── global/                 # 全局制度记忆（永久）
│   └── skills/                     # TDCA 函数语料技能库
│
├── src/                            # 源代码
│   ├── core/                       # 核心制度引擎
│   │   ├── constitution.py         # 宪法十六条执行器
│   │   ├── upda.py                 # 通用定价与分配算法
│   │   ├── nsfl.py                 # 负空间函数语言运行时
│   │   ├── six_elements.py         # 六要素校验器
│   │   ├── nca.py                  # NCA 生成与管理
│   │   └── nia_macm.py             # NIA-MACM 3.0 双协议引擎
│   ├── api/                        # 协议接口层
│   │   ├── config_rights.py        # 配置权 API
│   │   ├── mou_anchor.py           # MOU 税收锚定 API
│   │   ├── audit_trail.py          # 审计轨迹 API
│   │   └── session_index.py        # SI 文件管理 API
│   ├── ui/                         # 用户界面层（可选）
│   │   ├── dashboard.py            # 全周期管理仪表盘
│   │   ├── six_elements_editor.py  # 六要素声明编辑器
│   │   └── review_panel.py         # 审查面板
│   ├── infra/                      # 基础设施层（可选）
│   │   ├── chain_adapter.py        # TDCA 链联盟链接入
│   │   ├── cbdc_connector.py       # 数字人民币智能合约
│   │   └── storage.py              # NCA 分布式存储
│   └── skills/                     # 可复用技能模块
│       ├── code_review.py          # 代码审查技能
│       ├── security_audit.py       # 安全审计技能
│       └── compliance_check.py     # 合规检查技能
│
├── tests/                          # 测试套件
│   ├── unit/                       # 单元测试
│   ├── integration/                # 集成测试
│   └── e2e/                        # 端到端测试
│
└── docs/                           # 项目文档
    ├── README.md
    └── CHANGELOG.md
```

## 精简模式（小型项目/单 FC）

```
tdca-dev-workspace/
├── .tdca/                          # 制度元数据（结构同上，可只建 nca/ + session-index/）
├── src/                            # 源码
├── tests/                          # 测试
└── docs/                           # 文档
```

> 精简模式至少保留 `.tdca/nca/` 与 `.tdca/session-index/`——这是可审计、可遗传的底线。

## TIMA 记忆层生命周期

| 层级 | 内容 | 生命周期 | 跨模型迁移 |
|------|------|---------|-----------|
| Project | 当前 FC 六要素、审查记录、决策点 | 单 FC 周期 | 通过 SI 文件 |
| User | 用户偏好、制度基线版本、Δ 修正案 | 跨项目持久 | SI 文件 + 配置同步 |
| Global | 跨会话 SI、NCA 档案库、税收锚定 | 永久 | TDCA 链联盟链 |

## 跨模型基变换

模型版本变更（如 deepseek-v4-flash → v4.1）时：
1. SI 文件作为制度记忆的**基变换协议**
2. TIMA 负责 SI 文件跨模型语义一致性校验
3. 制度记忆不随模型变更丢失
