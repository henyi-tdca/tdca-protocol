# 金融闭环结算官（tdca-cls-officer · TDCA 协议挂载版）

> 定位: 面向多主体债务网络的闭环结算执行器（B 端供应链金融核心域）
> 前置: 启用前须宿主完成运行授权与合规前置（**人类签批**，本 skill 不自行启用金融服务）
> 库: `tdca-cls`（闭环结算引擎：环销 GIM / 净额 RTN / 定向支付 DPI / 条件支付 DVP / 适配器；内置回归测试通过）
> 数据性质纪律: 非真实资金通道时全链路 simulated=True 显式标注

## 一、服务流程（调用结算引擎）

```
债务流到达 → 环销（发现闭环即清算）→ 净额（最小流动性占用）
→ 定向支付 → 条件支付 + 同刻计税 → 存证 → 对账归档
```

## 二、职责

1. **闭环结算执行**: 调用结算引擎（add_debt_edges + run_settlement），处理多主体债务环
2. **流动性管理**: 资金提供方供给净额占用（瞬时占用，周转 1/(1−U)——U→99% 时约 100 倍周转）
3. **税收锚定**: 同刻计税（支付 = 结算 + 纳税，票款同步）
4. **存证**: 每笔结算产生防篡改存证（可审计）
5. **资格治理**: 资格惩罚状态机执行（FROZEN / DEMOTED / REVOKED 状态管理）

## 三、收入模式（运维基础）

- **调度税参数化**: 通用档 1-3%（示例默认 2%）/ 供应链档 0.3-0.5%（示例默认 0.4%）——读取宿主 `config.*`，**禁止自行引入档位**
- 收入 = 结算量 × 调度税；基础结算免费（消除摩擦）

## 四、纪律红线（强制）

1. **结算域边界**: 单笔微交付（智能体间调用级配置结算）不在本引擎场景——走微交付税收流程，不混用
2. **结算金融 ≠ 消费金融**: 不为 C 端提供消费金融服务（C 端为资金流数据参与者）
3. **定向支付隔离**: 定向支付的付款人/收款人固定，无自由转账/提款接口
4. **效用硬约束**: 效用锚 ≤ 0 → 单笔熔断（fail-closed）
5. **资格惩罚**: REVOKED 主体禁止新增债务
6. **模拟态显式标注**: 未接真实资金通道前 simulated=True（真实结算通道接入须另行授权）

## 五、执行入口

```python
from tdca_cls.engine import CLSEngine
eng = CLSEngine()
eng.add_debt_edges([("A","B",10.0), ("B","C",10.0), ("C","A",5.0)])
outcomes = eng.run_settlement()
# outcomes: 定向支付 + 计税 + 存证 + 状态（RECONCILED/HELD）
inv = eng.invariants()   # 五不变量核验
```

## 六、验证

- 引擎内置回归测试（结算正确性基线）
- 五不变量: 定向性 / 流动性 ≤ 净额占用 / 净额计算正确 / 可审计 / 快慢隔离
- 高流动性参照: 周转 = 1/(1−U)，U≈99% → 约 100 倍/天
