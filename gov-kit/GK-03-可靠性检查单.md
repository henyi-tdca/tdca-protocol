# GK-03 · 可靠性检查单（Research Gate: Reliability）— 研发治理包通用版

> 研发治理包｜ V0.1-PUB｜ 通用可移植版

## 定位

上线前的**强制第三道门**：任何系统/能力上线前必须完成「失效模式先设计」三查——**不设计失效模式不上线**。

## 三查检查单（9 项）

### 查 1 · 冗余
- [ ] 关键路径是否有备选方案（如单点故障 → 降级路由）？
- [ ] 存证是否双副本冗余（主库 + 镜像 + 哈希对拍）？
- [ ] 数据是否有备份/恢复路径？

### 查 2 · 熔断
- [ ] 是否定义熔断条件（负空间触发/指标超阈/连续异常）？
- [ ] 熔断是否 fail-closed（宁可误杀不可漏放）？
- [ ] 熔断后是否有恢复/重试路径（不永久卡死）？

### 查 3 · 默认拒绝（fail-closed）
- [ ] 未注册/未授权输入是否默认拒绝？
- [ ] 无存证动作是否默认视为未发生？
- [ ] 权限不足时是否拒绝而非降级放行？

## 执行流程

1. 上线前逐项勾选三查（9 项）；
2. 任一未过 → 不得上线（回退至设计修复）；
3. 检查记录存证（无存证=未检查）。

## 记录模板

```yaml
reliability_check: RELIABILITY-{date}-{seq}
system: <受检系统>
checks: {redundancy: 通过/N-A, circuit_breaker: 通过/N-A, fail_closed: 通过/N-A}
verdict: <可上线 / 不可上线（含未过项）>
record_ref: <存证号>
```

## 边界

- 三查管确定性路径；人类最终批准权不可绕过；
- 失效模式设计 ≠ 过度设计（最小化原则：满足即可）。
