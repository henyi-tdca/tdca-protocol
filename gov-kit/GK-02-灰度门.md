# GK-02 · 灰度门（Research Gate: Canary）— 研发治理包通用版

> 研发治理包｜ V0.1-PUB｜ 通用可移植版

## 定位

变更发布的**强制第二道门**：任何变更（功能/配置/流程）通过试验门后，必须**分轨灰度验证**——小范围 → 观察 → 全量。**不全量直上**。

## 灰度三要素（默认值，按风险档可调）

| 风险档 | 适用 | 灰度比例 | 观察期 | 回滚条件 |
|---|---|---|---|---|
| 低 | 文案/参数/内部流程微调 | 5% 起步 | 3 天 | 异常率 >0.1% 或红线触发 → 立即回滚 |
| 中 | 功能变更/工具新增 | 10% 起步 | 7 天 | 异常率 >0.5% / 指标未达标 / 负空间触发 → 回滚 |
| 高 | 架构/契约/对外口径变更 | 10% 起步 | 14 天 | 任意红线违例 / 指标严重未达标 / 人工裁决 → 立即回滚 + 复盘 |

**参数规则**：比例只增不减；观察期只延不缩；回滚条件任一触发即回滚（不讨论、不观望）。

## 流程（六步）

1. 发布提案（变更内容 + 风险档 + 灰度参数）；
2. 灰度部署（按比例放量）；
3. 观察（按观察期监控指标）；
4. 达标放量（逐步提高比例至全量）；
5. 未达标回滚（触发即回滚 + 记录原因）；
6. 存证（灰度记录，无存证=未灰度）。

## 记录模板

```yaml
canary_id: CANARY-{date}-{seq}
change: <变更内容>
risk_tier: <低/中/高>
canary_params: {ratio_start, observe_days, rollback_condition}
result: <达标放量 / 回滚（含原因）>
record_ref: <存证号>
data_provenance: <real/simulated>
```

## 边界

- 高风险的人工裁决（慢裁决）不可绕过；
- 低风险微调可走快速通道（证伪记录+存证即可，灰度可选）；
- 红线违例无灰度（立即熔断，自动执行层）。
