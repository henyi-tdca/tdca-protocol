# GK-05 · 效用归零（Utility Zeroing）— 研发治理包通用版

> 研发治理包｜ V0.1-PUB｜ 通用可移植版
> 原则：地板不是天花板（可验证效用是可持续性的最低可见信号，非效用近似）；归零是熔断底线非目标。

## 定位

**从制度源头杜绝「花冤枉钱」**：任何协作若无法在连续时间内产生可验证的效用锚定，其效用权重自动归零并触发熔断——无效用支出不收费、不记为有效。

## 执行路径（四步）

1. **计量**：每次调用计量进项/出项（效用锚）；
2. **验证**：连续窗口内验证效用锚定（是否产生可验证信号）；
3. **归零/确认**：验证失败 → 效用权重归零 + 熔断（不收费、不纳入有效账本）；通过 → 确认入账；
4. **存证**：归零/确认事件存证（无存证=未处置）。

## 触发条件

| 情形 | 处置 |
|---|---|
| 连续窗口内无可验证效用锚定 | 效用归零 + 熔断 |
| 空壳套娃/无效用锚定的投机 | 立即归零 + 熔断 |
| 效用锚定真实产生 | 确认入账 |

## 边界

- 「不入账」= 无效用记录**落审计存证**（fail-closed）但效用=0、不进有效账本——落盘是存证非有效入账；
- 当前为逐笔调用级归零；「连续窗口聚合判定」为下阶段细化项；
- 真实计量通道接入前为模拟态（ID92 语义）。

## 记录模板

```yaml
mouzero: MOUZERO-{date}-{seq}
event: <调用/协作标识>
utility_anchor: <0=归零 / >0=确认>
breaker_triggered: <true/false>
fee_charged: <0=不收费 / 正常>
record_ref: <存证号>
data_provenance: <simulated/real>
```
