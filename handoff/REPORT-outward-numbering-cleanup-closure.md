## 一、背景与面别

外部方实测发现：测试云公开接口的对外响应体中，资产名称与说明字段携带内部治理编号
（编号为内部账目口径，不应出现在对外可见面，外部用户与外部 AI 均可直接读到）。

经扩容核查，涉及面别如下（均已有实证处置）：

1. **REST 接口响应字段**——资产目录、税收锚定、确权历史、分配说明、知识术语等端点的展示文本；
2. **openapi 规范**——部分路由的函数 docstring 会被框架写入端点说明，随规范文档对外可读；
3. **前端产物**——构建产物内的展示串；
4. **门户静态页**——门户对外 HTML 内的展示串；
5. **公开 Markdown 文档**——正源树内对外可读的说明文档。

另查明一处结构性隐患：网关容器内数据库无持久化卷声明，容器重建即回种子态
（已在合并链中以独立项消除，见 §二·#313）。

## 六、保留类（类别描述，⛔ 不列编号）

以下类别经判定为**有意保留**，未改动：

1. **契约锚点编号**——公开契约文本中的锚定引用，属对外承诺的一部分；
2. **数据性质模拟标注**——对外声明数据为模拟态的性质标注，公开仓已含，按「已公开者一处不动」口径保留；
3. **真实交易标识值**——对外可验的真实标识，非内部账目口径；
4. **文件名原则集**——仓库内文件名中的编号段，不属对外呈现文本；
5. **字段名中的性质标注**——结构字段名（非展示值），改动将破坏接口兼容性。

登记不改项：源码注释、模块 docstring、模型字段 docstring、内部文档与测试件——
经实测不进入任何对外面（含 openapi 规范），按口径登记保留。
