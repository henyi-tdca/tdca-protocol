### 1.3 穿越条件（每 Phase → 下一 Phase）

| 穿越 | 条件 | 不满足时 |
|------|------|---------|
| P0→P1 | 连接权重 > 0.5 + 意图明确 | 熔断，提示补充协商 |
| P1→P2 | 六要素完成 + 意图置信度 ≥ 0.7 | 熔断，返回 L4 对话 |
| P2→P3 | 编译通过（constraints.failed 为空）+ Token 有效 | 熔断，显示失败原因 |
| P3→P4 | 沙盒验证通过 + 正和博弈验证 | 熔断，返回沙盒 |
| P4→P5 | PUF 绑定 + 四元绑定完成 | 熔断，检查硬件 |
| P5→P6 | 版权确权 + NCA 存证 | 熔断，检查确权 |
| P6→P7 | 接口注册 + 网络广播 | 熔断，检查注册 |
| P7→P8 | 正和满意解存在（ERI > CCI） | 熔断，调整配置 |
| P8→完成 | MOU 闭环（Tax_in + Tax_out > 0）+ 人类最终签名 | 熔断，人工复审 |

### 1.4 失败路径（ID84 停机定理）

```
任意 Phase 失败 → FUSE 熔断态
  ├── 可回退: 回退至失败 Phase 或指定前置 Phase（保留已生成 NCA）
  ├── 可终止: 标记 TERMINATED（NCA 记录终止原因）
  └── 需人工: HUMAN_REQUIRED（挂起等待人类裁决）

熔断档位（ID89 化学热力学）:
  Level-1: 软熔断（WARN）— 条件不满足，自动重试 ≤3 次
  Level-2: 硬熔断（BLOCK）— 触及 ⊗，立即停机
  Level-3: 紧急熔断（FATAL）— 数据完整性/法律负空间，永久冻结
```

### 2.1 模块划分

### 2.2 FlowEngine 核心逻辑

```python
class FlowEngine:
    """9 Phase 生命周期编排引擎（纯 Python 状态机）"""

    PHASES = ['P0', 'P1', 'P2', 'P3', 'P4', 'P5', 'P6', 'P7', 'P8']

    def __init__(self, nca_generator=None, mou_recorder=None):
        self.state = 'P0'
        self.phase_machine = PhaseMachine()
        self.nca_reporter = NCA-Reporter(nca_generator)
        self.mou_closer = MOU-Closer(mou_recorder)
        self.fuse_adapter = Fuse-Adapter()

    def start(self, intent) -> FlowState:
        """启动生命周期（Phase 0 意图孕育）"""

    def advance(self, context) -> FlowState:
        """推进下一 Phase（含穿越条件 + 熔断检查）"""

    def fuse(self, reason, level) -> FlowState:
        """触发熔断（对接 UI-006）"""

    def rollback(self, target_phase) -> FlowState:
        """回退至指定 Phase"""

    def trajectory(self) -> list:
        """返回全流程 NCA 轨迹"""
```

## 三、与 Phase B 前端对接接口

### 3.1 REST API 契约

| 接口 | 方法 | 说明 | 前端对应 |
|------|------|------|---------|
| `/api/v1/flow/start` | POST | 启动生命周期（Phase 0） | UI-007 穿越入口 |
| `/api/v1/flow/status` | GET | 当前 Phase + 状态 | UI-007 当前位置 |
| `/api/v1/flow/advance` | POST | 推进下一 Phase（含熔断检查） | UI-007 穿越按钮 |
| `/api/v1/flow/fuse` | POST | 触发熔断 | UI-006 熔断器 |
| `/api/v1/flow/rollback` | POST | 回退 Phase | UI-007 历史回退 |
| `/api/v1/flow/trajectory` | GET | 全流程 NCA 轨迹 | UI-007 历史轨迹 |

### 3.2 前端联动时序

```
UI-007 用户点击穿越（如 L4→L3）
    ↓
前端调用 /flow/advance
    ↓
FlowEngine: 检查穿越条件（六要素完成/置信度）
    ↓
条件满足 → Phase 推进 + NCA 生成 → 返回新状态
条件不满足 → 返回条件缺失 → UI-007 显示提示（HC-NAV-004）
快→慢穿越 → 前端先调 UI-006 熔断确认 → 确认后 /flow/advance
```

## 四、快慢系统调度策略

### 4.1 调度规则（ID84）

| 系统 | Phase | 执行方式 | 人类介入 |
|------|-------|---------|---------|
| 快系统 | 2/4/5/6/7/8 | 自动执行 | 事后审计 |
| 中快 | 3 | 参数确认 + 机器实时反馈 | 50% |
| 慢系统 | 0/1 | 人工深度介入 | 80-100% |

### 4.2 调度约束

```
1. 快系统前提: 慢系统制度编码已完成（ID84）
   → Phase 2 编译前必须 Phase 1 六要素完成

2. 负空间熔断: 触及 ⊗ 立即停机（ID84）
   → 任意 Phase 检测到负空间 → Level-2/3 熔断

3. 人类最终签名: Phase 8 交付前必须人类签名（ID84）
   → /flow/advance 到 P8→完成 需 human_signature 参数

4. MOU 闭环: 全流程 Tax_in + Tax_out > 0（ID79）
   → MOU-Closer 在 P8 完成后计算并验证

5. 化学热力学（ID89）: 相变检测
   → 场景切换时检测 Δw 阈值，触发 Skill 预加载或抑制归档
```

## 五、预研结论

1. **自研 FlowEngine（纯 Python）** 是当前环境下的最优选型：无 npm 依赖、制度原生、与后端工具链同栈
2. **9 Phase 状态机** 与 TDCA-FLOW-001 完全对齐，穿越条件 + 熔断路径 + 失败档位（ID84/89）已设计
3. **前端对接** 通过 6 个 REST API + UI-006/007 联动，实现五元拓扑层穿越 → Phase 推进的映射
4. **快慢调度** 落实 ID84 四条约束（快系统前提/负空间熔断/人类签名/MOU 闭环）
5. **下一步**：原型实现（2026-09-30）— PhaseMachine + FlowEngine + API 编码 + 测试
