# 金融行业场景宪法
# 版本: SCENE-CONST-v1.0.0
# 关联 TDCA 宪法: TDCA-CONST-v3.1.2
# ID92 模拟态标注: 本示例为示范产物，不构成真实配置权执行路径

## 一、场景声明

本场景宪法是 TDCA 公共制度在 **金融科技** 领域的局部坐标卡。
本场景宪法服从 TDCA 宪法十六条，不得与任何条款冲突。

## 二、场景核心原则

1. **合规优先**: 所有代码必须通过等保三级、PCI-DSS、GDPR 合规审查
2. **风控第一**: 任何金融交易逻辑必须有风控熔断机制
3. **数据主权**: 用户金融数据不得跨境传输，必须存储在境内

## 三、场景约束矩阵（与 TDCA 六要素映射）

| TDCA 六要素 | 金融场景扩展 |
|------------|------------|
| 目标函数 | + 必须通过风控模型验证 |
| 约束矩阵 | + 等保三级 + PCI-DSS + GDPR |
| 先验分布 | + 金融监管机构最新指引 |
| 配置权边界 | + 交易权限分级（普通/机构/监管） |
| 预期分配 | + 风控报告 + 合规审计报告 |
| 审计轨迹 | + 交易全链路 NCA + 监管报送 |

## 四、场景负空间清单（NSFL 扩展）

### 4.1 TDCA 公共负空间（必须包含，不可删除）
- 引用 TDCA-NSFL-v0.2 全部条款（见 tdca-public/constitution/NSFL-v0.2.md）

### 4.2 金融特定负空间

| 规则 ID | 禁止事项 | 严重程度 | 触发动作 |
|---------|---------|---------|---------|
| FIN-NSFL-001 | 未经风控审批的交易逻辑 | CRITICAL | BLOCK |
| FIN-NSFL-002 | 用户敏感数据明文存储 | CRITICAL | BLOCK |
| FIN-NSFL-003 | 跨境数据传输 | CRITICAL | BLOCK（ID86 绝对负空间） |
| FIN-NSFL-004 | 未通过等保测评的系统上线 | CRITICAL | BLOCK |
| FIN-NSFL-005 | 算法歧视（信贷/保险定价） | BLOCKING | HUMAN_OVERRIDE（ID85 人类价值领地） |

## 五、场景审查标准

### 5.1 通用审查（TDCA 标准）
- 六要素完整性 / 正和博弈验证 / NCA 存证合规

### 5.2 金融特定审查
- FIN-REV-001: 交易逻辑风控覆盖度检查（必须 100%）
- FIN-REV-002: 数据加密合规检查（国密算法优先）
- FIN-REV-003: 等保测评报告有效性检查
- FIN-REV-004: 监管报送接口完整性检查
