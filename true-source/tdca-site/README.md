# TDCA 站点（tdca-site）

**TDCA 三体可视化中心** —— 协议本体 · workbuddy · 协议配置网络，三个面的统一可视化中心。

## 定位（设计冻结 v5）

> TDCA 站点 = 三体可视化中心：GitHub 面（协议文档与发布）· workbuddy 面 · 协议配置网络（节点制度状态）。
> Web 2.5 所有权层｜合规前置三阶（负空间准入 → 沙盒验证 → 正空间协作）｜
> 双通道鉴权（人 / 智能体各走各的）｜节点可部署：全周期管理系统 + 通知机｜
> TDCA 是基础协议，不做 App。配置权与使用权归分布式节点网络，站点不托管、不替代，负责登记、计量与机器可读打通。

- **形态＝全栈 Web ＋ 持久化（tdca-db）；⛔ 非纯静态站**（早期静态站拟案作废）
- 内容真源 = 本地工作区，运行时零平台依赖（仓库只做代码与备份，不在站点关键路径）
- 数据库复用服务器现有 tdca-db；过渡期部署于香港服务器，不备案
- 增量成本 ¥0

## 期 1 口径（内部真跑 · 已定，不必再问）

- 地址用测试云现有 IP；域名归二期三期（待四项外部条件成熟）

| 外部依赖 | 期 1 内部替代 |

- **模拟态三处显式标注**：页面（前端文案）／接口（响应 `data_nature` 字段）／数据（每表 `data_nature` 列，默认 simulated）
- **最小访问控制（期 1 内部）**：全 API 口令门 `x-tdca-site-gate`（环境变量 `TDCA_SITE_GATE_KEY` 注入，fail-closed：未配置拒服）＋ 部署面 nginx basic auth 双保险；仅「不公布链接」不算数

## 常用命令

```bash
npm run dev      # 开发预览
npm run build    # 产物 → dist/
python scripts/sync_content.py --root ".." --check   # 内容脱敏预检（只读）
```
