## 〇、化合总式

```
第一重化合（工程三 ⊗ 场景）：
  试验 ⊗ 场景  → 安全结论的场景效度（脱离场景的 p<0.05 无意义）
  灰度 ⊗ 场景  → 灰靶的场景依存（同一指标在不同场景灰靶不同）
  可靠性 ⊗ 场景 → 失效模式的场景剖面（FMEA 沿场景画布六要素展开）

第二重化合（⊗ TDCA）：
  门控绑定   → admission/sandbox/production = 安全生命周期的三道判据门
  MOU 熔断   → 灰靶的硬下限（MOU ⊆ PSU，靶心距触底即熔断）
  NCA 确权   → 每个安全动作（降级/发布/熔断）发 NCA 存证
  NSFL 预检  → 负空间即安全边界，准入前强制扫描
  Shapley 定价 → 多智能体安全贡献与风险分摊按边际归因

```

涌现物：任一层单独不具备的**「场景化安全治理闭环」**——安全目标由场景涌现并确权（TDCA）、由灰靶框定区间（灰度）、由试验给出判据（试验）、由可靠性设计兜底（可靠性）、由 FRACAS 持续进化（闭环）。

**⚖️ 化合判据（用户 2026-08-30 20:52 裁定）**：化合 = 改变属性、产生新思维；叠加不改变属性，只产生两个独立思维的合作。本文所有化合条目以"属性改变"为判据写成——每条绑定都指明反应物属性 before→after 的变化（如灰靶从全局常数变为场景函数 target(scene)、FMEA 坐标从组件层级树变为画布六要素网格、门控从描述性映射变为可机验判据集），编译产物中由 `fusion_spec.attribute_changes` + `emergence` 涌现物判据强制承载。无属性改变的组合须降级标注为"合作"。

## 一、第一重化合：工程三协议 ⊗ 场景协议（七绑定）

### E1 场景依存灰靶（灰度 B1/B8 ⊗ 场景思维协议 · 场景即协议）

**化合语义**：安全灰靶不是全局常数，而是**场景依存效用**的产物。同一个智能体，在"内部文档摘要"场景幻觉率灰靶可放宽至 [3%,5%]；在"医疗问答"场景必须收紧到 [0%,0.5%]。场景变→灰靶漂移，这是规则不是例外。

- 绑定步：灰化定义阶段，「安全需求灰化」原语在**定义灰靶区间之前**必须先经场景思维协议界定场景归属（参与者网络/资源流动/价值流）。
- ⊗ 负空间：⊗ 禁跨场景复用灰靶（A 场景验收数据不得为 B 场景背书）；⊗ 禁场景未界定就定灰靶——那是悬空指标。
- 落地判据：每个灰靶必须携带场景标签 `target(scene)`，无场景标签的灰靶视为无效配置。

### E2 画布剖面 FMEA（可靠性 C4 ⊗ 场景画布）

**化合语义**：智能体 FMEA 的任务剖面分析（感知→推理→工具调用→行动→反馈）不是抽象链条，须沿**场景画布六要素**展开：每类参与者接触哪个失效模式、哪条资源流动承载失效传播、哪条规则缺口是根因、哪个技术架构节点是单点。

- 绑定步：容错架构设计阶段，「智能体FMEA」原语在**枚举失效模式时**嵌套调用场景画布模型，按六要素逐格扫描失效注入点。
- ⊗ 负空间：⊗ 禁脱离画布的通用 FMEA 模板直接套用（缺场景应力的 FMEA 是纸面作业）；⊗ 六要素缺任一则场景不可自持，FMEA 结论不可信。
- 产出物：带场景坐标的失效模式矩阵 `FMEA(canvas_cell × failure_mode)`。

### E3 涌现风险监控（灰度 B5 ⊗ 认知涌现）

**化合语义**：多智能体认知涌现产生价值的同时**涌现风险**——分散认知质变为协同场景，也可能质变为协同越权、共谋规避、级联幻觉。灰色关联分析的对象因此升级：不只监控指标序列，更监控**智能体间行为关联度的涌现结构**。

- 绑定步：灰度部署监控阶段，「关联监控」原语在计算关联度矩阵后增加涌现检验：关联度是否出现"无业务解释的同步偏离"。
- ⊗ 负空间：⊗ 禁把正常业务协同误判为共谋（须有业务基线对照）；⊗ 禁只监控单体指标遗漏涌现层——单个体全绿、整体越权是真实发生的失效。
- 判据：`emergent_risk = Σ 关联度异常 - 业务基线关联`，超灰靶即触发 E7 认知对齐复查。

### E4 嵌套失效传播（可靠性 C4/C6 ⊗ 嵌套法则）

**化合语义**：工具调用链、COP 嵌套调用、智能体委派链——都是**嵌套七元组**实例。FTA 自上而下分解时，割集沿嵌套结构走：每个嵌套层是一个潜在失效注入点，嵌套深度即传播级数。

- 绑定步：容错架构设计阶段，「故障树分析」原语在向下分解根因时按嵌套七元组逐层展开，最深层嵌套的失效对系统级顶事件的贡献必须量化。
- ⊗ 负空间：⊗ 禁 FTA 只展开两层就宣布根因找到（深层嵌套失效恰是最难归因的）；⊗ 禁嵌套链无 MOU 校验即放行（L2 协议层硬约束：嵌套调用必须携带 MOU 校验，如 TCP 校验和）。
- 产出物：嵌套级联割集表 `MCS(nested_path)`，单点故障清单按嵌套深度排序。

### E5 生命周期共适配（灰度 B9 ⊗ 生命周期适配）

**化合语义**：场景在演化，安全协议必须共适配。场景生命周期阶段（萌芽/成长/成熟/衰退）决定安全策略重心：萌芽期重 admission 灰化定义、成长期重 sandbox 对抗试验扩容、成熟期重 production 灰度监控、衰退期重退役与数据处置。滚动白化的对象从"指标序列"扩展为"指标序列 + 场景阶段双重修正"。

- 绑定步：灰度部署监控阶段，「滚动白化控制」原语的每轮预测-观测-修正循环中，先判场景阶段漂移，再修正灰靶与监控阈值。
- ⊗ 负空间：⊗ 禁场景已进入新阶段而安全策略停留在旧阶段配置（错配即风险敞口）；⊗ 禁一次性校正后不再复盘（与 B9 原生禁忌叠加）。
- 判据：每轮滚动修正须输出 `scene_stage + target_drift` 二元组，漂移超限触发灰靶重定义（回到 E1）。

### E6 治理化失效闭环（可靠性 C8 ⊗ 数据治理）

**化合语义**：FRACAS 的血液是失效数据，失效数据本身就是场景数据资产——须过数据治理：失效事件确权（谁报告、谁拥有、谁可读）、质量门（录入即校验，防脏数据污染根因分析）、合规边界（含用户隐私的失效样本须脱敏后才能进入 FRB 分析与模型重训）。

- 绑定步：灰度部署监控阶段，「FRACAS运行」原语在失效报告入口处嵌套数据治理 COP：确权→质量校验→脱敏→入库。
- ⊗ 负空间：⊗ 禁未确权的失效样本进入共享知识库（确权缺失=责任链断裂）；⊗ 禁为分析便利绕过脱敏（合规红线优先于根因分析效率）。
- 产出物：每条失效记录携带 NCA 确权戳 + 质量分 + 脱敏标记三件套。

### E7 认知对齐门（试验 A8 ⊗ 认知模型衔接）

**化合语义**：安全预警的最终消费者是双通道的——人类监督者（靠场景直觉决策）与智能体看门狗（靠 MOU 等硬信号维持）。认知模型衔接 COP 保证同一安全事件在两个认知模型中被**同频理解**：人类的预警可读、智能体的判据可算，且两者不矛盾。

- 绑定步：试验检查门控阶段，「trial_check_gate」的门控项在人工评审环节嵌套认知对齐校验：评审者与自动化门禁对同一证据的判定若冲突，禁止放行并升级 FRB。
- ⊗ 负空间：⊗ 禁双通道判定冲突时默认信任自动化（人类否决权优先，但须留痕）；⊗ 禁预警只有人类可读格式（智能体看不懂=看门狗失明）。
- 判据：门控通过须同时满足 `human_signoff ∧ machine_gate_pass`，冲突即熔断升级。

## 二、第二重化合：⊗ TDCA 协议（门控总装）

### F1 门控绑定：四阶段安全生命周期 × 三阶段准入

04 协议的映射在此正式化为**门控判据**（每道门有可机验的准入条件，不允许"口头过门"）：

| TDCA 门 | 准入判据（全部满足才放行） | 化合来源 |
|---|---|---|
| admission | ① 场景已界定（E1 场景标签就位）② 灰靶已定义且带场景标签 ③ FMEA 画布剖面完成（E2）④ NSFL 预检通过 ⑤ NCA 确权就绪 | 工程三 ⊗ 场景 ⊗ NSFL |
| sandbox | ① 受控对抗试验按惟一差异执行（A1/A2）② 攻击向量经分式/正交筛选 ③ 增长试验 RGT 态标记（允许边试边改）④ E3 涌现监控在线 ⑤ 嵌套链 MOU 校验通过（E4） | 试验 ⊗ 灰度 ⊗ L2 硬约束 |
| production | ① RQT 验证试验独立复验通过（禁边测边改）② 灰度发布区组设计就位 ③ FRACAS 闭环已激活（E6 治理化）④ E5 场景阶段监控上线 ⑤ 首次真实配置权调用路径就绪 | 可靠性 ⊗ 试验 ⊗ TDCA 机制 |

**门控纪律**：任何一门判据不全即 fail-closed（默认拒绝），允许降级到低阶门但禁止跳门。门控行为（放行/拒绝/降级）各发一条 NCA 存证。

### F2 MOU 熔断：灰靶的硬下限

灰靶决策（B8）给出区间管理，MOU 给出**不可谈判的底**：

- 灰靶是"运营区间"（可调、可协商、场景依存），MOU 是"氧气浓度"（低于即熔断，无协商空间）。
- 合成规则：`正常态 = 靶心距 ∈ 灰靶 ∧ MOU ≥ 熔断线`；`黄色预警 = 靶心距近边界 ∨ MOU 缓降`；`红色熔断 = 靶心距出靶 ∨ MOU 触底`。
- 熔断后强制路径：降级/停机 → NCA 存证 → FRACAS 录入（E6）→ 根因（FTA×E4）→ 纠正 → A/B 验证（惟一差异）→ 灰度恢复。
- ⊗ 负空间：⊗ 禁用灰靶区间宽裕掩盖 MOU 触底（灰靶再宽，MOU 是底线）；⊗ 禁熔断后不闭环直接恢复。

### F3 Shapley 安全定价：贡献与风险的边际归因

多智能体系统中"谁的失效贡献最大""谁的安全投入最值得"不能靠直觉，按 Shapley 值归因：

- **风险侧**：对级联失效事件，计算各智能体在所有参与顺序下的边际失效贡献 → Shapley 风险份额 → 定向加固优先级（E4 割集表 × Shapley 排序）。
- **投入侧**：各安全模块（watchdog/规则/HITL/缓冲）对系统可用度的边际贡献 → Shapley 安全价值 → 灰色规划预算分配（4.2 节灰参数规划的目标函数权重）。
- 与灰色关联（B5）的关系：灰色关联给**排序快筛**（贫信息低成本），Shapley 给**精确归因**（信息充足时启用）——两级归因，按信息灰度选级。
- ⊗ 负空间：⊗ 禁用占位 agent 冒充联盟成员计算 Shapley（套套逻辑归因无效，须真实行为数据）；⊗ 禁贫信息态强行精算（先灰关联，数据白化后再 Shapley）。

### F4 全链存证：NCA × 链式水印 × NSFL

- **NCA**：门控行为（F1）、熔断与恢复（F2）、归因裁定（F3）、失效录入（E6）——四类事件强制 NCA 存证，COP 编译产物 nca_emit 就绪。
- **链式水印**：安全事件链按 prev_hash 衔接（对齐 mcp_bridge Watermark 模式），任何事后篡改可检测——FRACAS 数据的可信性由此保证，而非靠存储介质可信。
- **NSFL**：负空间即安全边界。每 COP 的 ⊗ 负空间条目与 NSFL 通用禁忌（V0.1）合并预检，`scan_nsfl_text` 作为 admission 门禁组件（单一事实源，行级否定豁免）。
- ⊗ 负空间：⊗ 禁存证缺失的熔断（不可追溯的熔断等于没熔）；⊗ 禁 NSFL 预检绕行（门禁组件不可配置关闭）。

## 四、执行检查清单（双层化合版）

**化合配置层**
- ☐ 每个灰靶是否携带场景标签 `target(scene)`？跨场景复用是否已禁止？
- ☐ FMEA 是否沿画布六要素逐格扫描？是否存在未覆盖的六要素格子？
- ☐ FTA 是否展开到嵌套链全深度？深层割集是否量化？

**门控层**
- ☐ admission 五判据、sandbox 五判据、production 五判据是否全部可机验？
- ☐ 门控行为是否全部 NCA 存证？是否存在口头过门记录？
- ☐ NSFL 预检是否为 admission 门禁组件且不可配置关闭？
- ☐ **F1.5 否决权是否恒居决策树第一步**：NSFL 预检未过的事件，即使其他四判据全部通过，是否已整体拒绝（Fail-Closed）？

### F1.5 否决权（宪法条款，用户裁定 2026-08-30 21:07）

> **"对于任何无法通过 NSFL 预检的事件（负空间触碰），即使其他四判据全部通过，亦视为整体拒绝（Fail-Closed）。NSFL 预检的优先级永远高于其他四判据。"**

- **位阶**：负空间是安全宪法的宪法——五判据是门的法律，否决权是门的宪法；法律不得违宪，判据不得推翻否决。
- **执行语义**：否决预检恒居决策树第一步，未过即整体拒绝并 NCA 存证（原因码 veto），其余判据**短路不评**——不是"再看看其他判据能否救回"，而是根本没有评审资格。
- **不可推翻性**：禁止以多数判据通过、场景豁免、上级指令、降级重试等任何理由放行 NSFL 未过事件；该条款不可配置关闭。
- **化合属性改变**（对应 F1 fusion_spec 第三条）：NSFL 预检从"admission 五判据之一（与四判据并列）"变为"F1.5 否决权（恒居首、短路其余、优先级恒最高）"——这是属性跃迁而非叠加。
- **传播范围**：该条款写入全部 41 个 COP 的 `composition_policy.constitution` 与通用负空间（禁止否决权被推翻），不限于 F1。

### F1.5b 四态动态处置（动态管理修正，用户裁定 2026-08-30 21:19）

> **"TDCA 是动态管理，负空间虽然本质保守不轻易变化，但是还是会变化的——现在被定性为触犯负空间，不等于未来一定仍然是触犯负空间的行为。所以 TDCA 对在沙盒检验中判定触犯负空间的一般处置是：休眠 / 禁止 / 重塑 / 出清。"**

- **与 F1.5 的位阶关系**：否决权的不可推翻性**仅指即时门控裁决**（当下过门资格被封锁），**不指永恒身份**——拒绝是刚性的，处置是动态的，两者并存不冲突。
- **四态定义**（sandbox 检验触犯负空间后的裁定，裁定本身 NCA 存证）：
  | 四态 | 语义 | 后续 |
  |---|---|---|
  | **休眠** | 实体保留、暂停活动，等待负空间演化 | 负空间版本更新时**强制重评** |
  | **禁止** | 当前负空间版本下永久拒入 | 负空间修订涉及其触犯条款时可转休眠/重塑 |
  | **重塑** | 改造实体至合规后重走门控 | 重塑完成须全链重验（admission 起步） |
  | **出清** | 清出体系 | 全链留痕，不可静默消失 |
- **负空间版本化**：负空间本身随 TDCA 动态管理演化（NSFL 版本号追踪），触犯判定锚定**判定时的版本**——版本更新触发休眠/重塑态实体重评，这是"保守不轻易变化"与"仍会变化"的机制化平衡。
- **禁悬置**：否决后必须进入四态处置之一，不允许"既不休眠也不出清"的模糊悬置态（负空间新增禁令）。
