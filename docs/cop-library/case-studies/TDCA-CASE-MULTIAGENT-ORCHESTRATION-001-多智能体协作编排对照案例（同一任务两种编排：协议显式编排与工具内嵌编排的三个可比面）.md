# 多智能体协作编排对照案例：同一任务，两种编排

> 案例编号：`TDCA-CASE-MULTIAGENT-ORCHESTRATION-001`
> 版本：`V1.0` ｜ 日期：`2026-11-12` ｜ 性质：**应用案例（模拟态内部实验）**
> 数据性质：`Simulated` —— 本次为内部对照实验，非对外承诺、非实盘成效
> 披露：本案例含 AI 生成内容；不点名具体外部工具，以避免暗示任何背书

---

## 一、一句话

同一个任务，交给同一类外部 AI 工具做两次：一次要求它**按我方协议自己做编排**，一次**用它自带的默认编排**。成品打平，**过程资产化程度 `15 : 0`**。

---

## 二、实验怎么设的

| 项 | 设定 |
|---|---|
| 任务 | 相同：编辑一份同一主题的介绍材料（12 页） |
| 执行工具 | 相同：一款外部 AI 编程工具 |
| 人员介入 | 相同：无人逐步指导 |
| ⭐ 唯一变量 ⭐ | ⭐ 是否要求它按我方思维协议做任务编排 ⭐ |
| 对照次数 | 各一次 |

⭐ 注意一点 ⭐ ：第二次并**不是「没有编排」** ——它用的是工具**自带的、内嵌的、看不见的**编排。⭐ 所以本实验比较的不是「有制度 vs 没制度」，而是「**显性编排 vs 隐性编排**」 ⭐ 。

---

## 三、两次过程长什么样

| | A 组 · 协议编排 | B 组 · 工具默认编排 |
|---|---|---|
| 角色声明 | 5 份，各自写明身份、能力集、**不许越什么界** | 无 |
| 准入校验 | 5 份，逐件过校验规则 | 无 |
| 中间产物 | 3 份（叙事方案／事实核验／视觉方案） | 无 |
| 存证链 | 1 条，哈希逐条咬合，首条为起始锚 | 无 |
| 过程报告 | 有（九章，含 6 个问题与修复） | 无 |
| 制度层产物合计 | ⭐ `15` 件 ⭐ | ⭐ `0` 件 ⭐ |
| 交付用时 | 28 分 44 秒 | 未计时，迭代 6 轮版面修正 |

## 四、三个可比面

### 4.1 编排显隐

| 问 | A 组 | B 组 |
|---|---|---|
| 能说出分了几个角色吗 | ✅ 五份声明逐条可读 | ❌ ⭐ 说不出 ⭐ |
| 能说出每个角色的边界吗 | ✅ 负空间条款逐条列明 | ❌ 无 |
| 编排能改吗 | ✅ 改声明、重跑校验 | ❌ ⭐ 改不了（只能换工具或版本） ⭐ |

### 4.2 可审计性

| 层 | A 组 | B 组 |
|---|---|---|
| 准入 | ✅ 一条命令、50 个断言、退出码可判 | 无 |
| 边界 | ✅ 越权／职责／循环引用三查 | 无 |
| 存证 | ✅ 哈希逐条咬合 | 无 |
| 过程 | ✅ 九章报告，问题与修复逐条 | 无 |
| 仅剩 | —— | ⭐ 版面检查「零溢出」 ⭐ |

⭐ 一句话判别 ⭐ ：⭐ A 组的审计不需要原班人马在场；B 组的审计必须找到那次会话 ⭐ 。换个人接手，⭐ A 组能自证，B 组只能「信」 ⭐ 。

⭐ 还有一层易混 ⭐ ：**读脚本 ≠ 审过程**。脚本是结果，不是过程记录——从脚本看不出「为什么这样而不是那样」，更看不出中间否决过哪些方案。

### 4.3 可否成为复用资产

| 可复用要素 | A 组 | B 组 |
|---|---|---|
| 角色模板 | ✅ 换能力集即可复用 | ❌ |
| 校验模板 | ✅ 字段固定，可套 | ❌ |
| 存证机制 | ✅ 可脚本化 | ❌ |
| 过程范式 | ✅ 九章结构可套 | ❌ |
| 迭代中学到的经验 | ✅ 已写成可查件 | ⚠️ **真实的，但停在会话里** |
| ⭐ 可复用件数 ⭐ | ⭐ `15` ⭐ | ⭐ `0` ⭐ |

⭐ B 组那 6 轮调试买到的经验是真的 ⭐ ——圆间距系数、页脚安全线、密集三行必须物理分开——⭐ 但这些还停在会话记录里，没变成任何人能取用的资产 ⭐ 。⭐ 这不是 B 组的错，是「不写下来就不成为资产」的规律 ⭐ 。

## 五、四条可核判据（做完材料后自检）

本案例顺带沉淀出四条判据，用于检查一份材料「有没有递进逻辑」——全部可点数、可复现：

| # | 判据 | 查法 |
|---|---|---|
| 1 | 有问题定义页吗 | 是否有一页把要解决的问题列成 N 条（N ≥ 2） |
| 2 | 问题与答案对得上吗 | 每条问题能否在后文至少一页被显式回应（可列对照表） |
| 3 | 有贯穿全篇的论点句吗 | 是否有一句立场句，出现在开头／中段／结尾三处 |
| 4 | 标了证据强度吗 | 是否至少有一处标「已验证／未定」，且愿自曝最难一条 |

⭐ 缺第 1、2 条者，材料必然滑成知识点并列 ⭐ ——页面各自都对，但读者不知道「为什么从这页到那页」。

## 六、三点发现

1. ⭐ 「没有制度」是幻觉 ⭐ 。任何协作都有编排，区别只在编排是**写下来的**还是**藏起来的**。
2. ⭐ 黑箱能干出漂亮的活 ⭐ 。B 组成品与 A 组打平（版面检查都零问题），28 分钟出活——代价是**过程不可审、不可复用、不可改**。
3. ⭐ 本案例顺手自证了一件事 ⭐ ：B 组的编排正是一只**看不见的黑箱**。能用、好用，但你不知道里面发生了什么。两次任务的差别，恰是「从黑箱驱动到制度驱动」这一句。⭐ 这说明该主张不是口号 ⭐ ——它可被一次普通对照实验检验。
