## 摘要

当前所有智能体平台（无论闭源商用或开源编排）在"创建智能体"环节上**结构性缺席**：它们提供的是调参与编排，不是创建。TDCA 的创建论与它们有本体论级区别：**创建智能体 ＝ 制度反问题的显式求解**——从期望效用出发，反解出此前不存在的显式函数，经编译成为可确权、可验收、可复用的资产；而提示词预装是前向拟合未声明的函数，编排是对既有能力的连线。**TDCA 不生产解，TDCA 担保可解**——通过维护正交的资产基、确定性的判定基座、与开放的铸造流水线。

## 一、问题缘起

三问引出本报告：

1. TDCA 不做协作工作台式智能体平台，原生智能体如何创建？
2. TDCA 依赖大模型算力，是否动摇"制度红利大于技术红利"？
3. 当前平台与 TDCA 在创建环节的区别是否本质？

三问的答案收敛为一句话：**创建权在生态，可解性担保在 TDCA；算力可租，判定不可租；平台编排行为，TDCA 生产资产。**

## 二、创建的本体论：反函数求解

**命题（本报告核心条目）**：智能体创建 ＝ 制度反问题的显式求解。

- **前向（LLM 路径）**：权重 ＋ 提示 → 行为。函数从未被声明，行为靠拟合与祈祷；同 prompt 不同结果，验证靠抽样。
- **反演（TDCA 路径）**：期望效用 → 显式函数。函数语料的**七要素**（目标函数／约束矩阵／先验分布／配置权边界／预期分配／审计轨迹／负空间约束）即反问题的完整声明；制度与语言之间的同构跃进（**Compile，非蒸馏**）执行反演，产出可编译到任何载体的显式函数。
- **验收**：前向求值 f(x) 对照预期输出——确定性判定，一次计算，成本远低于评测。

> ⚠️ **要素同名须分（对外须守）**：本报告所称"函数语料七要素"，指**函数资产**的声明结构（上面七项）；它与**智能体创世声明**所用的"六要素"（设备／算力／协议／角色／知识／权限时效）是**两套不同的东西**，同名而异指，勿混读。前者判"这个函数做什么、受什么约束"，后者判"这个智能体由谁、以何资源、加载何协议、以何角色、凭何知识、权限多久"。

推论（工程判据）：**任何"创建智能体"任务，若产出物不能被表述为要素齐全的显式反问题（规范 ＋ 可前向验证的预期输出），则它不是在创建智能体，只是在写提示词。** 此判据可作为任务卡准入检查，零成本。

## 三、适定性三分类与三值制度的同构

反函数求解的良态性三条件，与主定理三值空间构成精确同构：

| 适定性条件 | TDCA 对应 | 三值落位 |
|---|---|---|
| 存在性 | 正和性：存在各方获益的配置 | 有解 → 正空间（可证明） |
| 唯一性 | 不要求唯一；多解由场景权重排序 | 多解竞争 → 沙盒比较 |
| 稳定性 | 审计轨迹：规范微变可被前向求值检验 | 不稳 → 熔断／升级人工 |
| 不适定·解不存在 | 不可算计，不给概率答案 | 负空间（归人裁决） |
| 不适定·尚未判明 | 效用叙事未经数据验证 | 沙盒（未裁决） |

**三值空间 ＝ 适定性三分类的制度化。** 主定理本体论与创建论由此焊接为同一张表的两面。

## 四、可解性担保：资产基与右反条件

右反存在 ⟺ 原映射满射：每个期望效用都有非空原像。这定义 TDCA 的供给侧职责——**生态负责求解，TDCA 负责可解**。要点三条：

1. **"足够多"的正确读法 ＝ 基的秩，不是库存量。** 覆盖靠基元的正交性与组合性：一万个同质化"写周报函数"不如十个正交基元。候选基已存在于体系：五阶效用（元素价态）、函数语料七要素（基元晶格）、场景量子（最小组合单元）。资产库靠组合式增长（化合／嵌套），不靠采购式增长。
2. **版权是资产库的供油系统。** 供给激励链：可调用（接口）→ 可配置（配置权边界）→ 可拥有（权属登记）→ 可定价（场景权重／版税／调度税）→ 有供给 → 库自增长 → 可解性扩大。"被调用的知识才是有价值的知识"即此飞轮。
3. **两条纪律**：反解命中率（incoming 规范中当前资产库可解的比例）为充足度核心指标；入库严选门槛（每个新基元须举证覆盖此前不可解方向，对齐破例识别——声称必需即须举证）。

## 五、判定基座与算力基座的切分

**命题**：TDCA 依赖大模型算力，但不依赖大模型判定。

三层架构：判定基座（宪法函数集——确定性、可复验、换模型判定不变）／语义层（人机与机机互译——大模型主场，理解翻译不算账）／算力基座（可租可换的被配置对象）。

- **硬判据**：任何制度判定，换掉底层模型后结果必须不变；若变，说明那是模型意见穿了制度的制服。概率推理进判定基座 ＝ 幻觉进宪法。
- **不可判定归人**：语义层遇到制度函数覆盖不了的问题，不许模型给概率裁定，走升级人工——与负空间熔断是同一根保险丝的两个档位。
- **与制度红利原则的关系**：依赖"算力存在"是配置关系，依附"某个模型"才是依附关系。银行依赖电力，但电网不能取代账本。双向校准闭环（模型迭代 ↔ 制度数据回流）是共同演化，非单向依赖。
- **工程测试**："换模型判定不变"测试进持续集成——同一任务卡送两个不同模型执行端，回执判定字段须一致；不一致即暴露语义层翻译漂移，或"模型意见冒充制度判定"。

## 六、平台化形态：函数大模型

TDCA 唯一正确的平台化形态是**函数大模型服务**（制度推理开放接口），而非智能体应用平台：

| 大模型开放平台 | 函数模型开放平台 |
|---|---|
| 对话补全接口，卖概率 | 判定接口，卖判定 |
| 上下文窗口 | 场景边界（负空间排除 ＋ 配置权边界） |
| 权重（训练） | 宪法函数集（显式设计） |
| 幻觉 | 越权判定（负空间熔断兜底） |
| 微调 | 活宪法在线升级 |
| 跑分评测 | 沙盒判例集（硬数据裁决） |

**中立性反而随平台化加固**：判定可复验 → 不可垄断判定 → 收费只能在便利层（协议层免费这一纪律的架构化）。第一批端点从现有资产长出（智能体能力名片握手通道 ＋ 效用精灵能力接口化）：正和判定、配置权边界判定（代理链衰减语义）、场景权重判定、存证锚定（登记证据包）。响应三要素：**判定 ＋ 策略版本号 ＋ 复验路径**（对齐安全行业的决策记录标准）。

## 七、编排、调参、创建：三级台阶与平台的结构性缺席

| 层级 | 动作 | 产物 | 代表 |
|---|---|---|---|
| L1 调参 | 往既有函数塞提示 | 无产物，只有输入 | 普通用户 |
| L2 编排 | 既有能力连线排序调度 | 配置——依附平台的视图 | 各类工作流平台 |
| L3 创建 | 反解并编译新函数 | 资产——独立存在、可确权、可验收 | TDCA 函数语料 |

编排产物四试金石全败：删平台即蒸发（无独立存在）；无资产化通道（无确权）；验证靠试运行（无确定性验收）；天花板 ＝ 模型能力（技术红利，折旧）。

**平台停留在编排是激励结构决定的**：编排按用量计费（词元／席位／执行次数），用户编排越久平台收得越多；真正创建以一次编译完成资产化，资产化即脱钩。平台没有动机把租户变成业主——"创建"按钮在编排平台功能清单里结构性缺席，不是没排进路线图，是排进去就背叛收入模型。

**诚实边界**：编排不是原罪。一次性任务、单一信任域内，编排更便宜（最小化合）；TDCA 体系内编排有其位置（配置权调度即撮合连线），但其上压着编排平台没有的两层楼——资产层与判定层。

### 7.1 编排的合法性域与可信缺陷清单

**不否定编排**：它是有效的协作流程——单一信任域、一次性任务、探索性工作中，编排够用、便宜、该用则用。本节划定的是：一旦目标定义为"可信协作"，编排的缺陷是结构性的。六个必要条件，六处缺席：

| # | 可信协作的必要条件 | 编排范式的结构性缺席 |
|---|---|---|
| 1 | 信任锚可脱离平台存续 | 信任锚在编排器／运营商；平台被攻陷、改规则、退出，信任即蒸发 |
| 2 | 确权与责任链（责任落到节点） | 产物是配置不是资产，无所有权即无责任；事故中每个节点都只说"我按流程走的" |
| 3 | 区分"流程发生"与"结果可信" | 只有运行留痕、没有判定留痕；系统中不存在"凭什么可信"的数据结构 |
| 4 | 负空间可表达 | 工作流编码"要做什么"，编码不了"不许做什么"；只能记录发生过的事，无法担保没发生的事 |
| 5 | 跨主体可运行 | 图必须有一个持图人——跨企业编排意味着一方可见全局、可改全局规则；拓扑矛盾，非功能差距 |
| 6 | 激励兼容（规则稳定、变更权收束） | 按用量计费，平台有动机让用户永远当租户；单方面规则变更权 ＝ 制度不稳定性的同义词 |

**关系定型**：编排回答"水按什么形状流"，制度回答"水凭什么可饮用"。编排可作为可信协作的**载体**（工作流可承载任务卡、跑铸造流水线），但不能作为可信的**定义层**——水管的形状随意设计，水质标准必须长在管道之外。由此修正 §七"三级台阶"的表述：L3 不是 L2 的替代，而是 L2 的上层——创建产生资产，编排搬运资产，制度担保资产。**编排范式在可信协作中的正确定位：被制度殖民的流程层。**

## 八、TDCA 的职责边界与红线汇总

**供给职责四件**：定晶格（资产接口标准）、播种子（参考场景包）、通回路（调用→数据→权重→定价→供给飞轮）、担保可解性（登记／严选／覆盖度量）。

**参考实现四红线**（承接"不造平台"之问）：最小性（指标 ＝ 被第三方替换的容易程度）、无特权（协议特性不得依赖参考实现）、同台受审（与第三方过同一套持续集成与哈希对账）、无席位（永远免费无配额）。

**平台化三红线**：判定逻辑全部开源可复验；响应必带策略版本 ＋ 复验路径；判定本身永不按次收费（收费只在调度／撮合／场景包层）。

**判定层三纪律**：模型中立（全链路对模型无感）；判定确定性（可复验 ＋ 换模型不变测试进持续集成）；不可判定归人（升级人工，不给概率裁定）。

## 九、工程落地：任务书生产线 ＝ 函数铸造

近期实践已构成创建论的活体样本：每张走完治理流程（提案→治理审查→沙盒→任务书→执行→复核→签批→落档）的任务书，不再是一次性指令，而是一个可复用函数的出生证明。落地三步：

1. **命名**：任务书生产线正式命名为"函数铸造车间"——产出从"文档"升格为"出生登记"；
2. **准入**：铸造入口加装反问题判据（§二推论）——要素不全的规范退回沙盒补全；
3. **度量**：铸造产出计入反解命中率的资产侧；每份出生登记带哈希与策略版本。

## 十、结论

智能体行业在 L1（调参）、L2（编排）挤成红海，L3（创建）结构性无人——因为创建背叛平台的收入模型，而 TDCA 的收入模型（协议免费 ＋ 资产层收税）恰恰**只从创建的成功中获利**：函数被铸造、被调用、被化合，制度才有税基。

一句话收拢：**平台把你留在流程里，TDCA 把你写进函数里；秩序不生产函数，秩序保证函数总在可解之处，并让每一次求解都留下可确权、可验收、可复用的出生证明。**
