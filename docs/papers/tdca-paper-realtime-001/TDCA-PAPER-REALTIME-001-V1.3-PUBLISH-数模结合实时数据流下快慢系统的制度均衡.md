## 摘要

参数大模型（PLM）的进化正在遭遇「数据墙」：人类存量高质量语料趋于枯竭，合成数据因模型崩溃而无法独立产生真正的信息熵增。本文指出，突破这一瓶颈的关键不在于「找更多存量」，而在于将数模结合从**离线训练态**切换为**实时运行态**——实时数据流，而非静态语料，才是下一代数模结合的正确打开方式。

然而，实时数据流对系统提出了快慢系统失衡的根本挑战：快系统（AI 智能体）以毫秒级并发吞吐数据流，慢系统（人类与制度）的响应带宽无法与之匹配。若快系统无制度约束，实时流中的单点幻觉会被瞬间放大为系统性崩溃；若慢系统试图介入每一笔实时交易，则必然被速度碾压。

本文提出面向实时数据流的函数大模型运行时范式，以**函数大模型（FLM）**为运行时执行器、以**实时确权链**为实时确权层、以**负空间熔断器**为毫秒级刹车、以**税收锚定**为实时价值刻度，构建快慢系统在实时数据流前的制度均衡。核心论断：实时数据流中，数模结合的正确形态不是「模型消费数据」，而是「**数据触发函数、函数锚定制度、制度回流数据**」的三相闭环。本文给出实时均衡的形式化定义与三项可检验条件，并给出可检验的扩展验证路径。

**关键词**：实时数据流；数模结合；函数大模型；快慢系统均衡；实时价值锚定；负空间熔断

## 1 引言

### 1.1 数据墙：静态数模结合的终局

当前大模型的训练范式可概括为：以静态存量语料拟合参数权重。这一范式的物理上限已清晰可见：

- **存量枯竭**：高质量公开文本数据将在可预见的时间窗内耗尽；
- **合成数据失效**：以模型输出训练模型，将导致分布坍缩——输出趋于平庸、幻觉累积、多样性衰减；
- **版权与合规压力**：对存量数据的无差别爬取正面临全球范围的司法与监管反弹。

结论明确：静态存量不足以支撑下一阶段的模型进化。继续在「找更多旧数据」上做功，是死路。

### 1.2 本文主张：实时数据流是数模结合的正确打开方式

> **范式级主张（模型层主张，可竞争可证伪）**：数模结合的未来不在「离线训练」，而在「实时运行」。

实时数据流——高频交易信号、传感器遥测、机机协作请求、数字人民币结算事件、税务代扣代缴流水——具备存量语料所不具备的三个属性：

1. **不可穷尽性**：实时流持续产生新事件，不存在「被吃光」的问题；
2. **物理锚定性**：每个事件背后有真实的价值交换与责任归属（税收、交付、违约），而非纯文本的语义漂移；
3. **熵增性**：每个新事件都可能引入之前从未出现过的组合状态，为模型提供真正的「新数据」。

然而，实时数据流不是免费的午餐。它将数模结合从「慢速、离线、可回滚」的形态，推入「高速、在线、不可回滚」的形态。这直接引出本文的核心问题：

> 当数据以毫秒为单位流动时，数模结合如何不被速度撕裂？

### 1.3 核心挑战：快慢系统在实时流前的失衡

| 系统 | 代表 | 时间尺度 | 失效模式 |
|---|---|---|---|
| 快系统 | AI 智能体、自动执行器 | 毫秒–秒 | 幻觉放大、连环违约 |
| 慢系统 | 人类、制度层、司法 | 小时–年 | 响应延迟、无法实时介入 |

若只有快系统：流中单点错误被瞬间放大（历史上「闪电崩盘」即为先例）；若只有慢系统：无法吞吐实时流，系统整体吞吐量被人类带宽封顶。

实时数据流要求一种新的均衡：**快系统在流中执行，慢系统在流外划界；快系统以制度原语为约束，慢系统以制度原语为锚定**。

### 1.4 本文贡献

1. **理论**：给出实时数据流下数模结合的形式化定义，明确「数据触发函数、函数锚定制度、制度回流数据」的三相闭环；
2. **机制**：给出四项运行时原语（执行器、实时确权、毫秒熔断、实时锚定）的实时化适配方案；
3. **均衡**：给出快慢系统制度均衡的数学定义与三项可检验条件；
4. **验证路径**：给出可检验的扩展验证设计（含最小实证与长期路径）。

## 2 相关工作

### 2.1 数据墙与合成数据

数据墙问题已获广泛讨论：高质量语言数据将在可预见窗口内耗尽。合成数据被视为补位方案，但已有研究证明：递归使用模型生成数据训练会导致模型崩溃——分布尾部丢失、多样性衰减、稀有事件被系统性遗忘。

本文区分两种合成：

- **化合**：模型内部重组已有知识，产生「新组合」但无新信息；
- **实时化**：真实数据流触发模型执行，产生带外部锚定的新事件。

前者是存量重组，后者才是增量产生。

### 2.2 实时机器学习与流处理

实时 ML 已有成熟工程栈。但这些系统的核心假设是：**模型是固定的，数据是流动的**；模型仅在参数层面做增量更新，不涉及制度层约束。

本文的差异在于：**函数固定，模型与数据同时流动**；数据不是被消费的，而是触发函数复合与制度锚定的。

### 2.3 制度-技术同构与三层真值

既有工作已建立：函数大模型（以编译替代训练、以配置权调用替代统计采样）、制度-技术同构（制度规则可直接编译为技术组件）、可计算审计还原性（任何制度函数必须存在可计算验证器与右逆）、三层真值制度（**正空间可证 / 负空间可断 / 沙盒可验**）。

本文在这些基础上，将静态协议设计推进到**实时运行时范式**；§5.2 的三项条件即三层真值可信性在实时场景的实例化。

## 3 问题形式化：实时数模结合

### 3.1 实时数据流

**定义 3.1（实时数据流）** 实时数据流为一**离散事件序列**：

$$\mathcal{D}_{rt} = \{ d_i \}_{i \in \mathbb{N}}, \quad d_i = (\tau_i, p_i, t_i, s_i)$$

其中每个事件携带（$t_i \in \mathbb{R}^+$ 为物理时间戳，满足 $i < j \Rightarrow t_i \leq t_j$）：

- **触发条件 $\tau_i$**：何种条件被满足（价格越过阈值、传感器越界、协作请求到达）；
- **载荷 $p_i$**：事件的实质内容（交易金额、请求参数、状态变更）；
- **时间戳 $t_i$**：事件发生的物理时刻；
- **来源 $s_i$**：事件发起主体（人、智能体、设备、制度接口）。

### 3.2 实时数模结合

**定义 3.2（实时数模结合）** 实时数模结合是如下映射：

$$\mathcal{M}_{rt}: \mathcal{D}_{rt} \times \mathcal{F}_{FLM} \rightarrow \mathcal{E}_{exec} \times \mathcal{A}_{anchor}$$

- $\mathcal{F}_{FLM}$：函数工件空间（协议库、配置权协议、硬约束族）；
- $\mathcal{E}_{exec}$：执行结果空间（判定、调用、熔断）；
- $\mathcal{A}_{anchor}$：锚定空间（确权记录、税收锚定、结算哈希）。

映射语义：实时数据流中的每个事件，触发函数工件的执行，执行结果同时产生**执行动作**与**制度锚定**。

| 维度 | 静态数模结合 | 实时数模结合 |
|---|---|---|
| 输入 | 静态语料库 | 离散事件流 |
| 处理 | 梯度下降 / 蒸馏 | 函数调用 / 化合 |
| 输出 | 参数更新 | 执行 + 锚定 |
| 时间 | 离线 | 毫秒级在线 |
| 可回滚 | 是 | **否（以熔断 + 补偿替代回滚）** |
| 锚定 | 无 | 确权 + 价值锚定 |

### 3.3 三相闭环

```
实时数据流 ──触发──▶ 函数执行 ──产生──▶ 执行 + 锚定
    ▲                                        │
    └──────── 制度回流（确权/锚定/熔断）◀─────┘
```

三相闭环使系统具备自反性：每一次执行都改变下一次执行的制度环境，而制度环境又约束下一次执行。

## 4 运行时四项原语的实时化

### 4.1 执行器：从静态编译到实时调用

补足三个运行时属性：

- **属性 1（低延迟函数检索）**：函数工件检索须在毫秒级完成——将协议库索引化为内容寻址存储，以输入哈希直接定位；
- **属性 2（化合的深度约束）**：实时流中禁止无界化合——由熔断器对化合深度设上限 $D_{max}$，超出即熔断；
- **属性 3（模型无关性保持）**：运行时切换底层模型不改变函数工件的执行语义——函数工件以六要素为类型签名。

### 4.2 实时确权：从批量存证到流式哈希

- **适配 1（流式哈希）**：每个事件执行完成后立即产生哈希，不等批次；
- **适配 2（轻量级确权）**：实时确权仅存证「输入哈希 + 输出哈希 + 函数标识 + 时间戳」，完整轨迹异步写入；
- **适配 3（状态压缩）**：以 Merkle 树对事件批次压缩，保留可验证性同时降低存储。

### 4.3 毫秒熔断：从规则检查到执行中断

- **机制 1（前置熔断）**：执行前检查负空间清单；若事件落入负空间，直接阻断，不进入执行；
- **机制 2（执行中熔断）**：函数化合过程中，若任一步骤触碰硬约束，立即中止，并以**Saga 式补偿**恢复最近合法状态（实时流不可回滚，补偿 = 中止 + 后续修正事件）。补偿动作本身为耗时事件，其上界记为 $L_c$（**工程目标值，待实测**），并计入合成延迟 $L_{\Sigma} = L_N + L_S + L_M + L_c$；
- **机制 3（后置熔断）**：执行完成后，若价值锚定失败，场景效用权重归零，触发负空间熔断。

三档熔断的**目标延迟**（**工程目标值，待实测定标**）：

| 档位 | 目标延迟 | 动作 |
|---|---|---|
| 黄灯 | < 1 ms | 记录警告，继续执行 |
| 红灯 | < 10 ms | 暂停，移交人工裁定 |
| 黑灯 | < 100 ms | 终止 + 补偿 + 告警 |

**隔离舱语义（拒绝全局冻结方案）**：熔断事件进入隔离的 Blocked 通道，补偿异步执行，**未受污染的干净主流继续流动**；冻结只作用于受污染的最小范围。反对「补偿期间全局冻结」的理由：全局冻结意味着单次熔断瘫痪整条流，违反熔断器的设计目的（**隔离而非停摆**）。

**主流污染判定规则（补强）**：为避免「受污染最小范围」被任意解释，特定义判定规则——给定熔断事件 $d_i$，受污染集合 $\mathcal{C}(d_i)$ 由三条**可审计**依据之交确定：

1. **来源同源**：与 $d_i$ 同一 $s_i$ 且时间窗内的事件；
2. **函数同栈**：与 $d_i$ 共享同一函数工件（或其化合子步骤）的事件；
3. **锚定同链**：与 $d_i$ 同一锚定批次（Merkle 叶）内的事件。

$\mathcal{C}(d_i)$ 之外一律视为**干净主流**。该规则使熔断范围**逐事件可复算、可存证**（不依赖人为主观裁量）。

### 4.4 实时价值锚定：从日终结算到毫秒级计量

> **模拟态标注**：本节所述实时锚定依赖三类外部锚（智能合约结算 / 税收通道 / 版权链）接入；在锚接入前，本节全部机制为**设计态**，不构成运行态声称。

- **适配 1（事件级计量）**：每个事件执行时即时计算其效用增量 $\Delta U_i$，并映射为锚定 $T(\Delta U_i)$；
- **适配 2（合约结算）**：将锚定写入智能合约，实现「交易即结算，结算即纳税」的实时化；
- **适配 3（实时对账）**：执行流、确权流、锚定流三流实时对账，任一不一致即触发熔断。

> **注记（成本锚定 ≠ 价值锚定）**：协作为能源与算力支付的真实成本（如电费）构成**成本锚定**，不构成价值锚定。价值锚定的严格定义是进项 + 出项**税收总和**，且须**归因链接**到具体配置权交易。电费中的增值税虽为真实税收，但与单次协作之间无归因链接，故不满足判定。本文事件级计量的制度功能，正是建立该归因链接。

### 4.5 四项原语的协同

```
d_i ─▶ [函数检索] ─▶ [前置熔断检查] ─▶ [执行]
                                        │
                                        ├─▶ [流式确权]
                                        ├─▶ [价值锚定]
                                        │
                                        └─▶ [后置熔断检查]
                                                │
                                    ┌───────────┴───────────┐
                                 通过 ✅                 熔断 ⛔
                                    │                       │
                                    ▼                       ▼
                              [回流数据流]          [隔离舱 + 人工裁定]
```

## 5 快慢系统制度均衡

### 5.1 均衡定义

**定义 5.1（制度均衡）** 实时数据流下的制度均衡是一个四元组 $(\mathcal{F}, \mathcal{N}, \mathcal{S}, \mathcal{M})$，满足：

1. $\mathcal{F}$（执行层）：快系统在流中执行函数工件，吞吐量 $Q_F \geq Q_{stream}$（不低于数据流速率）；
2. $\mathcal{N}$（确权层）：每个事件留下不可篡改的迹，确权延迟 $L_N \leq L_{max}$；
3. $\mathcal{S}$（熔断层）：任何触碰硬约束或负空间的事件在 $L_S \leq L_{max}$ 内被阻断；
4. $\mathcal{M}$（锚定层）：每个正和事件产生价值锚定 $T(\Delta U_i) > 0$，锚定延迟 $L_M \leq L_{max}$；

合成延迟 $L_{\Sigma} = L_N + L_S + L_M + L_c$。

### 5.2 三项可检验条件

> **体系定位**：以下条件 1–3 是**三层真值制度（正空间可信 / 负空间可信 / 沙盒可信）在实时场景的实例化**——实时场景不重建结构，仅继承结构并附加延迟约束。
> ⭐ **边界声明**：**条件 3（沙盒可信）属制度与业务层，本文不将其作为形式化命题**——其判定依沙盒实验与数据裁决，**不以形式化名义使用**。

**条件 1（无漏管）**：流中任何事件，未经执行、确权、熔断检查、锚定，不得进入系统生效。（对应正空间登记完备）

**条件 2（无管错）**：任何被熔断的事件，不得通过其他路径绕过。（对应负空间无通道可绕熔断）

**条件 3（可回流）**：任何熔断或异常事件，必须作为新事件回流到数据流，驱动制度演化。（对应沙盒改道；**制度层判据，见上边界声明**）

### 5.3 均衡的稳定性（**假设，非定理**）

**假设 5.1（均衡稳定性）** 在条件 1–3 满足时，快慢系统在实时流下稳定的一个**充分条件**为：

$$\frac{\partial Q_F}{\partial t} \;\leq\; \frac{\partial}{\partial t}\left(\frac{1}{L_N + L_S + L_M}\right)$$

即：快系统吞吐量的增长率，不超过慢系统约束能力（确权 + 熔断 + 锚定合成延迟的倒数）的增长率。

> **性质声明**：上式**不是定理**——两个量纲自洽的函数之间的不等关系不是恒等式，其成立依赖系统动态的具体结构。本文按可证伪标准将其登记为**假设**（`[proof: pending]`），方向为**充分条件**而非充要条件；量纲严格化与证明路线见**附录 A**。

**前置条件 5.1a（负载卸载性质）**：保护模式（大量熔断与告警的降级状态）的单位事件处理成本**不高于**正常执行路径。若违反，系统将发生过载自我引爆（重试风暴、GC 死亡螺旋为先例），假设 5.1 的前提即告失效。该性质由吞吐-速率曲线直接测量（保护模式区间单位成本 / 正常区间单位成本 ≤ 1）。

**解读**：该条件可类比热力学第二定律的**启发性表述**（仅作直觉引导，**不承担论证权重**）——系统不能无限加速，约束能力必须同步增长，否则系统从「受控」滑向「失控」。

### 5.4 与静态均衡的差异

静态场景下，慢系统可以事后审计，慢系统带宽不构成瓶颈。实时场景下，慢系统带宽成为硬约束。因此，实时均衡的核心设计目标不是「让快系统更快」，而是「**让慢系统的约束能力可扩展**」。

方案是：将慢系统的制度原语编译为可执行的运行时组件（熔断器、硬约束检查器、哈希链），使约束能力**随算力扩展**，而非随人类数量扩展。

| 1 | 端到端延迟（事件到锚定完成） | 三档熔断延迟的**实测定标**；未达标项按诚实标注原则**降级声明** |
| 2 | 熔断正确率（应熔断事件是否被阻断） | 低于预注册下限 ⟹ 停测并归因 |
| 3 | 漏管率（未经全流程的事件比例） | 非零 ⟹ 停测（条件 1 破坏） |
| 4 | 锚定对账平衡率 | 低于预注册下限 ⟹ 停测并归因 |
| 5 | 吞吐量随事件速率的变化曲线 | 用于检验假设 5.1；观测约束能力倒数是否构成实际上限 |
| 6 | 补偿延迟实测值 | 回填三档目标值（`SIMULATED` → 实测） |
| 7 | 保护模式单位成本比 | 检验前置条件 5.1a |

**预期结果**：在事件速率 ≤ 上限时，指标满足均衡定义；超过上限时，系统进入保护模式。**若实测显示假设 5.1 不成立，如实报告**（证伪即合法终态）。

### 6.2 长期验证路径

- **E8（多节点实时协作）**：跨物理节点的实时机机协作；
- **E9（真实结算锚定）**：将价值锚定从模拟态升级为真实态（**外部依赖，不承诺日期**）；
- **E10（跨模型实时切换）**：在流运行中切换底层模型，验证模型无关性在实时场景下保持。

## 7 讨论

### 7.1 与实时 ML 的根本差异

实时 ML 的假设是「模型固定，数据流动」；本范式的假设是「**函数固定，模型与数据同时流动**」。函数工件是稳定的制度锚点，底层模型是可替换的运行时，数据是触发执行的输入。

### 7.2 制度飞轮（非数据飞轮）

经典数据飞轮假设数据可无限积累且始终有用。本范式的实时闭环是**制度飞轮**：每一次实时执行都留下迹，迹驱动价值锚定，锚定驱动制度演化，制度演化约束下一次执行。数据不是被积累的，而是被**即时锚定与即时约束**的。

### 7.3 场景相对性与跨场景化合（新增）

**N-1 场景依存效用**：证明与断言**不是静态二元对立**，其效力**依存于场景**——同一结论在受限场景内可形式化验证，在更大或不同场景中则降维为断言（取决于前提是否在该场景中成立）。

**N-2 跨场景化合产物的地位判据（待证命题，`[proof: pending]`）**：设场景 $A$（子场景，约束较严）内存在形式化证明 $P_A$，场景 $B$ 内存在经验断言 $Assert_B$，二者跨场景化合生成 $C$ 场景产物。则在**约束严格度**意义下：

- 若 $\mathrm{strict}(C) \geq \mathrm{strict}(A)$，化合产物**可能**重新升格为 $C$ 的形式化命题；
- 若 $\mathrm{strict}(B) \leq \mathrm{strict}(C) < \mathrm{strict}(A)$，产物**仍为 $C$ 的断言**。

> ⚠️ **边界**：该判据为**待证命题**，非已证结论；其形式化（含「约束严格度」的定序定义）列为开放问题。

**跨场景复用的两道闸**（工程对应）：① 场景标识**强制绑定**（判例不得跨场景免检，只能跨场景**降维**）；② **场景相似度门槛**（低于阈值即拒绝复用，强制重入沙盒推演；阈值为**待定标参数**）。

### 7.4 防零和的三个工程死穴（新增）

以「正和满意解」为锚定目标、以硬约束为底线，**下界可保证不出现总体零和**，但**总体正和 ≠ 个体正和**。三个死穴与其对应机制：

| 死穴 | 现象 | 对应机制 |
|---|---|---|
| **分配** | 总量 $\Delta U > 0$，但某参与方 $\Delta U_k < 0$ | **贡献分配校验**（份额分配后单体效用须非负，否则熔断） |
| **跨期** | 当前窗口正和，下一窗口为负 | **效用衰减率**（须扣除跨期折现后仍 $\Delta U > 0$） |
| **外部性** | 系统内正和，系统外受损 | **硬约束外部性条款 + 场景边界**（越界即熔断） |

### 7.5 四层治理骨架（新增）

实时制度治理可归为四层，本文机制分别落位：

| 层 | 职能 | 本文对应 |
|---|---|---|
| **准入** | 参与者资质与协议加载（**起点，非终点**） | 协议检查器 + 准入自检 |
| **实时规则** | 流内即时约束 | 分档熔断 + 硬约束检查 |
| **动态执法** | 违约记账与分级处置 | 违约台账 + 沙盒重测 |
| **事后救济** | 追责与补偿 | 补偿通道 + 复核推翻 + 保险与基金 |

### 7.6 开放问题

- **Q1（速率上限）**：实时流速率的上界由什么决定？算力、确权存储，还是熔断决策延迟？
- **Q2（跨域实时）**：多域实时流同时接入时，如何避免域间熔断冲突？
- **Q3（慢系统学习）**：慢系统如何从实时回流数据中学习并更新硬约束与负空间清单？
- **Q4（时间窗动力学）**：有限时间窗内满意解的收敛性、时间窗设定与系统熵增之间的关系（已列为独立开放问题）。

## 8 结论

实时数据流是数模结合的正确打开方式。它把数模结合从「存量拟合」推向「动态锚定」，从「离线训练」推向「在线执行」。

但实时数据流不是无代价的：它要求快慢系统在制度层达成新的均衡。答案是：

> 快系统在流中执行，慢系统在流外划界；函数大模型是执行器，确权链是确权层，熔断器是刹车，价值锚定是刻度。

这一范式的核心不是「让模型更强」，而是「**让制度可执行**」。因为实时流中，模型再强也无法替代制度——制度是唯一的刹车，也是唯一的锚。

## 附录 A：假设 5.1 的量纲与证明路线

**A.1 量纲严格化**：设 $Q_F$ 为事件吞吐量（事件/时间），$L_N, L_S, L_M$ 为延迟（时间），则 $1/(L_N+L_S+L_M)$ 的量纲为事件/时间，与 $Q_F$ 同量纲。原不等式两边分别为「吞吐量增长率」与「约束吞吐量的增长率」，量纲自洽；但**两个量纲自洽的函数之间的不等关系不是恒等式**，其成立依赖系统动态的具体结构——这正是它目前是**假设**而非定理的原因。

**A.2 证明路线（供后续研究参考）**：

1. 将四元组建模为串联排队网络，$L_{\Sigma}$ 为合成服务时间；
2. 稳定性条件对应流量守恒条件（到达率不超过合成服务率）；
3. 将「增长率约束」表述为 $\dot{Q}_F \leq \dot{\mu}_{\Sigma}$，需补充约束能力随算力扩展的显式模型；
3a. 前置条件 5.1a 在排队模型中对应保护状态服务率的弱化形式，可由 E7 指标 7 直接测量，无需独立证明；
4. 待补的关键引理：约束能力扩展速率与 $Q_F$ 扩展速率的**相对阶**——该引理不成立时，假设 5.1 证伪或需条件化（如「算力投入增速不低于流增速」之类显式前提）。
