## 摘要

制度系统若要同时具备**程序正义**与**实质正义**，必须同时容纳「普适规则」与「个案判断」。规则层可以形式化、可以机验；而个案判断往往依赖尚未编码的默会知识，无法当日完成形式化。既有制度设计在这一点上是**缺层**的：规则有、沙盒有，但**判例如何被固化、检索与推翻**，缺乏机制。

本文提出**断言锚点（Assertion Anchor）**：在实时协作场景下，当系统在有限时间窗内无法经形式化推导得到全局最优解时，允许**策略性接受**满足正和且通过硬约束检查的**满意解**；该满意解经确权存证后，成为该场景下可被后续推理检索引用的**判例**，从而终止无休止递归。

断言锚点的完整生命周期是**三态跨空间状态机**（候选 → 判例 → 被推翻）；其推翻是**状态迁移而非删除**，并配有**追溯阻断线**，使推翻的代价上限为个案级而非系统级。本文给出四项工程盲区与防守、一份记录 schema、一组可测量指标、一条**制度层**升格管道，以及跨场景化合产物地位的**待证判据**。

**关键词**：断言锚点；正和满意解；判例层机制；三态状态机；追溯阻断；混合法系

## 1 引言：从法理映射看缺失层

### 1.1 法条与案例双轨

成熟的法律体系处理纠纷依赖两条轨道：

- **法条（演绎）**：普适必然规则，从一般到个别；
- **案例（归纳）**：裁判者在具体情境中对模糊、未编码的默会知识作出判断，并沉淀为先例。

两条轨道互补：法条提供确定性，案例提供适应性。只有法条而无案例，系统在边界情形上僵化；只有案例而无法条，系统在一致性上崩塌。

### 1.2 缺失层：判例如何被固化、检索与推翻

将上述结构映射到制度化的自治协作系统，可得三重对应：

| 法理层 | 系统对应 |
|---|---|
| 法条（演绎） | 形式化证明 ＋ 硬约束族 |
| 案例（归纳） | 负空间断言 ＋ 沙盒实验 |
| **先例制度** | **？** |

系统的前两层已有雏形，第三层缺失：**判例如何被固化、检索与推翻**尚无机制。而实时数据流场景把这一缺失放大为工程灾难——缺乏判例锚点的智能体将在每一笔实时协作中重新推演形式化条件，或陷入无休止递归，或干脆放弃约束。

> **原则归属声明（非承重）**：本文不新增任何停机原则或归零纪律。断言锚点是既有原则——「协作终止条件应取正和交付的**充分解**，而非最优解」——的**机制层实现**（可执行、可存证、可检索、可推翻）。⚠️ 该既有原则的权威表述件本文**不作承重依据**，仅作方向一致性说明。

## 2 核心定义

### 2.1 断言锚点

**定义 2.1（断言锚点）** 在实时流场景下，系统在有限时间窗 $\Delta t$ 内无法通过形式化验证导出全局最优解时，允许策略性接受满足 $\Delta U > 0$（正和）且通过硬约束检查的**满意解**。该满意解经确权存证后，即成为该场景下的**断言锚点**，作为后续同场景推理的基准判例，拒绝无限递归。

核心属性：

1. **有限时间性**：拒绝无限递归，须在 $t + \Delta t$ 内收敛；
2. **满意原则**：从「全局最优」退守「帕累托改进（正和）」，承认计算资源的有限性；
3. **锚定确权**：通过存证把「解」固化为不可篡改的制度资产。

> **声明**：定义 2.1 为设计态定义，其收敛性**未证**（`[proof: pending]`，见 §6）。

### 2.2 跨空间状态机

断言锚点不是单一空间的对象，其完整生命周期是**三态跨空间状态机**：

```
[新事件无法形式化求解]
        │
        ▼
┌─────────────┐   确权（硬约束通过 ＋ ΔU>0 ＋ 锚定校验）   ┌──────────────┐
│ 候选态       │ ─────────────────────────────────────▶ │ 判例态        │
│ (proposed)  │                                         │ (active)     │
└─────────────┘ ◀─────────────────────────────────────  └──────────────┘
        ▲                                                    │ 终裁／复核
        │                                                    │ 判定为恶例
        │              ┌──────────────┐                      ▼
        └──────────────│ 被推翻态      │ ◀──────────────────────────
                       │ (overruled)  │      状态迁移留痕（见 §4.3）
                       └──────────────┘

升格出口（见 §4.5）：判例态 → [统计清白 → 候选资格] → [机验 ＋ 签批] → 硬约束族条目
```

- **候选态**：满意解已产生但尚未确权，受沙盒约束（隔离语义，同批论文 §4.3）；
- **判例态**：可被后续同场景推理检索引用，降低实时计算熵增；
- **被推翻态**：禁止检索调用，但**记录永存**（见 §4.3）。

> **空间归属注**：被推翻态锚点住在**正空间的可反驳态**（其内容曾被升格为判例），**不是负空间数据**。其价值在于为沙盒提供**边界路标**（此类候选曾失败、失败模式可查），不构成向负空间的渗漏——三空间边界不因判例演化而模糊。

### 2.3 启发式锚定声明

定义 2.1 吸收有限理性理论作为**启发式锚定**（方向性引用，合法），但断言锚点三项判据（硬约束通过 ／ 正和 ／ 锚定校验）的可信性**不抵押给任何社会科学理论**——与同批论文中「热力学类比不承担论证权重」同一纪律。

### 2.4 断言–证明双生律

**陈述**：形式化证明与断言不是静态二元对立，而是知识演化的双极：

- **收敛路径**：断言在实时协作中持续消除反例（沙盒度量、违约台账、复核推翻），经验证幸存后进入形式化候选，经机验与签批萃取为硬约束或定理；
- **降级路径**：形式化引擎在计算边界、不完备边界、时间边界上走不通时，为避免系统停机，主动降维为有限时间窗正和满意解——断言诞生。

**纪律边界（不得逾越）**：双生律是**演化机制**，不是**升格捷径**。断言与证明之间的每一次形态转换都必须通过其**目标空间**的可信性判据，不得由统计存活直接跃迁——否则即拆毁三层真值制度所维护的断言／证明边界。

> ⭐ **边界声明（与同批论文 §5.2 同口径）**：三层真值中的**沙盒可信**（无叙事不经数据升入正空间）**属制度与业务层，本文不将其作为形式化命题**——其判定依沙盒实验与数据裁决，**不以形式化名义使用**。
>
> 同理，本文的**升格管道属制度层机制**（见 §4.5），不作为形式化命题；不完备性等援引仅作启发式锚定，不承担论证重量（§2.3 同纪律）。

## 3 工程盲区与防守

### 3.1 时间窗内的短视（盲区 1）

- **风险**：时间窗过短时，智能体为达「正和满意」采取短期套利，将风险推迟到下一窗口，导致局部正和、全局负和。
- **防守**：满意解判断加入反脆弱条款——存证携带「**该解对后续时间窗的预期效用衰减率（`DecayRate`）**」。
- **冷启动规则**：新场景候选态锚点无历史数据，**禁止事前预测**，一律取保守默认 `DecayRate = 1.0`（按全衰减处理）；须在沙盒积累真实运行数据后以滚动估计更新。`DecayRate` 的定位是**刹车片而非预言机**——宁可低估效用，不可用预测冒充测量。
- ⭐ **上调触发条件（硬要求）**：默认值 `1.0` 的**上调路径必须给出可审计触发条件**——包含①**样本量下限**（累计观测窗内的有效事件数不少于给定下限）与②**收敛判据**（滚动估计序列的波动幅度落到给定区间内）；**在给定前，该默认值标 `conditional`**。触发条件的具体数值为**治理参数（`SIMULATED`，待实测定标）**。
- 衰减率超阈值时，即使当前 $\Delta U > 0$，也必须触发预警或退回候选态。

### 3.2 「满意」判定权的归属（盲区 2）

- **风险**：若由智能体自行判定「满意」，系统易将「不触发熔断的生存状态」伪装为满意状态，逃避实质正和约束。
- **防守**：严格限定满意解计算权归属**协议层效用函数**，并与价值锚定强绑定。本防守是既有**归零纪律**（锚定无归因链接则场景效用权重归零）在判例层的直接应用——**引用既有纪律，非新增条款**：若锚定无归因链接，即使系统内部判定满意，外部制度层不予承认（「无存证，不协作」）。

### 3.3 非对称时间窗与异步撕裂（盲区 3）

- **风险**：智能体处理能力与响应速度不同步（一方的 10 ms 窗与另一方的 100 ms 窗不对齐），造成「超时误杀」与状态撕裂。
- **防守（两级拆分）**：
  - **单次交易级**：发起配置权调用时须链上声明 `max_latency`；对方无法在声明延迟内返回满意解时，**强制返回 BLOCKED 而非超时挂起**（熔断终局性，确保交易终局，杜绝挂起态）；
  - **违约治理级**：强制 BLOCKED **仅针对当次交易**；对重复延迟违约方走分级处置——违约次数记入**违约台账**，达阈值者**降入沙盒重测**（重新标定其 `max_latency` 声明），而非信誉即杀。以此防止「快者通吃」的中心化压力误杀诚实但慢的智能体。

> ⭐ **能力边界声明（替代原「延迟惩罚系数」方案）**：曾有一种设计思路——令声明延迟与资源占用权重挂钩（声明越长，该笔交易的锚定系数折减越大），以使「报长受罚」与「报短受罚」构成双边惩罚，从而诱导**真实声明**。**本文不采纳该方案**，理由如下：
>
> 诱导真实声明要求「报真值」是**唯一**最优策略；其必要条件是该惩罚函数对 `max_latency` 构成**严格单射且其逆可验证**。若惩罚函数与 `max_latency` 之间存在**平坦区**（非一一对应），则「报真值」与「报邻近值」的效用**相同**，唯一性不成立——**单调递增不足**以保证唯一最优。
>
> 换言之，本节给出的是一份**能力边界声明**：本机制保证**终局性与可追责**，**不保证**声明真实性；后者是**开放问题**（见 §6）。

### 3.4 过早固化与路径依赖（盲区 4）

- **风险**：将「幸存 N 次反例」的断言过早固化为硬约束，第 N+1 次颠覆性反例到来时系统僵化（地心说教训的本质是**统计存活被误当证明**，而非形式化本身之罪）。
- **防守（两段式升格 ＋ 复评审周期）**：
  1. **升格两段式**：统计清白**只授予形式化候选资格**（`ExtractionReady = true`），机验与签批通过前**不得以硬约束身份运行**（§4.5 管道）；
  2. **复评审周期（`TTL`）**：硬约束条目带复评审时限，到期重走机验与签批（未通过即降级回断言层）。**语义精确化**：两次评审之间条目**保持硬**——`TTL` 是「活宪法」的执行机制，而非约束软化；防止对手利用「软化窗口」择机攻击；
  3. ⭐ **逾期未审处置（硬要求）**：须明示**逾期即降级（fail-closed）**或**到期锁定 ＋ 告警（fail-safe）**之一，且**不得留空**；⚠️ 逾期**不等于**未通过（两者处置不同）。具体取值与告警路径为治理参数（`SIMULATED`）。
- ⛔ **不采纳**「以证伪悬赏激励攻击硬约束」的排期安排：该机制涉及对外激励与分配口径，**不在本文范围**，须另行合规评估。

## 4 工程落地

### 4.1 记录 schema（设计态）

```go
// AssertionAnchor 断言锚点记录（设计态 schema，供施工评审）
type AssertionAnchor struct {
    Type            string  // 恒为 "AssertionAnchor"
    State           string  // proposed | active | overruled（三态，见 §2.2）
    SceneID         string  // 归属场景（场景量化单元）
    InputHash       string  // 输入哈希（论迹）
    OutputHash      string  // 满意解输出哈希（不论心）
    DeltaU          float64 // 正和效用增量
    DecayRate       float64 // 后续窗口效用衰减率；启动默认 1.0（保守），上调须满足 §3.1 触发条件
    TimeWindow      int64   // 时间窗 Δt（毫秒）
    MaxLatency      int64   // 声明延迟（毫秒，声明与当次调用同链存证）
    MOURef          string  // 价值锚定引用（模拟通道阶段可空，但须就地标注）
    OverruledBy     string  // 推翻裁决引用，仅 State = overruled 时有值
    OverruleTx      string  // 推翻交易哈希（迁移留痕，见 §4.3）
    LegacyMark      bool    // 追溯阻断线标记（索引级批量操作，见 §4.3）
    ExtractionReady bool    // 形式化候选资格：统计清白授「资格」而非「身份」，语义 = 可送检 ≠ 已通过
    ExtractedRef    string  // 升格引用：转入硬约束族的条目编号（State = extracted 时有值）
}
```

同场景后续推理优先检索 `State = active` 判例，降低实时计算熵增。

> ⚠️ **与早期版本相比的删除项**：不再包含任何「延迟惩罚系数」字段（理由见 §3.3 能力边界声明）。

### 4.2 测量指标

**断言收敛率** = 转化为判例态锚点的事件数 / 总请求事件数。

- 过低：系统过于保守（时间窗或阈值过严）；
- 过高且后续故障频发：满意解被滥用，回调硬约束校验强度或锚定绑定。

> ⭐ **阈值预注册要求**：本指标的判定阈值与失败处置**须在观测开始前注册**，⛔ **不得事后调参**（承「可验证才可审」纪律）。

### 4.3 推翻机制

**推翻 = 状态字段迁移，非删除**：哈希链记录**永不可删**；推翻操作写入新的状态迁移交易（`active → overruled`，含 `OverruledBy` ／ `OverruleTx` 字段），迁移本身留痕可审计。该设计是**三态原则「可反驳为合法终态」在判例层的实例化**——推翻不破坏不可篡改性；恰恰相反：**可推翻性依赖不可篡改性**（否则无法追溯谁依据了已被推翻的判例）。

推翻流程：终裁或复核评审判定恶例 → 写入迁移交易 → 检索层即时屏蔽被推翻判例。

**追溯阻断线**：系统级推翻**不得转化为系统级债务**——

- 阻断线以**推翻交易的链上位置为界**（哈希链天然给出精确边界）：推翻前已基于该判例的历史交易仅置 `LegacyMark = true`（**索引级批量标记，严禁重写历史记录**——否则标记操作本身成为新的雪崩源）；推翻后的新调用由检索层即时屏蔽；
- 历史被标记交易**不自动发起补偿**；仅当某笔历史交易在实际业务中引发严重纠纷时，按个案调取存证人工终裁，补偿走既有补偿通道（**不新增**）。
- 即：**推翻的代价上限是个案级的，不是系统级的**。

### 4.4 延迟契约与违约台账

- 配置权调用请求须携带 `max_latency` 声明，声明与当次调用**同链存证**；
- 违约事件（对方超时强制 BLOCKED）记入独立**违约台账**（违约方、次数、场景、时间窗分布）；
- 阈值规则：连续 $k$ 次违约（$k$ 为治理参数，初始值 `SIMULATED`，待实测定标）→ 自动降入沙盒重测，重测通过可恢复声明资格。

### 4.5 升格管道（**制度层机制**）

```
判例态 (active)
   │  条件：DecayRate 收敛 ＋ 无新增违约 ＋ 沙盒度量清白（观察窗长度 SIMULATED）
   ▼
ExtractionReady = true        ←— 统计清白仅到此为止，授「候选资格」不授「硬约束身份」
   │  触发评审
   ▼
机验（Lean 通道 ／ Go 断言通道双轨）
   │  通过
   ▼
签批 ──▶ 硬约束族新条目（带复评审 TTL）
   │  原判例 State = extracted，ExtractedRef = 条目编号
   ▼
到期复评审：重走机验＋签批；未通过 → 条目降级回断言层（原 extracted 判例不得自动复活）
```

> ⚠️ **定位声明**：本管道**属制度层机制**，⛔ **不作为形式化命题**（§2.4 边界声明）。⛔ **不采纳**「统计上不再遇到反例即可升格为硬约束」——统计性缺席**不等于**证明，该路径将拆毁断言／证明边界。

## 5 讨论

### 5.1 证明与断言的场景依存（洞见 1）

证明与断言**不是静态二元对立**，其效力**依存于场景**：同一结论在**受限场景**内可形式化验证，在更大或不同场景中则**降维为断言**（取决于前提是否在该场景中成立）。这与「沙盒可信留在制度与业务层」的分层结论**同向**：局部确定性在跨场景时降维，属结构性质，而非实现缺陷。

### 5.2 跨场景化合产物的地位判据（**待证命题**）

**判据（`[proof: pending]`）**：设场景 $A$（子场景，约束较严）内存在形式化证明 $P_A$，场景 $B$ 内存在经验断言 $Assert_B$，二者跨场景化合生成 $C$ 场景产物。则在**约束严格度**意义下：

- 若 $\mathrm{strict}(C) \geq \mathrm{strict}(A)$，产物**可能**重新升格为 $C$ 的形式化命题；
- 若 $\mathrm{strict}(B) \leq \mathrm{strict}(C) < \mathrm{strict}(A)$，产物**仍为 $C$ 的断言**。

> ⚠️ **边界**：该判据为**待证命题**，非已证结论；其形式化（含「约束严格度」的定序定义）列为开放问题（§6）。⛔ 不得作已证声称。

**跨场景复用的两道闸（工程对应）**：① 场景标识**强制绑定**（判例不得跨场景免检，只能跨场景**降维**）；② **场景相似度门槛**（低于阈值即拒绝复用，强制重入沙盒推演）。

### 5.3 场景相似度阈值（洞见 4）

跨场景复用须通过相似度门槛。⚠️ 阈值为**治理参数（`SIMULATED`，待实测定标）**；本文仅给出机制方向（复用须过闸、未过闸即重入沙盒），**不给出具体数值**。

### 5.4 防零和的三个工程死穴（洞见 3）

以「正和满意解」为锚定目标、以硬约束为底线，**可保证不出现总体零和**，但**总体正和 ≠ 个体正和**。三个死穴与对应机制：

| 死穴 | 现象 | 对应机制 |
|---|---|---|
| **分配** | 总量 $\Delta U > 0$，但某参与方 $\Delta U_k < 0$ | **贡献分配校验**（份额分配后单体效用须非负，否则熔断） |
| **跨期** | 当前窗口正和，下一窗口为负 | **效用衰减率**（须扣除跨期折现后仍 $\Delta U > 0$） |
| **外部性** | 系统内正和，系统外受损 | **硬约束外部性条款 ＋ 场景边界**（越界即熔断） |

> ⚠️ **结论强度限定**：不得表述为「至少不会出现零和」；精确口径 = 「**锚定硬下限 ＋ 三层校验（分配／跨期／外部性）**下，**总体**零和被排除；**个体**非负须由分配校验逐案保证」。

### 5.5 四层治理骨架（洞见 5）

实时制度治理可归为四层，本文机制分别落位：

| 层 | 职能 | 本文对应 |
|---|---|---|
| **准入** | 参与者资质与协议加载（**起点，非终点**） | 协议检查器 ＋ 准入自检 |
| **实时规则** | 流内即时约束 | 分档熔断 ＋ 硬约束检查 |
| **动态执法** | 违约记账与分级处置 | 违约台账 ＋ 沙盒重测 |
| **事后救济** | 追责与补偿 | 补偿通道 ＋ 复核推翻 ＋ 保险与基金 |

## 6 开放问题

1. **锚点收敛性与时间窗动力学**：如何证明「有限时间窗内的正和满意解」具有收敛性？时间窗 $\Delta t$ 的设定与系统熵增、存证成本、锚定效率之间的动力学关系是什么？是否存在最优 $\Delta t$ 使系统整体效用最大化？
   - **双向耦合**：本问题与同批论文「均衡稳定性假设」共享「时间窗动力学」内核——前者给稳定性条件，本文给锚点收敛条件，二者互为约束，宜并列推进（`[proof: pending]`）。
2. **跨场景严格度的定序定义**：§5.2 判据赖以成立的「约束严格度」如何定序、如何可比？
3. **声明真实性**：§3.3 已说明本机制不保证 `max_latency` 声明真实性；在不引入惩罚系数的前提下，是否存在其它**可验证**的声明真实性机制？
4. **衰减率的滚动估计**：`DecayRate` 上调触发条件（样本量下限 ＋ 收敛判据）的最优取值与稳健性。

## 7 结论

断言锚点机制把制度系统从「纯形式化」补齐为「**兼具程序正义（形式化证明）与实质正义（满意解断言）**的混合法系」：它承认计算理性的边界，赋予制度层回溯与翻案能力，以「判例固化—检索—推翻」闭环补齐三层真值制度的缺失层，契合「论迹不论心」的协作本质。

但同时必须如实声明边界：本文给出的是**设计态机制 ＋ 可检验路径**，其中收敛性、严格度定序与声明真实性**均未证**；`DecayRate`、违约阈值、相似度阈值等参数为**工程目标值（待实测）**。
