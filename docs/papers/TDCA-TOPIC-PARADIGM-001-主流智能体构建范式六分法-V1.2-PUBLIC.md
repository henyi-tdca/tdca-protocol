## 摘要

主流大厂的平台与方法论名目繁多，底层可归为**六种基本范式**：提示词定义、工具挂载、工作流编排、智能体循环、多智能体组织、知识记忆外挂。六范式全部运行在"调参—编排"两层，共享同一 DNA：**智能体 ＝ 模型的配置视图；创建 ＝ 前向声明；信任锚在平台；计费锚在用量**。唯一例外是谷歌——它是唯一主攻协议层（A2A／ADK／MCP）的玩家，复刻 Android 打法抢互操作层的地主位置。六分法全景图之上，TDCA 的位置不是第七种范式，而是**范式层级的上移**：大厂配置模型，TDCA 配置"配置"本身。

---

## 一、六种基本范式

### P1 提示词定义范式（人格声明）
智能体 ＝ 系统提示词 ＋ 模型。创建动作即写一段角色描述（你是谁／职责／语气）。
代表：OpenAI GPTs 与 Agents SDK 的 instructions、字节豆包智能体、百度文心智能体、腾讯元器。
特征：创建成本一段话；产物最薄——换平台提示词重写，无独立存在性。

### P2 工具挂载范式（能力接线）
智能体 ＝ 模型 ＋ 工具清单。函数调用／MCP 把搜索、代码、接口接入模型；能力边界 ＝ 工具表边界。
代表：Anthropic MCP 生态、OpenAI tools、各家全跟进。
特征：MCP 已成"工具 USB 口"事实标准；2025 年以来全行业标配。

### P3 工作流编排范式（流程画布）
智能体 ＝ 节点图。低代码画布拖节点连线：模型节点、工具节点、条件分支、循环；确定性流程 ＋ 概率节点的混合体。
代表：字节扣子（Coze）、Dify、n8n、阿里百炼、百度千帆 AppBuilder。
特征：企业市场主力——技术负责人看得懂流程图；编排收益已有实证（编排可让复杂任务完成率从约 10% 升至约 60%）。

### P4 智能体循环范式（感知-行动环）
智能体 ＝ 循环里的规划者：观察环境→规划→调工具→看结果→再规划，直至收敛。ReAct 的工业版。
代表：Claude Code、OpenAI Codex、DeepSeek Harness（nanoMuse 桌面端运行底座）。
特征：当前能力上限所在，编码智能体为先锋队；与环境耦合最紧。

### P5 多智能体组织范式（角色分队）
智能体 ＝ 一群角色的协作。监督者-执行者（Microsoft Magentic-One）、角色小队（CrewAI）、移交（OpenAI Agents SDK）、辩论与群聊（AutoGen／AG2）。
特征：2026 年各家主推卖点；学术侧失败分类学（14 种失败模式、44.2% 为系统设计问题）表明此范式工程门槛最高。

### P6 知识记忆外挂范式（检索增强 ＋ 记忆）
智能体 ＝ 模型 ＋ 向量库 ＋ 记忆槽。知识库检索增强、长期记忆、人格记忆。
特征：解决"不记得"，不解决"不可信"。

## 二、共享 DNA：四个根假设

六范式表面各异，底层共享同一世界观：

1. **智能体 ＝ 模型的配置视图。** 所有范式的原材料都是模型的既有能力：提示词是调它的方式，工具是扩它的方式，工作流是排它的方式，多智能体是分它的方式。**能力集合在模型出厂日封板，六范式只是六种摆放法，没有一种让新函数进入世界。**
2. **创建 ＝ 声明，不是求解。** P1 声明人格、P3 声明流程、P5 声明角色——全部是前向声明：写下期望，祈祷执行。无一家提供"从期望效用反解显式函数"的动作。
3. **信任锚在平台。** 运行时、记忆、工具协议皆系于平台——离开平台，"智能体"蒸发。
4. **计费锚在用量。** 按词元／席位／执行次数计费——平台有动机让用户永远编排下去，单方面规则变更权 ＝ 制度不稳定性的同义词。

## 三、厂商位置速览

| 厂商 | 主范式组合 | 特色一步 |
|---|---|---|
| OpenAI | P1＋P2＋P4＋P5 | 移交原语 |
| Anthropic | P2（MCP）＋P4＋Skills | Skills 文件夹化、可组合、可版本化——胚胎期资产思想，但无确权／定价／审计层 |
| Microsoft | P5（Magentic-One）＋Agent Framework | 监督者-执行者编排，企业 IT 友好 |
| 字节 | P3（扣子）＋P1（豆包）＋渠道发布 | 流量渠道集成最强 |
| 腾讯 | P1（元器）＋办公场景智能体（P4）＋智能体身份设施 | 率先做智能体身份设施 |
| 阿里 | P3（百炼）＋Qwen-Agent 开源 | 模型-平台一体 |
| 百度 | P3（千帆）＋搜索工具 | 工具与入口优势 |

特别记录：Anthropic Skills 把能力做成带说明文件的文件夹——已是"资产"的形体，但停在资产化门口（无出生登记、无计价、无留痕纪律）。**离"创建论"最近的一步由别人走出，但止步于确权之前。**

## 四、例外：谷歌是协议玩家，不是范式玩家

谷歌六范式全覆盖（Gems＝P1、MCP＝P2、Vertex Agent Builder＝P3、Mariner／Jules＝P4、ADK＝P4＋P5、grounding＝P6），但真正的战略主攻在范式之下的连接层：**开源 ADK、捐 A2A 入 Linux 基金会（v1.0.0，150+ 企业）、拥抱 MCP**。

战略判读：Android 打法复刻——放弃应用层房东地位，抢生态互操作层地主位置；不与其他家比"谁的智能体强"，比"谁的智能体之间必须说同一种话"。盈利面在云服务、grounding 搜索、企业分发。

其"可信"答案暴露协议思维边界：grounding（检索增强＋引用溯源）解决"说的有出处"——**引用≠判定**，仍属运行留痕层级，到不了判定留痕。

与 TDCA 的双重关系：**警惕面**——传输协议若向上扩展"任务"的权利字段，制度层的入口将被传输层封死（此为本侧内部议题所记之主要收编风险）；**合作面**——A2A＋ADK 恰是制度信封（Relay Card）最现成的宿主（信封借管道、管道借信封），格式兼容优先级应列所有传输适配第一位，抢在 A2A 自长权利字段之前。

## 五、协议层澄清：MCP ≠ A2A

| | MCP | A2A |
|---|---|---|
| 连接 | 智能体↔工具／数据 | 智能体↔智能体 |
| 机制 | 工具清单＋单次调用 | 能力名片（Agent Card）＋任务生命周期（提交→执行中→完成／取消／失败）＋异步流式 |
| 出品 | Anthropic→Linux 基金会 | Google→Linux 基金会 |
| 类比 | USB 口——插上用外设 | 电话线＋名片簿——找到对方、谈生意、跟踪订单 |
| 互补关系 | 纵向：往下够工具 | 横向：往外找伙伴 |

两者为接力非替代：智能体 A 用 MCP 发现工具不够 → 用 A2A 找到智能体 B → 派单 → B 再用 MCP 调工具执行。均属连接层：**MCP 解决"手够得着"，A2A 解决"嘴说得上"，均不解决"事凭什么可信、归谁、值多少"。**

## 六、对位表：六分法全景之上的 TDCA 位置

| 维度 | 六范式（P1–P6） | TDCA |
|---|---|---|
| 操作对象 | 模型的能力 | "配置"本身（函数／资产／配置权） |
| 创建动作 | 前向声明（写人格／拖流程／分角色） | 反函数求解（期望效用 → 显式函数语料） |
| 产物性质 | 配置视图——删平台即蒸发 | 资产——可独立存在、可确权、可验收 |
| 信任结构 | 信任锚在平台运营商 | 信任锚在可复验制度产物（判定记录／哈希审计／登记册） |
| 能力天花板 | 模型能力（技术红利，折旧） | 场景空间覆盖度（制度红利，累积） |
| 计费结构 | 用量计量（租户经济） | 资产调用税（业主经济） |

**定位一句话**：六范式铺满"调参—编排"两层地板，TDCA 站在它们共同够不到的"创建"层——不是第七种范式，是范式层级的上移。大厂配置模型，TDCA 配置配置本身。

配套判据（与创建论 §二推论一致）：**任何"创建智能体"任务，若产出物不能表述为要素齐全的显式反问题（规范＋可前向验证的预期输出），则它不是创建，只是 P1–P6 中的某一种配置。**

## 七、结论

1. 六分法是全景地图：P1–P6 覆盖当前全部主流构建方法论，四条根假设解释其共同边界；
2. 谷歌是唯一的协议层例外，其 Android 式打法使 A2A 兼容成为 TDCA 传输适配的第一优先级；
3. 全景图之上 TDCA 的位置不是参赛，而是上移——创建论（姊妹篇）在此地图上标出 L3；
4. 发布次序：本份（地图）在前，创建论（位置）在后，先让读者看见全行业，再看见空位。
