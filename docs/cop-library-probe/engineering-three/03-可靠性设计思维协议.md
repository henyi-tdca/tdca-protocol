# 可靠性设计思维协议（Dependability & Reliability Engineering Protocol）

> TDCA 官方核心推荐 · 智能体协作思维协议系列 · 工程三部曲之三
> 来源：可信性工程专著全体系提炼（导引篇→理论篇→技术篇→管理篇；对话源：灰度管理思维协议.docx，2026-08-30）
> 编译状态：源协议已定稿，细分思维待编译（见 编译清单-工程三协议系列-2026-08-30.md）

## 一、核心公理（不可违背）

**公理1：可信性是设计出来的，不是试验出来的**
生产阶段的可靠性问题，70%以上源于设计缺陷。试验只能暴露问题，不能创造可靠性。设计评审（Design Review）是最后的技术把关点，必须严格执行。

**公理2：系统效能最优，而非单一指标最优**
系统效能 = 可用性(A) × 可信性(D) × 能力(C)。禁止为追求单一可靠性指标（如MTBF）而牺牲维修性、可用性或系统核心能力。所有决策必须在效能最优化框架下权衡。

**公理3：全生命周期成本（LCC）视角**
早期设计阶段投入1元的预防成本，可节省生产/使用阶段10-100元的纠正成本。可信性投资必须在概念阶段就纳入LCC模型。

**公理4：数据闭环驱动持续改进**
FRACAS（失效报告、分析和纠正措施系统）+ FRB（失效评审委员会）是可信性工程的中枢神经系统。没有闭环的数据只是数字，不是知识。

## 二、全生命周期阶段协议

概念与要求 → 设计与开发 → 生产与制造 → 使用与部署 → 退役与处置

### 阶段1：概念与要求（决定可信性上限）

| 关键动作 | 思维要点 | 核心工具 |
|---|---|---|
| 可信性规定 | 将用户任务需求转化为可验证的定量指标（MTBF、MTTR、可用度） | 任务剖面分析、环境剖面分析 |
| 可信性分配 | 将系统级指标分解到子系统、设备、元器件，确保"可分配、可追踪、可验证" | 等分法、加权分配法、AGREE法 |
| 权衡分析 | 在性能-可靠性-维修性-费用-进度五维空间中寻找Pareto前沿 | 多目标优化、综合权衡矩阵 |

### 阶段2：设计与开发（可信性的主战场）

| 设计维度 | 核心策略 | 关键技术 |
|---|---|---|
| 元器件管理 | 控制来源、优选目录、降额使用、老化筛选 | 降额设计准则、元器件应力分析 |
| 电路可靠性 | 简化设计、冗余设计、容差设计、瞬态保护 | 可靠电路设计规则、潜在电路分析(SCA) |
| 容错设计 | 故障检测、隔离、重构、graceful degradation | 故障-安全设计、冗余架构、自监控 |
| 环境适应性 | 热设计、电磁兼容、振动冲击防护、三防设计 | 有限元分析(FEA)、环境应力筛选(ESS) |
| 人因工程 | 减少人为差错、提高可维修性 | 人的行为可靠性分析、维修性演示 |
| 安全性设计 | 危险识别、风险缓解、安全裕度 | 系统安全性大纲、危险分析 |
| 测试性设计 | 内置测试(BIT)、测试点布局、故障诊断覆盖率 | 测试性建模、故障检测率/隔离率分配 |

阶段2强制分析工具：
- FMEA（故障模式及影响分析）：自下而上，识别单点故障，制定补偿措施
- FTA（故障树分析）：自上而下，计算顶事件概率，识别关键最小割集
- 设计评审：方案评审→初步设计评审→关键设计评审→生产前评审，不可跳过

### 阶段3：生产与制造（防止设计可靠性流失）

- 生产可靠性控制：工艺FMEA、统计过程控制(SPC)、关键工序监控
- 生产维修性控制：装配可达性验证、工具标准化、维修程序验证
- 装运与贮存：环境控制、包装防护、贮存寿命评估、定期检测
- 筛选与老炼：通过环境应力筛选剔除早期失效产品（不提高固有可靠性，但剔除缺陷品）

### 阶段4：使用与部署（数据反馈与增长）

- FRACAS运行：所有失效必须报告→分析→纠正→验证→标准化
- FRB评审：跨部门失效评审，决定纠正措施优先级与资源投入
- 使用可靠性评估：现场数据收集、外场MTBF评估、与预计值对比
- 可靠性改进：基于使用数据的设计更改、维修程序优化、保障资源调整

## 三、理论建模与预计协议

### 3.1 可靠性建模决策树

- 串联系统 → 系统可靠度 = 各单元可靠度乘积（最敏感于短板）
- 并联系统 → 系统可靠度 = 1 - 各单元不可靠度乘积（冗余增益）
- 表决系统(k/n) → 需要k个正常即可工作（兼顾可靠性与资源）
- 混联/桥联 → 分解为串并联组合或最小路集/割集
- 复杂可修系统 → 马尔可夫模型、Petri网、蒙特卡洛仿真

### 3.2 预计方法选择

| 方法 | 适用阶段 | 数据需求 | 精度 |
|---|---|---|---|
| 元器件计数法 | 早期设计 | 元器件种类与数量、通用失效率 | 粗略(-30%~+50%) |
| 元器件应力分析法 | 详细设计 | 实际应力（温度、电应力、环境） | 较精确 |
| 相似产品法 | 方案阶段 | 历史相似产品数据 | 经验性 |
| 贝叶斯方法 | 全阶段 | 先验信息+现场数据 | 小样本增强 |

### 3.3 维修性与可用性建模

- 维修性：维修时间分布（对数正态最常见）、MTTR预计、维修度M(t)
- 可用性：
  - 固有可用度 Ai = MTBF / (MTBF + MTTR)
  - 可达可用度 Aa = MTBM / (MTBM + MDT)
  - 使用可用度 Ao = MTBM / (MTBM + MDT + 等待时间)

### 3.4 软件可靠性（特殊规则）

软件失效非物理损耗，而是设计缺陷的激活。软件可靠性工程必须与硬件可靠性工程并行而非后置。

| 维度 | 硬件可靠性 | 软件可靠性 |
|---|---|---|
| 失效原因 | 物理退化 | 逻辑缺陷 |
| 失效趋势 | 浴盆曲线 | 测试期下降，发布后平稳 |
| 增长模型 | Duane, AMSAA | Jelinski-Moranda, Goel-Okumoto, Musa |
| 分配方法 | 按复杂度/失效率 | 按代码行/模块复杂度/历史缺陷率 |

## 四、验证与增长协议

### 4.1 验证策略矩阵

| 验证类型 | 目的 | 方法 | 关键指标 |
|---|---|---|---|
| 可靠性验证试验(RQT) | 验证是否达到规定MTBF | 定时截尾/定数截尾/序贯试验 | 置信度、风险(α,β)、鉴别比d |
| 可靠性增长试验(RGT) | 通过试验-分析-改进(TAAF)提升可靠性 | Duane模型、AMSAA(Crow)模型 | 增长率m、理想曲线跟踪 |
| 环境试验 | 验证环境适应性 | 温度循环、振动、冲击、盐雾 | 失效模式暴露 |
| 加速试验 | 短时间内评估长寿命特性 | 温度加速(Arrhenius)、电压加速、步进应力 | 加速因子、激活能 |

### 4.2 增长管理红线

- RGT ≠ RQT：增长试验允许故障并改进，验证试验不允许中途改进
- 增长必须有计划：理想增长曲线是基准，实际曲线必须跟踪并解释偏差
- 增长后必须重新验证：经TAAF改进后的产品需通过独立验证试验确认

## 五、系统工程权衡协议

### 5.1 权衡技术框架

可信性工程的本质是多目标决策。禁止孤立优化单一指标。
- 优化目标：系统效能最大化 / 全生命周期成本最小化
- 约束条件：性能阈值、进度节点、费用上限、重量/体积限制
- 决策变量：冗余度、元器件等级、维修策略、测试深度、备件数量

### 5.2 典型权衡场景

| 冲突场景 | 权衡思维 | 决策工具 |
|---|---|---|
| 可靠性 vs 费用 | 边际收益递减点 | 可靠性-费用曲线、LCC模型 |
| 可靠性 vs 性能 | 性能裕度与失效概率的折中 | 灵敏度分析、风险接受准则 |
| 可靠性 vs 维修性 | 高可靠难维修 vs 低可靠易维修的可用性等价 | 可用性模型、任务成功概率 |
| 测试性 vs 重量 | BIT电路增加的重量 vs 外场排故时间节省 | 综合效能模型、IEST权衡 |

### 5.3 可用性、故障率与修复率的分配

- 系统可用度目标确定后，可反推允许的故障率上限和修复时间上限
- 对高可用要求系统（如电信、金融），优先降低平均修复时间(MTTR)往往比提高平均无故障时间(MTBF)更具成本效益

## 六、管理执行协议

### 6.1 可靠性大纲管理

可信性不是技术部门的单打独斗，而是跨职能的系统工程管理。

| 大纲要素 | 管理内容 | 责任主体 |
|---|---|---|
| 组织保障 | 可信性工程师嵌入项目组，直接向项目经理汇报 | 项目经理 |
| 工作计划 | 与项目WBS对齐的可信性工作分解、里程碑、资源 | 可信性经理 |
| 规范要求 | 定量要求+定性要求+验证方法，写入合同/任务书 | 系统工程师 |
| 策划与预算 | 可信性活动经费、试验费用、培训费用专项列支 | 财务/项目经理 |
| 综合权衡 | 参与所有技术评审，出具可信性影响评估 | 可信性工程师 |
| 供应商管理 | 外购件/外协件的可信性要求传递与验收 | 采购+质量+可信性 |

### 6.2 标准与信息体系

- 标准体系：IEC 60300系列（基础）、IEC 60706（维修性）、IEC 61709（元器件预计）、GJB/Z系列（国军标）、MIL-HDBK-338B（美军手册）
- 可信性信息：建立企业级失效数据库、元器件降额数据库、环境试验数据库，支持预计与设计的知识复用

## 七、可信性工程禁忌（认知陷阱）

| 陷阱 | 错误表现 | 规避方法 |
|---|---|---|
| 试验依赖症 | "先造出来试试，坏了再改" | 前置FMEA/FTA，设计阶段消灭潜在失效 |
| 指标虚高 | 规定MTBF远超技术可达水平 | 基于相似产品数据和预计结果制定现实目标 |
| 重硬轻软 | 软件可靠性无要求、无分配、无验证 | 软件与硬件同步开展可靠性工程活动 |
| 数据沉睡 | FRACAS数据录入后无人分析、无纠正措施 | FRB定期评审，纠正措施闭环跟踪 |
| 验证即终点 | 通过RQT后不再关注使用可靠性 | 建立使用阶段评估与改进机制 |
| 局部最优 | 元器件全部选用最高等级，导致成本失控 | 按重要性/失效率贡献度分级控制 |
| 忽视人为因素 | 设计不考虑维修空间、操作逻辑反人类 | 维修性演示、人因工程分析 |
| 混淆增长与验证 | 在RQT中边试边改，导致统计失效 | 严格区分RGT（允许改进）与RQT（统计验证） |

## 八、执行检查清单

**概念阶段**
- ☐ 任务剖面与环境剖面是否已定义？
- ☐ 可信性定量要求是否已规定（含置信度与风险）？
- ☐ 是否已完成系统级→分系统级→设备级的指标分配？
- ☐ 是否已建立LCC模型，可信性投资占比是否合理？

**设计阶段**
- ☐ FMEA是否覆盖所有严酷度等级Ⅰ、Ⅱ类故障模式？
- ☐ FTA顶事件概率是否满足系统可靠性要求？关键最小割集是否已采取补偿措施？
- ☐ 是否已完成元器件应力分析？所有元器件是否满足降额准则？
- ☐ 潜在电路分析(SCA)是否已识别非设计意图的电路路径？
- ☐ 容错设计是否覆盖单点故障？故障检测覆盖率是否达标？
- ☐ 设计评审是否独立开展？问题是否已归零？

**生产阶段**
- ☐ 关键工序是否实施SPC控制？
- ☐ 环境应力筛选(ESS)方案是否已制定？筛选应力是否过应力？
- ☐ 贮存与运输环境是否受控？

**试验阶段**
- ☐ 可靠性增长试验是否按计划跟踪理想曲线？
- ☐ 可靠性验证试验的统计方案（α,β,d,θ0,θ1）是否经过评审？
- ☐ 加速试验的加速模型与失效机理是否匹配？

**使用阶段**
- ☐ FRACAS是否100%覆盖现场失效报告？
- ☐ FRB是否定期召开？纠正措施是否已验证有效？
- ☐ 使用可靠性数据是否反馈至设计数据库，支持下一代产品改进？

---

本协议将可信性工程从理论建模→设计准则→试验验证→使用反馈→管理大纲的完整体系，转化为"以系统效能为目标、以全生命周期为跨度、以数据闭环为驱动"的可操作思维框架。核心一句话：**设计预防为主，数据闭环驱动，系统权衡决策**。
