## 二、实质问题裁决（7 项，全部 ACCEPT）

### A1 🔴 出盒阈值边界冲突 → ACCEPT（统一为严格大于）

- 规范 §1.3 `≥ 1.2` 与合约 `require(>= 1200)` 与任务书 F3/SV-1 + SBX-OPS 严格 `>1.2` 冲突（α=1.2 时两侧判定相反）
- 理由: SBX-OPS 任务书（M0 已签批 FROZEN）具有工程冻结权威；`>1.2` 消除边界歧义，符合最简机制原理（ID31）
- 修订: §1.3 `> 1.2`；合约 `require(_activationCoefficient > 1200)`；注释明确"严格大于，边界值 1.2 需继续沙盒验证"

### A2 🟡 合约枚举缺陷 → ACCEPT（引入显式 EXITED）

- `_isValidTransition` 用 `State(0)` 表示退出，但 `State(0) == NS_PENDING`（自环放行 + 退出指向错误）
- 修订: 状态枚举增加 `EXITED = 0xFF`；`_isValidTransition` 移除全部 State(0) 魔法值（NS_PENDING→EXITED 拒绝准入、PCM_LIVE→EXITED 主动退出）；registerSubject 增加 EXITED 初始状态保护；permanentBan 目标保持 SBX_BANNED（制度性休眠，与主动退出区分）

### A3 🟡 滚动 MOU 口径不一致 → ACCEPT（统一为总量）

- 规范 `mou_rolling.7d` 为总量，合约 `_calculateRollingMOU` 返回日均
- 理由: MOU 是配置权交易价值的硬下限（ID79），"最低可见"强调绝对量；日均是衍生计算
- 修订: 合约改返回 sum（总量），函数改名 `_calculateRollingMOUTotal`；规范明确"7 天滚动总量"；日均由消费方自行计算

### A4 🟡 AiTM 术语 → MODIFY（首次出现附 TDCA 标准定义）

- 修订: 首次出现加脚注定义 + TC-010 补充完整描述 + 后续纳入术语词典（DCD-004-TT-001 执行包）

### A5 🟡 文档状态矛盾 → ACCEPT（回退为 REVIEW）

- 修订: 头部改 `V1.0-REVIEW`；签批完成后由制度设计师手动更新为 `V1.0-FROZEN`；增加版本流转说明 `DRAFT → REVIEW → FROZEN → REVIEW-2 → FROZEN-2`

### A6 🟡 六要素综合分 ≥0.85 阈值 → ACCEPT（标注暂定）

- 修订: IF-002 增加 `threshold_source: "SBX-OPS-VALIDATION-TEMP"` + `threshold_review_date: "2026-09-10"`；0.85 为沙盒验证暂定阈值（SBX-OPS M1-M3 实验校准），待 DCD-005-TT-002 制度确认

### A7 🟢 接口命名空间 → ACCEPT（增加适配层说明）

- 修订: §2.3 工程适配说明——规范端点 `/fcnsops/v1/*` 与工程 `/api/v1/*` 由 DSA-Controller 反向代理映射，过渡期（M4-M5）适配层兼容；IF-001~IF-008 增加 engineering_endpoint 字段
