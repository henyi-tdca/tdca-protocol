## 一、项目定位与制度依据

### 1.1 定位

沙盒实验操作空间（Sandbox Operations, SBX-OPS）是 TDCA 全周期管理系统中负责创新孵化、正和博弈验证、场景化实验管理的核心子空间。它与负空间管理操作空间（NS-OPS）构成一体两翼：

- **NS-OPS**: 管理「不可做」的负空间约束（慢系统人机界面）
- **SBX-OPS**: 管理「可以做」的沙盒实验（创新孵化、正和验证、场景配置）

### 1.2 制度依据

| 原理/制度 | 来源 | 在本项目中的体现 |
|-----------|------|-----------------|
| 生态沙盒体系 | ID27 / ID39 | Meta-TDCA 多主体三层级沙盒架构 |
| 三位一体正和结构 | ID39 | 创新者/投资者/政府三方正和博弈 |
| 场景化创新便利原理 | ID39 | S-Right 场景配置权 |
| 激活系数公式 | ID39 | 激活系数 =（出盒税收+就业社保）/ 政府初始 PCR 投入 |
| 化学热力学原理簇 | CHEM-001~004 | 五阶资产化合/反应釜/催化剂/抑制剂 |
| 最小化合原则 | ENG-003 | 物理叠加优先，必要才化合 |
| 快与慢战略 | ID71 | 快系统（自动化实验）+ 慢系统（人类价值判断） |
| 负空间第二边界 | ID86 | 法律禁止领域绝对熔断 |

## 二、功能规格（F1-F8）

### F1 沙盒生命周期管理（CRUD）

| 子功能 | 说明 | 权限 |
|--------|------|------|
| 沙盒创建 | 五主体（创新者/投资者/政府/平台/服务机构）发起，六要素声明 | 多签门控 |
| 沙盒配置 | 场景配置权（S-Right）分配，PUCR 预售/质押机制 | 配置权协议 |
| 沙盒运行 | 实验执行、数据收集、正和性实时验证 | 自动化 |
| 沙盒评估 | 激活系数计算、MOU 税收锚定验证 | 混合（快计算+慢确认） |
| 沙盒出盒 | 正和交付确认、NCA 存证、资产确权 | 异构三角 ≥3 签名 |
| 沙盒关闭 | 负空间熔断、资产清算、审计归档 | 人类裁决 |

### F2 三位一体正和结构

```
        政府（制度供给方）
           /        \
          /   正和   \
         /   博弈场   \
    创新者 ←——————→ 投资者
    （技术/场景）   （资本/资源）
创新者：提交场景效用函数、知识产权质押、PUCR 预售
投资者：配置权投资、风险分担、收益分配（Shapley）
政府：PCR 初始投入、制度供给、税收锚定、激活系数验收
```

### F3 激活系数引擎（核心算法）

```python
# 激活系数计算
activation_coefficient = (exit_tax_revenue + employment_social_security) / government_initial_pcr

# 决策门
if activation_coefficient > 1.2:
    status = "财政自给性达成" → 政策可复制推广
elif activation_coefficient > 1.0:
    status = "基本盈亏平衡" → 条件续期
else:
    status = "财政不可持续" → 负空间熔断 / 资产清算
```

**硬约束**: 激活系数 > 1.2 是沙盒出盒的必要条件（非充分）。

### F4 场景化创新便利（S-Right）

| 机制 | 说明 |
|------|------|
| 微创新场景准入 | 低门槛快速入盒，最小配置单元验证 |
| 制度梯度 | L0→L1→L2→L3 渐进式制度松绑 |
| PUCR 预售 | 零数据企业通过预售配置权产生第一笔硬数据 |
| 成熟企业质押 | 既有企业质押自有资源入盒 |

### F5 五阶资产化合实验（CHEM-001~004）

| 化合类型 | 说明 | 监控指标 |
|----------|------|---------|
| 正向化合 | 五阶资产（IP/知识/交换/场景权重/认知 NCA）组合生成新效用 | 效用剩余释放、MOU 税收锚定 |
| 反向分离 | NCA 析构（高成本，需法律仲裁/治理介入） | 分离成本阈值 |
| 催化剂场 | TDCA 协议网络降低正向活化能 | 协议调用效率 |
| 抑制剂 | NSFL 负空间函数语言阻止非正和化合 | 熔断触发率 |

**ENG-003 最小化合检查器**: 每次配置权调用前自动判定——物理叠加是否足够？不可拆分性/涌现价值/非线性三条件检验。

### F6 正和博弈实时验证

- 效用精灵介入: 每次实验迭代评估正和性
- NCA 嵌套认知资产: 记录完整思维过程（结构可信+认知可信）
- 宪法十六条分布式执行: 可观测/正和/自证
- 负空间熔断: 非正和方向自动阻断（对接 NS-OPS BV-1）

### F7 沙盒-负空间联动

| 联动场景 | 机制 |
|----------|------|
| 沙盒实验触碰负空间 | NS-OPS BV-1 触发 → 自动熔断 → 人类仲裁 |
| 负空间调整影响沙盒 | NS-OPS 调整权 → SBX-OPS 沙盒参数同步 |
| 法律负空间更新 | NSFL 更新 → 沙盒准入规则自动刷新 |
| 沙盒出盒制度转化 | 沙盒成功经验 → UPDA 活宪法 OTA 升级输入 |

### F8 全操作 NCA 存证与审计

- 沙盒全生命周期 NCA 存证
- 激活系数计算过程可审计
- 五阶资产化合轨迹追溯
- 出盒资产确权与配置权登记

### 3.2 数据模型

```python
# 沙盒实例
class Sandbox:
    sandbox_id: str           # did:tdca:sandbox:{uuid}
    phase: Phase              # Phase0 / P0 / P1 / Exit / Closed
    initiator: DID            # 发起方 DID
    trinity: TrinityConfig    # 三位一体配置
    s_rights: List[SRight]    # 场景配置权分配
    pucr: PUCRConfig          # PUCR 预售/质押
    activation: ActivationLog # 激活系数历史
    nca_chain: List[NCA]      # NCA 存证链
    negative_space_refs: List[str]  # 关联负空间约束 ID

# 三位一体
class TrinityConfig:
    innovator: InnovatorProfile     # 创新者（技术/场景）
    investor: InvestorProfile       # 投资者（资本/资源）
    government: GovernmentProfile   # 政府（制度/PCR）
    shapley_weights: Dict[str, float]  # Shapley 分配权重

# 激活系数记录
class ActivationLog:
    timestamp: datetime
    pcr_input: float            # 政府初始 PCR 投入
    tax_revenue: float          # 出盒税收贡献
    employment_ss: float        # 就业社保
    coefficient: float          # 激活系数
    status: ActivationStatus    # 财政自给性判定
```

## 六、与现有系统接口

### 6.1 NS-OPS 负空间管理操作空间（已验收 M3）

```
SBX-OPS → NS-OPS
├── 沙盒创建时：查询负空间约束清单（NS-OPS F1 API）
├── 实验运行时：实时校验负空间边界（NS-OPS F3 API）
├── 触碰负空间：触发 BV-1 熔断（NS-OPS 熔断接口）
└── 出盒评估时：获取负空间合规证明（NS-OPS 审计接口）

NS-OPS → SBX-OPS
├── 负空间更新：推送沙盒准入规则刷新
└── 法律负空间变更：触发沙盒实验重新评估
```

### 6.2 FlowEngine / PhaseMachine

```
SBX-OPS → FlowEngine
├── 沙盒生命周期：Phase 0（准入）→ P0（实验）→ P1（评估）→ Exit（出盒）
├── 状态同步：沙盒状态 → FlowEngine 生命周期状态
└── 事件触发：激活系数达标 → PhaseMachine 阶段推进信号
```

### 6.3 效用精灵

```
SBX-OPS → 效用精灵
├── 每次实验迭代：提交场景效用函数 → 正和性评估
├── 五阶资产化合：提交化合方案 → 涌现价值判定
└── 出盒评估：申请正和交付确认 → 效用精灵签署
```

## 七、开发纪律与规范

继承 TDCA-FC-NS-OPS-001 会话框规范（S0/S1/S2），并增加沙盒专项规范：

- 激活系数计算不可 mock: 须对接真实税收数据或沙盒模拟税收合约
- PUCR 预售须真实硬数据: 零数据企业的第一笔数据须可验证
- 三位一体任何一方须可独立审计: 不能存在单方黑箱
- 沙盒实验与负空间约束实时联动: 延迟 < 1 秒
- 五阶资产化合须记录必要性判定: ENG-003 检查器日志存证
- 出盒评估须人类最终签名: 智能体可推荐，人类裁决
