# CKS 同步协议部署规范（M3）

> **文档编号：** CKS-001
> **Function-Call-ID：** TDCA-PHASE-E-INT-1（M3）
> **日期：** 2026-08-04
> **验收标准：** 与 TIMA VersionVector 兼容 + 冲突解决规则（宪法约束编码）
> **硬约束（HC-EINT-003）：** CKS 协议与 TIMA VersionVector 兼容；冲突解决编码宪法约束（正和博弈优先 / 人类签名权不可覆盖）

## 一、协议定位

CKS（Cross-Agent Knowledge Synchronization）在 EIOS 中作为认知层知识同步部署规范。**核心原则：不重实现 TIMA CKS**（NSFL 禁止），而是：
1. **直接复用** TIMA 已归档的 `VersionVector` / `CKSProtocol` 类（import，零修改）
2. **EIOS 层新增宪法收敛适配层**，解决 TIMA LIM-D3-001 已知限制（sync_with 冲突仅记录、未编码宪法收敛规则）

```
EIOS 认知层
  └─ CKSSyncAdapter（本规范新增：宪法收敛冲突解决）← 部署规范定义
        │  import + 复用
        ▼
  TIMA CKSProtocol / VersionVector（Phase D 已归档，禁止修改）
```

## 二、与 TIMA VersionVector 兼容性（逐项对应）

| TIMA VersionVector 接口 | EIOS 复用方式 |
|------------------------|--------------|
| `__init__(agent_id)` | 直接实例化，格式一致 |
| `increment()` | 直接调用 |
| `merge(other)` | 直接调用（max 合并策略） |
| `dominates(other)` | 用于收敛规则 3（版本支配判定） |
| `to_dict()` | 序列化存储（与 TIMA 记录格式一致） |

兼容性保障：CKS 部署不修改、不包装 VersionVector 数据结构——同步记录格式与 TIMA `_memory_store` 完全一致（`memory_id/content/version_vector/agent` 四字段）。

## 三、宪法收敛冲突解决规则（解决 LIM-D3-001）

冲突出现条件：同一 `memory_id` 在本地与远端均存在，且版本向量不互相支配（`dominates` 双向为假）。

| 规则 | 宪法约束编码 | 判定逻辑 |
|------|-------------|---------|
| R1 正和博弈优先 | 正和博弈原理 | 比较 `content.mou.total`，正和高者胜 |
| R2 人类签名权不可覆盖 | 宪法第四条（人类最终签名权） | 任一版本 `content.human_signature=true` → 该版本胜出并**锁定**（后续同步不可自动覆盖） |
| R3 版本向量支配 | CKS 版本语义 | `dominates` 成立者胜（较快/较新写入） |
| R4 平局上报慢系统 | 慢系统 | 以上规则均无法裁决 → 冲突上报人类裁决（记录 NCA） |

优先级：R2 > R1 > R3 > R4（人类签名权最高，正和次之，版本语义兜底，平局人类裁决）。

## 四、部署拓扑（对齐 TIMA DESIGN-002 Section 4）

```
┌─────────────────────────────────────────────┐
│ L0 法律记忆 / L1 所有权记忆（强一致）          │
│   RaftSubset（TIMA 复用，L0/L1 不可丢失）     │
├─────────────────────────────────────────────┤
│ L2 配置权 / L3 效用记忆（最终一致）            │
│   VersionVector（TIMA 复用）+ 宪法收敛适配层  │
└─────────────────────────────────────────────┘
EIOS 节点间同步: CKSSyncAdapter.sync_with(peer)
```

- L0/L1：`propose_institutional`（Raft 强一致，供宪法 OTA/版权确权）
- L2/L3：`update_memory` + `sync_with`（版本向量最终一致 + 宪法收敛）

## 五、同步流程时序

```
节点A.update_memory(M1) ──┐
                          ├─→ CKSSyncAdapter.sync_with(节点B)
节点B.update_memory(M1) ──┘        │
                                   ├─ merge 版本向量（TIMA VersionVector.merge）
                                   ├─ 逐 memory_id 比较
                                   │    ├─ 仅一端存在 → 直接同步
                                   │    ├─ 版本支配 → 支配者胜（R3）
                                   │    ├─ 冲突 → 宪法收敛（R2 > R1 > R3）
                                   │    └─ 平局 → 上报慢系统（R4，人类裁决）
                                   └─ 输出 resolved 列表 + 冲突上报列表
```

## 六、API 契约（EIOS 集成）

```
POST /api/v1/cks/sync           {peer_endpoint} → {merged_vector, resolved: [...], escalated: [...]}
GET  /api/v1/cks/vector/{agent} → {version_vector}
GET  /api/v1/cks/conflicts      → 待人类裁决的冲突列表（慢系统面板）
```

| 要素 | 契约 |
|------|------|
| 输入 | `{peer_endpoint}`（对端 CKS 节点地址） |
| 输出 | `{merged_vector, resolved[memory_id→winner_agent], escalated[memory_id]}` |
| 异常 | 409 平局冲突（escalated，待人类裁决） |
| 制度锚定 | 宪法第四条（人类签名权）+ 正和博弈原理 + 快慢系统 |
