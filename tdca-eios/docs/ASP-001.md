# ASP 智能体调度协议 V0.1（M2）

> **文档编号：** ASP-001
> **Function-Call-ID：** TDCA-PHASE-E-INT-1（M2）
> **日期：** 2026-08-04
> **验收标准：** 状态机定义（与 FC-012 9 Phase 同构）+ 调度 API 契约
> **硬约束：** ASP 状态机必须与 FC-012 的 9 Phase 流程一一映射（破例识别）；禁止绕过 FC-012 直接调度

## 一、协议定位

ASP（Agent Scheduling Protocol）是 EIOS 的智能体全生命周期调度协议。ASP **不是** FC-012 的替代品，而是 FC-012 TDCA-FLOW 编排引擎在 EIOS 中的**门面适配层**：ASP 状态语义（面向产品/用户）↔ FC-012 Phase（面向制度/流程）一一映射，核心迁移判定全部委托 FC-012 的 `PhaseMachine`/`FlowEngine`（封装调用，零源码修改）。

```
应用层/外部调用方
      │  ASP API（本协议）
      ▼
ASP 适配层（状态映射 + 偏离检测）     ← 本协议定义
      │  委托（translated phase + context）
      ▼
FC-012 FlowEngine（9 Phase 状态机）   ← Phase C 已归档，禁止修改
```

## 二、状态机定义（与 FC-012 同构）

### 2.1 状态集合（12 态，与 FC-012 `ALL_STATES` 一一对应）

| ASP 状态 | FC-012 状态 | 语义 | 人类介入度 |
|----------|------------|------|-----------|
| CREATED | P0 | 意图孕育（H-H，最慢） | 100% |
| PARSING | P1 | 意图编译（H-M，慢） | 80% |
| COMPILING | P2 | 协议编译（M-L，快） | 20% |
| VALIDATING | P3 | 沙盒验证（H-L，中） | 50% |
| ANCHORING | P4 | 节点锚定（L-L，最快） | 5% |
| REGISTERING | P5 | 上链确权（L-L） | 5% |
| PUBLISHING | P6 | 接口发布（L-L） | 5% |
| SOLVING | P7 | 正和求解（L-L） | 5% |
| DELIVERING | P8 | 智能合约交付（L-L） | 5% |
| COMPLETED | COMPLETED | 完成（归档+退役准备） | 0% |
| FUSED | FUSE | 熔断（Level-1/2/3） | 可变 |
| TERMINATED | TERMINATED | 强制退役（记忆清理） | 0% |

### 2.2 事件与迁移规则（继承 FC-012 PhaseMachine）

| 事件 | 触发 | 说明 |
|------|------|------|
| ADVANCE | 推进 | 条件满足则进入下一 Phase（条件定义继承 FC-012 `PhaseMachine.conditions`） |
| ROLLBACK | 回退 | 回退到指定 Phase（`phase_seq` 截断，NCA 记录 ROLLBACK） |
| FUSE | 熔断 | 触发 FUSE（NSFL Level-1/2/3，FC-012 `FuseAdapter`） |
| HUMAN_APPROVE | 人类批准 | 仅 P8→COMPLETED（MOU 闭环 + 人类最终签名，宪法第四条） |

**迁移条件表（继承 FC-012，不可在本协议重定义）**：

| 迁移 | 条件（FC-012 已定义） |
|------|----------------------|
| P0→P1 | connection_weight > 0.5 + intent_clear |
| P1→P2 | six_complete + intent_confidence ≥ 0.7 |
| P2→P3 | constraints_failed 为空 + token_status=valid |
| P3→P4 | sandbox_passed + delta_utility ≥ 0（正和验证） |
| P4→P5 | puf_bound + quad_bind（PUF 绑定 + 四元绑定） |
| P5→P6 | copyright_registered + nca_onchain |
| P6→P7 | interface_registered |
| P7→P8 | eri > cci（正和满意解存在） |
| P8→COMPLETED | mou_closed（tax_in+tax_out>0）+ human_signature |

## 三、破例识别（偏离检测）

任何以下情况自动触发破例识别（BLOCKED + 记录）：

1. ASP 状态不在 12 态映射表内 → 非法状态
2. 迁移目标与 FC-012 `ALL_STATES` 不兼容（如新增"PAUSED"态）→ 拒绝
3. 事件不合法（如 P0 直接 HUMAN_APPROVE）→ 拒绝并提示合法事件集
4. 试图绕过 FC-012 直接变更 phase → 拒绝（仅允许通过 FlowEngine 接口）

```
触发动作: [ID38-TRIGGER] reason=<偏离描述> → BLOCKED
处理: 记录 NCA + 上报慢系统（人类裁决）
```

## 四、调度 API 契约（REST，FastAPI）

### 4.1 端点定义

```
POST /api/v1/asp/agents                 创建智能体调度（→ CREATED/P0）
GET  /api/v1/asp/agents/{agent_id}      查询当前 ASP 状态 + FC-012 phase
POST /api/v1/asp/agents/{agent_id}/advance     推进（携带迁移上下文）
POST /api/v1/asp/agents/{agent_id}/rollback    回退（携带目标 ASP 状态）
POST /api/v1/asp/agents/{agent_id}/approve     人类批准（P8→COMPLETED）
GET  /api/v1/asp/agents/{agent_id}/timeline    生命周期时间线（M5 看板数据源）
```

### 4.2 请求/响应契约

```json
// POST /advance 请求
{
  "agent_id": "AGENT-001",
  "context": {
    "six_complete": true,
    "intent_confidence": 0.9
  }
}
// 响应
{
  "agent_id": "AGENT-001",
  "asp_state": "COMPILING",
  "fc_phase": "P2",
  "human_intervention": 0.2,
  "nca_ref": "NCA-P2-AGENT-001",
  "fuse": null
}
```

### 4.3 错误契约

```json
{ "error": "ID38-EXCEPTION",
  "reason": "非法状态转换: CREATED → SOLVING（跳过 9 Phase 中间态）",
  "action": "BLOCKED",
  "suggested": "合法事件: ADVANCE（→ PARSING）" }
```

## 五、与 EIOS 三层架构集成

- **认知层**：ASP 适配层位于认知层，委托 FC-012（封装）——符合 M1 架构"认知层为唯一中介"
- **基础层**：P4 ANCHORING 委托 NMDeviceDriver.register_to_l1()（M4 mock）；P2 COMPILING 委托 KG Compiler（FC-005）；P3 正和验证委托 Genie API
- **应用层**：M5 看板通过 `/api/v1/asp/agents/{id}/timeline` 获取时间线
