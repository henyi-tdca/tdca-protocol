## 陈述

**形式化证明是多智能体协作机制建设的必选项**（创始人明示，2026-09-13）。

机制建设交付时，**必须并列其证明状态**——`proved` / `refuted` / `conditional` 三态之一，
或显式的 `[proof: pending]` 标注；**未登记的声称视为无效**。

## 论证（**为何「必须」而非「可选」**）

| # | 论据 | 说明 |
|---|---|---|
| **1** | **机机协作缺人类信任兜底** | 人际协作的最终争议可由人类权威（司法 / 公信力）裁决；**机机协作**在规模与速率上无法逐笔回到人类裁决——其信任必须由**机器可验证的凭据**承担，而「可验证」的形式化形态就是**证明**（含可执行断言器作为其工程形态） |
| **2** | **制度即代码 ⟹ 代码正确性须证明** | TDCA 的制度以**可执行形式**落地（准入校验、熔断、存证链、计量）。可执行制度若**未被证明**，其失效形态正是**制度空转**（对外声称有约束、实际不生效）——证明是「制度不空转」的**形式化证据**，与 `M-6` 结构性风险的治理**同向** |
| **3** | **声称-证明一致性** | 外部核查曾指出「**声称超前于证据**」（线上仅声称、无证明文件）→ 已建 `CLAIMS-MATRIX` 逐项绑定。**必选项**是把该纪律从「对外纠偏」升级为**建设前置**：没有证明状态声明的机制**不得计为已交付** |
| **4** | **审计可控性的数学基础** | 「可审计」若只是承诺，则不可审查。公理 6 系列（反函数可计算性 / 审计还原）把审计**从承诺变为数学对象**——必要性在于：**审计权须有可被攻击者检验的边界**，而非由被审计方自我声明 |
| **5** | **规模可持续性须证明而非主张** | 「五可 ⟺ 可持续」（定理 8.8）若停留在主张，则**规模承诺不可承担**。必选项使「可持续」成为**待证命题**（P-7 / 本课题 M-3·M-4），而非叙事 |
| **6** | **对抗性环境下的门槛价值** | 证明的**机器验证门槛**可拦截「看似完美但实际有漏洞」的构造——这与「机器验证通过才消耗人工审查资源」的既有提交需知同构：门槛不是形式主义，而是**审查资源的防护** |

## 边界（**防过界，逐条强制**）

1. **证明 ≠ 绝对安全**——任何证明须附 **模型假设 + 适用范围**；**禁止**「绝对安全」表述（沿用既有纪律）；
2. **三态皆合法终态**——`proved` / `refuted` / `conditional`；**证不出不是失败**（输出精确反例或改述为 conditional 并更新范围，亦为交付）；
3. **制度层不走证明器**（`EVO-001` 范畴防线：制度层走 DCD 存证闭环，**永不走证明器**）；本件所要求的证明对象是**模型层命题与可执行机制的建模**；
4. **证明不替代制度事实**——DCD 决议、NCA 存证、争议裁决、外部接口落地**不可**由证明替代；
5. **不设全量闭环时间表**（对齐 `EVO-001`）——必选项规定**交付时必须并列证明状态**，**不**规定「何时把所有问题证完」。

## 推论：必选项的**操作定义**（落地机制四项 · **已签批生效 2026-09-13**）

| # | 机制 | 判据 |
|---|---|---|
| **R-1** | **机制交付并列证明状态** | 任何机制/制度/能力的交付件**必须**载明其相关声称的 Tier 与证明引用（或 `[proof: pending]`）；未载明 → 交付**不完整** |
| **R-2** | **新声称强制登记** | 新增公理 / 命题 / 定理声称**必须**登记 `CLAIMS-MATRIX`（Tier + 证明引用）——**未登记声称视为无效**（沿用既有纪律） |
| **R-3** | **`[proof: pending]` 不得作对外声称依据** | 对外件中出现未证明声称时，须显式标注或删除；**不得**以「必选项」为名把 pending 视为已证 |
| **R-4** | **机器验证门槛不得放宽** | 「可验证才可审」为**硬门槛**；必选项**只可加严**，不得以「内部必做」为由降低验证要求（红线 6 同款） |
