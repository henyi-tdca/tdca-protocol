## 一、问题界定（创始人指出的国标边界）

GB/Z 185.2/.3 的身份码与身份管理，隐含预设：**智能体持续存在**——OID 身份码分配、注册/账户/凭证/鉴别全生命周期、注销回收。对**日抛型智能体**（一次性/短期任务实例，用完即销毁）该机制**无法承载**：无「注册—存续—注销」周期可管理；一码一智能体在日抛场景失义；身份锁定/回收对即刻失效实例不适用。

## 二、制度结构（V1.1 核心修正：按**范围**分，不按身份轨排他分）

**关键澄清**：国标**不是** TDCA 内永久型智能体的"身份轨替代"；TDCA 范围内**一律实施 TDCA 标准**（永久型与日抛型皆然）。国标身份体系的价值在**走出 TDCA 范围**时作为**互操作链接层**。

| 范围 | 对象 | 身份机制 | 说明 |
|---|---|---|---|
| **TDCA 范围内** | 永久型 + 日抛型（全部 TDCA 内智能体） | **TDCA 标准实施**——通知机令牌 / TDID 体系（硬件根身份 + 五锚 + SM2；`call_type` 区分持久/日抛） | TDCA 内政基线：不因国标改变内部实施 |
| **走出 TDCA 范围** | **永久型**（可承载注册制者） | **国标身份链接层**——以 GB/Z 185 OID 身份码建立外部链接（TDID ↔ OID 桥接映射） | 国标是"出门的钥匙"：与外部/国家体系互操作 |
| **走出 TDCA 范围** | **日抛型** | 国标注册制**不可承载**（无持久生命周期）→ 跨域以**令牌信任/桥接机制**实现（待细化 §六） | 国标机制的边界；TDCA 解法补位 |

**一句话**：**TDCA 范围内用 TDCA 标准（内政），走出 TDCA 范围以国标身份链接（外交）；永久型可桥接，日抛型由通知机令牌承担。**

## 三、TDCA 范围内实施：通知机令牌体系（既有基座）

**令牌结构**（既有资产 `.tdca/identity.tdca.json`，非新造）：
- `tdid`：**TDID = SHA256(PUF 指纹 ‖ 宪法哈希 ‖ 批次号) 前 32 位**——硬件根身份锚定
- 五锚：address / line / hardware / cost / subject
- `sm2_pubkey` + SM2 签名（密钥材料永不落盘）
- `firmware_version` 白名单校验（越界即 SCENE-PHY-002 熔断）

**调用规则**（既有资产 `.tdca/config/call-rules.json`）：
- `call_type`：区分调用类型（**`disposable` 日抛型为既有预留**；持久型实例同走 TDCA 调用规则）
- 税率（调度税/版税档）+ MOU 锚定（模拟态，D-011）+ NSFL V0.2 + SM2 签名

**生命周期**：
```
签发令牌（TDID）→ 进入（凭令牌鉴权）→ 调用（触发 L3 计量 + 税率 + MOU 锚定）
→ 失效（日抛型任务结束即终 / 持久型按规则续存）→ 存证永续（NCA 轨迹保留，身份可回收、轨迹不消失）
```

**制度要点**：令牌即身份锚｜失效不等于无痕（NCA 永续）｜配置权边界由令牌承载瞬时切片｜**范围内不依赖国标身份库**（内政自持）。

## 四、走出范围：国标身份链接层（"也可以链接"）

1. **桥接映射**：TDID（TDCA 内身份根）↔ GB/Z 185 OID 身份码（外部身份）——映射关系本身生成 NCA 存证（链接行为可审计）
2. **链接方向**：TDCA 内智能体走出 TDCA 范围时，以国标身份码作为**外部可识别身份**（对等方/监管可见）；反之外部智能体进入 TDCA 范围时，其国标身份作为**入口凭据**之一（接入仍须过 TDCA 准入与令牌体系）
3. **不改变内部基线**：链接是接口层行为，不回写 TDCA 内部身份体系（内部仍是 TDID）
4. **界面纪律**：桥接映射不得使 TDCA 内部编号/角色名外泄（对外只呈现国标身份码与公开面信息）

## 六、待细化项（登记跟踪）

1. **跨域认可（日抛型）**：国标注册制不可承载下的跨域方案（令牌信任列表 / 桥接签名互认）
2. **桥接映射规范**：TDID ↔ OID 映射的字段级规范与失效同步（身份回收/注销时的双向通知）
3. **长期聚合**：海量日抛型实例存证按批次锚定（避免逐条膨胀）
4. **国标后续标准衔接**：若国标研制"智能体审计/交易"细分标准，本件界分与桥接设计可作接口条款**备料**（对外走裁定）
5. **继承边界**：日抛型一般无继承，特殊情形须人类裁决
