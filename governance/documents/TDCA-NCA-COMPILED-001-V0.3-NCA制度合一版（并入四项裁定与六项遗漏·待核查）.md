## 三、⭐ 统一编号与命名

| 项 | 规定 |
|---|---|
| **NCA-ID** | `NCA-<侧码>-<YYYYMMDD>-<3 位序号>`；⭐ 一律**不含动作后缀** |
| **侧码** | `TDCA-REASONIX`／`KIMI`／`WORKBUDDY` |
| **GSEQ** | `GSEQ-{NNNN}`，全局单调递增，按 `Timestamp` 升序；⭐ **只登记于索引**，⛔ 不写入文件、⛔ 不改命名 |
| **当日序号** | ⭐ **当日现有计数 +1**（计数式）；⛔ 禁止两库独立编号 |
| **缺口** | 编号即事实时间序；缺口**不可回填**；⚠️ 计数式遇历史缺口有**撞车风险 ⟹ 由校验器检出并报** |
| ⭐ **并发** | ⭐ **风险自担（明示）**：现有工件为**直接写入**（无原子预约）；⭐ **并发场景之撞车风险由使用侧自行规避并自担**（裁定 R-3）；⚠️ 不使用侧为风险背书 |
| **生成方式** | ⭐ 统一由生成器产出；⛔ 人工禁止手动预分配 —— 判据＝「**件内 `nca_id` 与文件名一致 ＋ 索引有登记**」（⛔ 不以生成标记判） |
| **件名与落位** | `NCA-<侧码>-<YYYYMMDD>-<NNN>[-动作后缀].yaml`；落位 `<侧根>/.tdca-nca/<YYYY-MM>/` |
| **编码** | **UTF-8（无 BOM）**；换行 **LF** |
| **撞车** | 跨库同名 `nca_id` 内容不同 ⟹ 双版本以 `-D`／`-W` 后缀区分；⚠️ **文件内 `nca_id` 不变**（校验比对时**去后缀**） |
| **特殊存证** | 跨项目专属 ID 可保留，但**必须在索引登记 GSEQ** 并标 `legacy` |

## 四、⭐ 统一字段（**十三项核心 ＋ 义务块六项**）

### 4.1 ⭐ 核心字段（十三项）

| # | 字段 | 规定 |
|---|---|---|
| 1 | `nca_id` | 见 §三 |
| 2 | `side` | `reasonix`／`kimi`／`workbuddy` |
| 3 | `timestamp` | `YYYY-MM-DDTHH:MM:SS+08:00`（⛔ 无时区即不合规） |
| 4 | `chain_space` | `RX`＝`gseq`／`KW`＝`kimi`／`WB`＝`ref-gseq` |
| 5 | `chain_id` | 本侧自链编号（`RX`：`GSEQ-nnnn`／`KW`：`KWS-nnnn`／`WB`：无） |
| 6 | `chain_ref` | ⛔ 仅跨侧引用；⛔ 不放自链号 |
| 7 | `prev_nca` | 本链内前一件 `nca_id`；链首写 `GENESIS` |
| 8 | `operation_type` | 见 §五 |
| 9 | `actor` | 工具／会话标识（⛔ 零角色名、⛔ 零真名） |
| 10 | `artifacts` | `[{path, sha256_16}]`（16 位短哈希） |
| 11 | `data_provenance` | `real`／`simulated`（模拟态显式标注，`ID92` 保留） |
| 12 | `profit_sharing` | 涉费时 `模拟态 15% 记账（ID92）`；⛔ 无现金流、⛔ 不承诺打款 |
| 13 | `compliance` | 挂载六条（只赋能不改码／不复制上游代码／算力零提及／不声称上游背书／无存证不执行／分润模拟态） |

⭐ **变更**：⛔ 不再要求 `Generated-By` 生成标记（现有生成器不写、在册覆盖 0）。

### 4.2 ⭐ **义务块**（`obligations:` · 六项 · 必备 · 纳入机器校验 · 裁定 R-2）

⭐ 定位：**核心十三项**之外，**「义务块」为必备扩展** —— 承原 11 字段体系之六项义务，⛔ **不得因统一而丢失**。

| # | 字段 | 规格 | 机验要求 |
|---|---|---|---|
| **O-1** | `function_call_id` | 本件所属调用／任务标识 | ⭐ 非空；⭐ 与索引 `fc_id` 一致 |
| **O-2** | `state_hashes` | `{pre, post}` 前后状态 SHA-256 | ⭐ 两者非空且为 64 位十六进制 |
| **O-3** | `config_right` | `{scope, rollback, audit_trail_ref, human_signature_required, max_retry, granted_by, expires}` | ⭐ 键齐；`human_signature_required` 为布尔 |
| **O-4** | `audit_trail` | 步／时间／证据 之列表（≥1 条） | ⭐ 非空；每项含步名与时间 |
| **O-5** | `human_signature` | `{status, signed_by, signed_at}` | ⭐ **决策点件（立项／交付冻结／审查／签批）不得为 `Pending`**；其余允许 |
| **O-6** | `negative_space_check` | `{nsfl_version, triggered, trigger_reason}` | ⭐ `triggered` 为布尔且**显式**；为 `true` 时 `trigger_reason` 非空 |

⭐ **写法**：顶层 `obligations:` 承载，六键齐备。
⚠️ **存量**：⛔ **不迁移、不回改**（读取层兼容）。
⭐ **自检（承 T-2）**：登记前须过「**十三项齐备 ＋ 义务块六键齐备 ＋ YAML 可解析**」，⛔ 未过者不得写入台账。

## 七、⭐ 生命周期五环节

```
登记 Registration → 存证 Evidence → 归档 Archival → 检索 Retrieval → 审查 Review
```

| 环节 | 核心动作 | 载体 | 纪律 |
|---|---|---|---|
| **登记** | 分配 `nca_id` ＋ GSEQ，写入索引 | `NCA-REGISTRY.yaml` | 每生成一个**立即登记** |
| **存证** | 十三项 ＋ **义务块** ＋ 前后哈希 ＋ 人类签批 | NCA 文件本体 | 内容完整、哈希可验 |
| **归档** | 写**域内权威库** → 镜像 → 会话结束前归并 | 各库 `.tdca-nca/` | ⛔ 禁止单库长期滞留 |
| **检索** | 单一项目走项目目录／全局走索引；⭐ **时间窗切片**（GSEQ 单调递增，可按时间窗快速切片；撞车同名以 GSEQ 区分） | 项目目录 ＋ 索引 | ⭐ **双键**（GSEQ ＋ NCA-ID）定位 |
| **审查** | 哈希基线核对 ＋ GSEQ 连续性 ＋ 签批完整性 ＋ ⭐ **撞车／镜像核查**（核 `status` 标注与物理文件一致：`collision` 双版本、`mirror` 双副本） | `dir_checksum` ＋ 索引比对 | ⛔ **不可删改**（最高等级违规） |

⭐ **归档纪律**：①生成 → 写域内权威库 → 镜像 ②会话结束前归并 ＋ 更新索引 ③⛔ 禁止单库长期不归并 ④⛔ 禁止手工改名破坏引用链。
⚠️ **异常处置**：撞车＝双版本（`-D`／`-W`）；镜像＝跨库同 MD5（各留副本、索引标 `mirror`、不重复计数）；非标准格式／草稿＝`legacy`／`draft`。
⭐ **项目内 NCA**：原地保留；按分组登 `project_sections`（含 `dir_checksum` 基线）。

## 十、⭐ 对外动作存证 与 准入

**对外动作存证（七字段 · 强制 fail-closed）**：对外动作（邀请／挂载／化合／治理协作）**先存证后动作，无存证不动作**：
`repo_full`／`mode`／`license_spdx`／`invite_nca_ref`／`response_status`／`profit_sharing`／`compliance`

**准入 NCA（缔约者）**：`TDCA-ADMIT-{YYYYMMDD}-{SEQ}`，`Operation-Type = AdmissionNCA`；⭐ 缔约者**自签署**；接受基协议 4 项（CONST／NSFL／WORKING-SPEC／OPC）＋红线 ＋ `ID92` 模拟态。

⭐ **生态准入（运行态）**：**零权利态 → 机读证据 → 准入存证** —— 缔约者／生态对象初始处 **`PENDING_LOAD` 零权利态**；经**机读证据核验**通过后方可置 `EcosystemAdmit`；⛔ **无准入存证即不得赋予任何权利**（fail-closed）。

## 十三、⭐ 跨侧纪律 ＋ 索引字段
