## 二、规范化序列化规则（复算的唯一依据）

> ⭐ 本节即四问 `4` 之第 ③ 件。外部拿到锚值后，**只按本节**即可逐字节复现，⛔ 不需内部数据、⛔ 不需密钥。

### 2.1 参与入账的字段（固定五项，缺者按空串）

`event_id`｜`type`｜`ts`｜`amount`｜`currency`

### 2.2 取值规范化

1. `ts` 一律转 `UTC`，格式 `YYYY-MM-DDTHH:MM:SS.ffffffZ`（`6` 位小数，不足补零）。
2. `amount` 一律**十进制字符串**（⛔ 浮点），保留 `2` 位小数，不足补零，⛔ 千分位、⛔ 科学计数法。
3. `currency` 大写三字母；缺省为空串 `""`。
4. `event_id`／`type` 原样（`UTF-8`，不做大小写折叠、不做去空白）。

### 2.3 序列化（规范化字节串）

- 形如 JSON 对象，**键按 `UTF-8` 字节序升序**，分隔符为 `,` 与 `:`，⛔ 空格、⛔ 换行。
- 字符串转义按 `RFC 8785`（`JCS`）；布尔与 `null` 用小写字面量。
- 例（示意，非真实数据）：
  `{"amount":"15.00","currency":"CNY","event_id":"EVT-...","ts":"2026-08-20T15:50:20.486926Z","type":"transaction_fee"}`

### 2.4 哈希与前缀区分

| 层 | 公式 |
|---|---|
| 叶子 | `leaf = SHA-256( 0x00 ‖ canonical_event_bytes )` |
| 内部节点 | `node = SHA-256( 0x01 ‖ left ‖ right )` |
| 批锚 | `batch_root = Merkle根`（叶子按 `event_id` 的 `UTF-8` 字节序升序排列；奇数节点末位复制自身） |
| 日锚 | `day_anchor = SHA-256( 0x02 ‖ canonical_day_header_bytes )` |

- `canonical_day_header_bytes` 之字段固定五项：`date`（`YYYY-MM-DD`，`+08` 日界）、`prev_day_anchor`（首日为空串 `""`）、`batch_count`、`event_count`、`batch_roots`（按 `batch_id` 升序的哈希数组）。序列化守则同 §2.3。
- **输出形式**：一律 `sha256:` ＋ `64` 位小写十六进制。
- ⭐ 前缀 `0x00`／`0x01`／`0x02` 为**防二次原像**所必需，⛔ 省略；省略即视为不合规实现。

### 2.5 排除项（⛔ 永不入规范化）

内部编号（`GSEQ`／`NCA`／`T-` 号等）｜现行水位字段 `nca_watermark`｜`data_nature`｜`note`｜库内自增 `id`｜任何密钥、口令、令牌、内网路径、主机名。

## 三、三条接口（只读、匿名、零凭据）

| # | 路径 | 返回字段 |
|---|---|---|
| `1` | `GET /api/v1/audit/ledger-public?since=&until=&cursor=` | `ts`｜`data_nature`｜`events[]`（五项＋原判字段）｜`total`｜`next_cursor`（**不透明串**，⛔ 暴露内部序号；`limit` 须**真生效**，⛔ 静默忽略） |
| `2` | `GET /api/v1/audit/anchors` | `days[]`，每项：`date`｜`day_anchor`｜`prev_day_anchor`｜`batch_count`｜`event_count`｜`status`（`anchored`／`none`） |
| `3` | `GET /api/v1/audit/anchors/{date}` | `date`｜`day_anchor`｜`prev_day_anchor`｜`status`｜`batches[]`：`batch_id`｜`batch_root`｜`event_count`｜`first_event_id`｜`last_event_id` |

- ⛔ 返回内部编号、⛔ 返回未公开字段、⛔ 返回库结构。
- `status = none` 之日：`day_anchor` 与 `prev_day_anchor` 均返回 `null`，⛔ 返回占位哈希。

## 四、缺日与更正程序

1. **缺日**：当日无批 ⟹ `status: none`，`day_anchor: null`；日列表**仍出一行**，⛔ 缺行、⛔ 静默。
2. **断链判定**：`prev_day_anchor` 必须等于**上一个 `status=anchored` 日**之日锚；`none` 日不参与串联，⛔ 计入链。
3. **更正**：一经发布不得撤、不得重排；如需更正 ⟹ **新锚（新版本日锚）＋明示更正件**，旧锚与旧件**原样保留**。
4. **停机与恢复**：恢复后当日若已过发布时点 ⟹ 仍按当日发布，并在件内注明恢复时点；⛔ 倒填前一日。

## 五、可证与不可证（表述基准，⛔ 简化）

- ⭐ **可证**：各日台账形态与公开锚一致；各日之间未被重排；单条事件是否入账可按批锚对数级证明。
- ⭐ **不可证**：账内事件内容的真实性；入账之前的处理是否正确；本规格之外的口头承诺。
- ⛔ 对外一律⛔ 简写为「不可篡改」而不附条件。
