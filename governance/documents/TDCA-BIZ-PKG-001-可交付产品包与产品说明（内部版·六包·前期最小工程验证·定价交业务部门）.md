## 二、⭐ 各包详述（**包内组成 ／ 交付形态 ／ 客户前提 ／ 最小验证 ／ 已知边界**）

### ⭐ P-01 · 智能体认知评测与资产价值评估包

| ⭐ 项 | ⭐ 内容 |
|---|---|
| **包内组成** | ① 基座三模块（认知距离／认知状态向量／模糊数学层）；② `cog_align`（对齐评测：引擎＋报告＋存证＋API＋CLI＋场景包）；③ `util_value`（效用价值评估：引擎＋报告＋存证＋API＋CLI＋入表模块）；④ `value_services` 统一入口；⑤ 用例集 |
| **交付形态** | ⭐ **Python ≥ 3.12，仅标准库（零第三方依赖）**；API 服务默认端口 `8123`／`8124`；报告与存证落地；⭐ 随工具发布包同构（在册版本 **V2.2 全量 8 包**） |
| **客户前提** | 提供待评测主体状态向量（或样例数据）；资产入表需客户提供销项／进项交易数据；⚠️ 数据性质须标注（真实／合成） |
| **最小验证（MVE-1）** | ⭐ 跑一条评测（两主体）＋ 一条资产入表（单资产单期）→ 出报告 ＋ 存证落链 ＋ 链校验通过；⭐ 证据＝报告文件 ＋ 存证件 ＋ 校验输出 |
| **已知边界** | ⛔ 上链为模拟通道（真实上链待接入）；⛔ 不出会计鉴证意见；⚠️ 本包**不绑定**任何客户系统接口（数据靠导入） |
| **在册验收证据** | 发布结构回归**全绿**（增值服务 94 用例）；工具链全套回归在册；交付件 M1／M2 **已冻结**（签批在册） |

## 三、⭐ 前期最小工程验证（**MVE 总方案**）

| ⭐ 项 | ⭐ 口径 |
|---|---|
| **目的** | 用最小代价证明「**产品包真的能交付**」（而非只证明"代码能跑"） |
| **范围** | ⭐ 六包各一条最小路径（MVE-1~MVE-6，见 §二），⛔ 不含定制、⛔ 不含客户系统对接 |
| **通过判据** | ① 每包按其 MVE 产出**可留存的证据**（报告／存证件／校验输出／对照件）；② ⭐ **含负控**（P-04、P-06 必做"改一件必报错"）；③ 全程无我方在线依赖（P-04／P-06 客户本地可复算） |
| **证据留存** | ⭐ 每包一份验证记录（路径＋时间＋结果）＋ 存证件；⚠️ 数据性质按在册纪律**就地标注**（真实／合成） |
| **不做** | ⛔ 不做性能压测（另项）；⛔ 不做客户现场部署（属交付实施）；⛔ 不出具任何"已认证／已合规／已上链"表述 |
| **交付给谁** | ⭐ 创始人验收 → 业务部门据以定价 → 对外承接 |
