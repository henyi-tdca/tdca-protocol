## 一、目的与范围

**目的**：明确 TDCA 与各**连接协议**（MCP / A2A / GB/Z 185 / ATH 等）的层间定位与接口约定，固化「连接层（他者）+ 价值责任层（TDCA）」口径，防止层间混淆与重复建设。

**范围**：定位模型 + 逐协议关系表 + 对接接口约定 + 边界纪律 + 维护机制。不含法律层（L0）内容——L0 归立法，TDCA 不越级（既有口径）。

## 二、层间定位模型

```
[连接层]  能不能连、怎么连 —— MCP / A2A / GB-Z 185 / ATH / AGENTS.md（他者）
   ↓ 握手/发现/交互/工具调用（技术语法）
[价值责任层]  该不该连、怎么配、怎么分、效用如何验证、责任如何归属 —— TDCA（L2 配置权市场 + L3 效用计量）
   ↓ 配置权边界/效用锚定/税收锚定/NCA 存证（经济语法）
```

**定位原则**：
1. **不替代**：TDCA 不与任何连接协议竞争连接层职责
2. **不越级**：TDCA 不进入 L0 法律层（不替代立法）
3. **可叠加**：价值责任层运行于任一连接协议之上（协议无关性）
4. **制度优先**：负空间问题不在连接层就地解决（连接层的"扩展点"不承载负空间语义）

## 四、对接接口约定（TDCA 组件映射）

| 连接层入口 | TDCA 组件 | 接口语义 |
|---|---|---|
| MCP 工具调用 | TDCA MCP server（enforce/nca/nsfl 四工具） | 调用前准入检查（enforce_check）→ 调用即存证（nca_append）→ 负空间评估（nsfl_eval）；**已实证**（DSH/Codex 挂载 EXECUTED） |
| A2A Agent Card | 配置权发现（CDP）主体描述 | Card 字段 → 能力画像 + 配置权边界声明（新增字段以扩展点隔离）——**✅ 已实现**：`layer_interop/a2a_cdp.py`（GSEQ-1198；来源可信与正和可信分离） |
| GB/Z 185.2 身份码 | 配置权身份根（P-Right 载体） | 身份码 = 权利容器的国家标准形态（内化白皮书 §2.1） |
| GB/Z 185.4/185.7 | 函数语料六要素 / S-Right 执行接口 | 描述（对内能力）与工具调用（对外可调用）统一为函数语料；每次调用 → 配置权交易 + 效用计量 + 税收锚定 |
| ATH 握手/令牌 | 配置权鉴别与边界切片 | 握手成功 → 配置权会话初始化；令牌 = 边界瞬时切片（非等价物）——**✅ 已实现**：`layer_interop/ath_token.py`（GSEQ-1198；切片经 CCV 五层方可转调用权） |
| 任一连接层的调用事件 | MOU 税收锚定触发点 | 调用事件 → 进项/出项 + MOU 硬验证（fail-closed） |
| **日抛型/永久型身份界分** | **通知机令牌（TDID）为核心** | **TDCA 范围内一律实施 TDCA 标准（通知机令牌/TDID，永久型与日抛型同用）；走出 TDCA 范围以国标 OID 身份码建立外部链接（永久型可桥接；日抛型国标注册制不可承载，跨域待细化）——详见 TDCA-STD-AGENT-ID-001 V1.1（GSEQ-1185）** |

## 五、边界纪律（强制）

1. **对外件纪律**：本规范对外引用时零内部编号（GSEQ/NCA/DCD 等）、零内部角色名、算力零提及、宁缺毋假
2. **不承诺兼容性**：对外不对任何连接协议作背书/互认声称（各自条款自持）
3. **实证为准**：接口状态以库内实证（Witness 过的实证件）为准，不引用未实证能力
4. **不自行对外接触**：与协议方/标准组织的接触一律经创始人（ID71）+ 披露口径
