## 二、A 块 · 审批后端（两个端点）

### A-1 `GET /api/site/join/list`（评审只读队列）

| 项 | 要求 |
|---|---|
| 鉴权 | 须登录会话或令牌；且**须审核身份**（reviewer） |
| 返回 | `{"items":[{ "id", "display_name", "applicant_kind", "channel", "created_at", "status", "nsfl_result", "reviewer_note" }]}` |
| status 枚举 | `pending`／`sandbox`／`active`／`rejected`／`nsfl_rejected`（前端已按此五态渲染，**不得改名**） |
| 判据 | 未登录 → **401**；非审核身份 → **403**；空队列 → **200 且 `items: []`**；正常 → 200 数组 |
| 安全 | ⛔ 不得返回凭据值、⛔ 不得返回自然人敏感信息（展示名可脱敏） |

### A-2 `POST /api/site/join/review`（审核写）

| 项 | 要求 |
|---|---|
| 头 | `x-tdca-reviewer`（审核人标识）＋ 写令牌（前端以 `Authorization: TDCA-CRT-<token>`、`X-TDCA-Token-Type: execution` 发送） |
| 体 | `{"join_request_id", "action": "approve"｜"reject", "note"}` |
| 业务规则 | ① 放行两段：`pending → sandbox`、`sandbox → active`；谢绝：`→ rejected` ② **每次放行须复核敏感词清单，触负即 409 拦截并留痕** ③ 每次操作**落 NCA 存证**（含审核人标识、动作、备注） |
| 判据 | 缺令牌 → **401/403**；触负 → **409** 且状态不变、留痕；重复审核同一单 → 幂等或 409（二者择一，回报说明取哪一） |
| 安全 | ⛔ 令牌值不得落库明文、⛔ 不得回显；⛔ 智能体不得代签（审核人须为人类主体） |

> **前端契约冻结**：字段名、枚举值、路径、请求体结构**一律照前端现状**，⛔ 不得为方便后端而改前端契约。若确需改，须先停下来报，另批处理。

## 三、B 块 · 机器可读通道七项对齐（对外面，最先做）

首页现公开陈列 7 个端点，实测在线仅 `GET /api/site/docs/{family}` 一项。要求：

| 项 | 要求 |
|---|---|
| 做法 | 在该表**逐项增一列"状态"**：`在线`／`在建`；在建项⛔ 不得再以"可用"面目陈列 |
| 范围 | **只加一列状态，不改其余文案、不改版式、不改其他区块** |
| 判据 | 七项各有状态；**页面不存在"声明可用但点不通"之项**；`docs/{family}` 标"在线"（其 help 族未入站属族级，可另注） |
| ⛔ 禁止 | ⛔ 为凑"在线"而先上线空壳端点；⛔ 删除整张表；⛔ 把未上线项悄悄从表中删去而不留痕 |

> **理由一句**：对外说了做不到，比没做更伤人。**先诚实标状态，再按批补齐。**

## 四、C 块 · 私域入口显性化

| 项 | 要求 |
|---|---|
| 目标 | 私域入口**导航可见**、**门内可达**、**权限分明**（现况：闸在工作——相关端点返 401；但导航上找不到门） |
| 做法 | ① 导航露出私域入口（运维独立入口与「我的」内私域面）② 门内六栏（站务／服务／治理操作／审计与留痕／应急／账户）照现状呈现 ③ 未实现处一律标"建设中"＋"预计批次" |
| 判据 | 未登录点入口 → 明确引导登录（⛔ 空白页 ／ ⛔ 报错页）；非 operator 登录 → 明确无权限提示（⛔ 露出内容）；operator → 可达且六栏齐 |
| ⛔ 禁止 | ⛔ 以隐藏入口当权限控制（安全靠鉴权，不靠藏）；⛔ 私域内容出现在公域任何公开面 |
