# 存证（`NCA`）制度 · 对外节选版 `V1.1`

**版本** `V1.1`（与内部现行版**同版**） ｜ **状态** ⭐ **已生效（内部执行）** ｜ **本件为对外节选，非全文**（差异清单见附录 A）

> ⭐ 本件用于对外说明「这条制度是什么」。它是**制度的对外呈现**，不是另一套制度；⭐ **与内部现行版同版本、同口径、同判据**。
> ⭐ 本件非司法裁决、非对外法律文件；效力范围以本组织内部执行为限。

---

## 一、一句话

系统里**每一次有制度意义的动作，都留一条可验的存证**——带编号、带前后哈希、带签批、带负空间检查结论，按链串起来，事后**可追溯、可归因、不可删改**。

*这一节防的是：事情做完了，却说不清是谁在什么时候做的是什么。*

---

## 二、存证的十三项字段

| # | 字段 | 规定 |
|---|---|---|
| `1` | **存证编号** | 唯一编号，按统一命名规则（本组织内唯一） |
| `2` | **出具方** | 出具方标识（⭐ **不写人名、不写角色名**） |
| `3` | **时间戳** | ⭐ **必须带时区**——无时区即不合规 |
| `4` | **链空间** | 该条属于哪条链 |
| `5` | **链内编号** | 本链自编号 |
| `6` | **跨链引用** | ⭐ **仅用于跨侧引用**；⛔ 不得填入本链编号 |
| `7` | **前一件** | 本链内前一条的编号；⭐ **链首写 `GENESIS`** |
| `8` | **动作类型** | 见第三节枚举；⛔ 不得留空或以「不适用」充数 |
| `9` | **行为者** | 工具或会话标识（⭐ **零真名**） |
| `10` | **产出物件** | 路径 ＋ ⭐ **十六位短哈希** |
| `11` | **数据性质** | `real`（真实）或 `simulated`（模拟）——⭐ **模拟态须显式标注** |
| `12` | **分润** | 涉费时标模拟态；⭐ **无现金流、不承诺打款** |
| `13` | **合规挂载** | 六条：只赋能不改码 ／ 不复制上游代码 ／ 算力零提及 ／ 不声称上游背书 ／ 无存证不执行 ／ 分润模拟态 |

---

## 三、动作类型（十五类 · 中英对照）

任务立项（`TaskLodge`）／ 交付（`Delivery`）／ 移交物件（`HandoffDeliverable`）／ 观察（`Observation`）／ 核证（`Witness`）／ 裁定（`Ruling`）／ 签批（`SignOff`）／ 追加更正（`Amendment`）／ 通知（`Notice`）／ 交接（`Handoff`）／ 开框（`ProtocolInit`）／ 收官（`SessionClose`）／ 分析（`Analysis`）／ 评估（`Review`）／ 文档（`Document`）。

⭐ 「不适用」**不得**作为新件类型；缺类型即不合规，须先补判再登记。

---

## 四、四项必登时点

| # | 时点 | 对应类型 |
|---|---|---|
| `1` | 开工或受理 | `TaskLodge` |
| `2` | 交付或回报 | `Delivery` ／ `HandoffDeliverable` |
| `3` | 核证或签批 | `Witness` ／ `SignOff` |
| `4` | 收官或裁定 | `SessionClose` ／ `Ruling` |

⭐ **一次动作一次登记**；⛔ **一事多记，⛔ 漏记**。

---

## 五、三项存证要件（缺一即完整性违规）

1. ⭐ **前后状态哈希可验**；
2. ⭐ **人类签批**——决策点缺失即违规；
3. ⭐ **负空间检查结论显式标注**（触发与否**都要写**）。

*这一节防的是：只写「做完了」，不写「依据什么、谁批的」。*

---

## 六、自动化记录之豁免（⭐ 重要 · 常被误读）

- ⭐ 系统自动化、机械类记录**在册明文豁免**，⛔ **不需、也⛔ 不应**逐条登成存证；
- ⭐ 豁免不是遗漏，而是**有意设计**：它们留在**运行日志**层即合规；
- ⛔ **不得为「凑覆盖数量」把自动化事件灌进存证库**——那会把资产稀释成流水，反而摧毁其可信性。

---

## 七、红线与纪律

| # | 纪律 |
|---|---|
| `1` | ⭐ **追加制**：⛔ 改历史行、⛔ 改既有件字段值；有错另出更正件 |
| `2` | ⭐ **凭据零落盘**：任何口令／密钥／令牌**不入件** |
| `3` | ⭐ **算力零提及、零角色名、零真名** |
| `4` | ⭐ **内外一致**：对外呈现与本组织内部执行**同版本、同口径、同判据**；⛔ 粉饰 |
| `5` | ⭐ **不得为过闸放宽门禁**（只可加严） |
| `6` | ⭐ **无存证不执行**：缺存证即不得视为已办 |

---

## 八、存证与「运行日志」的分界（⭐ 七条 · 通俗版）

| # | 存证 | 运行日志 |
|---|---|---|
| `1` | 只在**有制度意义的时点**生成，一次动作一件 | 系统自动批量产生，同一秒可上千条 |
| `2` | ⭐ **执行凭据**（无它即不算办成） | 运行证据（有日志 ≠ 事已办成） |
| `3` | 有主体、有哈希、有**判断依据**、有签批位、有链 | 只有时间／类型／级别／对象／耗量 |
| `4` | 记**语义与判断**（为什么这样定、依据哪条、谁批的） | 记**事实与状态**（何时发生了什么、耗时多少） |
| `5` | 自动化类**明文豁免**，不进存证库 | 豁免清单即其**归属地** |
| `6` | ⭐ **不可重建**：缺一件即判断链永久断点 | 可重放／重采集，可定期轮转 |
| `7` | ⭐ **资产**（可评估、可继承、可对外证明） | **成本项**（运维开销） |

⭐ **一句话**：**日志记「机器干了什么」，存证记「谁、凭什么、做了判断」**——日志可以重放，存证断了就断根。

⭐ 由此两条禁令：⛔ **不得用日志口径（调用数／请求数）统计存证规模**；⛔ **不得为扩充数量而灌自动化事件**。
