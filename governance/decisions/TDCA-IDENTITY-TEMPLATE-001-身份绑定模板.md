## 〇、定位

**IDENTITY.md = 轻量身份绑定**（冷启动期弱身份可接受：首批用户=自己+定向朋友）；制度确权另行走 **OPC 准入 NCA**（缔约者自签署）。两者串联：IDENTITY.md 通过 → 获得发射权 → 参与缔约时生成准入 NCA。

## 一、IDENTITY.md 模板正文（用户可复制填写）

```markdown
# IDENTITY · 智能体身份绑定声明

> 用途：让我的智能体代表我参与 TDCA 协作（组建/加入联盟、缔约、贡献 COP）。
> 流程：本地生成密钥 → 填写本文件 → PR 到本仓库 → enforce_entry 校验 → 获得发射权。

## 一、声明

- 我（GitHub 用户名）：{{github_username}}
- 声明以下智能体代表我参与 TDCA 协作：
  - 智能体标识：{{agent_name}}
  - 公钥指纹：{{public_key_fingerprint}}
- 生成时间：{{date}}
- 用途声明：{{purpose}}
  （示例：代表我组建科研协作联盟 / 代表我加入供应链协调联盟）

## 二、生成步骤（约 3 分钟）

1. 本地生成密钥：`ssh-keygen -t ed25519 -C "{{github_username}}-tdca-agent"`
2. 取公钥指纹：`ssh-keygen -lf ~/.ssh/{{key_name}}.pub`
3. 将指纹填入上方「公钥指纹」字段
4. 将本文件另存为 `IDENTITY-{{github_username}}.md`，PR 到本仓库 `docs/identity/`

## 三、校验与确权

- `enforce_entry` 扫描校验：公钥指纹格式 + 声明字段完整性（自动）
- 通过 = 轻量身份绑定（我的智能体获得发射权）
- 制度确权（另行）：参与缔约时生成 OPC 准入 NCA（TDCA-ADMIT-TEMPLATE-001，缔约者自签署）
- 贡献历史积累后，可升级链上证明（后置）

## 四、纪律

- 私钥永不上传（仅公钥指纹入仓）
- 一个 GitHub 用户可绑定多个智能体（各自独立指纹）
- 撤销：删除本文件 PR 即解除绑定
```

## 二、使用说明（给用户）

1. **无代码门槛**：只需 3 条命令 + 填 4 个字段（GitHub 名/智能体名/指纹/用途）
2. **PR 即注册**：enforce_entry 自动校验，无需人工审批（冷启动期）
3. **代表权**：绑定后智能体可代表你缔约（发射权），不可代表他人

## 四、通知机绑定评估（V0.2 升级路径，现阶段不引入）

创始人质询：通知机（可信物理根节点）能否作为冷启动绑定（模拟器可生成身份给用户）？

**评估结论：技术可行（SIL 模拟器 V1.0.0 已交付，可生成模拟通知机身份），但现阶段（V0.1 冷启动 MVP）不引入**：

| 维度 | ssh 指纹（V0.1，现用）| 通知机绑定（V0.2，预留）|
|---|---|---|
| 身份硬度 | 密码学弱身份（私钥持有）| 硬件级强身份（硬件 ID + SE 密钥 + 状态机 + NCA-Lite）|
| 用户侧成本 | 3 分钟零依赖 | 需运行模拟器（分发/依赖）|
| 制度契合 | 通用密码学 | TDCA 原生（可信物理根节点叙事）|
| 迁移成本 | — | 模拟器身份 → 真硬件身份（三缺口闭合后）|

**触发条件（V0.2 启动）**：通知机硬件三缺口（芯片/驱动/板，GSEQ-0370）闭合后，IDENTITY.md 增加"通知机身份"选项——用户持模拟器身份过渡，真硬件就绪后迁移；与"可信物理根节点"叙事一致。
